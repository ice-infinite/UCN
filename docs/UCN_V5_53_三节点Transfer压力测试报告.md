# UCN V5-53 三节点 Transfer 压力测试报告

## 结论

在 A=`COM5/ESP32-S3-N16R8`、B=`COM34/ESP32-S3-N16R8`、C=`COM38/ESP32-S3-N8R8` 的真实三节点台架上，A→B→C 使用两段 `115200 8N1 UART`，ESP-NOW 同时在线，最终 Route 为 `2 hops/cost 68`。每个消息等级都传输相同的 8 KiB 应用数据。

- T128～T8K 连续两轮共 `14/14` 个阶段全部完整到达，无无效数据、重复消息或 CRC 错误；仅一轮 T2K 重传 1 个 Fragment 后成功。
- 可靠等级有效端到端吞吐为 `2.48～3.17 KiB/s`。T4K 两轮平均约 `3.13 KiB/s`，相对 T128 的 `2.57 KiB/s` 提升约 `21.8%`；T8K 平均约 `3.11 KiB/s`，提升约 `21.0%`。
- T32/T64 是无 Transfer Fragment ACK 的 Direct 快速帧。它们峰值更高，但持续压力下不稳定：T32 两轮完成率 `98.44%/98.05%`，T64 为 `100%/96.09%`。固定延时无法在 Heartbeat/Ping/中继转发瞬时竞争下保证全收。
- 大消息等级的收益来自减少消息级固定开销并获得逐片 ACK/重传，不是把 8 KiB 当作一个物理帧。当前台架的可靠吞吐最佳点位于 T4K/T8K 附近。

## 测试方法

| 等级 | 等载荷组合 |
| --- | ---: |
| T32 / T64 / T128 | `32×256` / `64×128` / `128×64` |
| T256 / T512 / T1K | `256×32` / `512×16` / `1024×8` |
| T2K / T4K / T8K | `2048×4` / `4096×2` / `8192×1` |

C 使用固定序号图和确定性 Payload 逐消息校验；A 周期请求 C 返回对应等级的远端统计。吞吐以 C 实际收到的应用字节除以 A 开始至收到回报的端到端时间计算，不使用本地入队速度。B 只做 Core 透明中继，不创建 Transfer 对象。

## 资源与边界

压力镜像 RAM/Flash：A=`63,756/602,607 B`、B=`48,756/596,111 B`、C=`55,796/598,411 B`。A/C 固定 Transfer 对象均为 `8,672 B`，没有按消息动态分配 8 KiB Heap。Run 4 最小 Heap A/B/C=`294,568/309,392/304,572 B`，栈余量=`5,224/4,972/5,260 B`；无重启或 Panic。

本轮不代表 ESP-NOW-only、921600 UART、CAN-FD、Bearer 切换中 Transfer、多发送端并发、长稳、CPU 百分比或功耗。必须可靠的 T32/T64 连续业务应增加应用层序号/ACK/重发，或使用会进入可靠 Fragment 状态机的等级；不能只靠固定节流承诺零丢失。
