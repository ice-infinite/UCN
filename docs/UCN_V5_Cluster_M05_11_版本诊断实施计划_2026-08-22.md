# CLV2-05-11 版本与能力诊断实施计划（2026-08-22）

## 1. 授权边界

`CLV2-05-10` 已获外部受限 GO，但 M05 整体仍为 `AUDIT HOLD`。本项只为未来的 v4 RX Owner 提供**调用方持有、无状态**的版本/能力诊断结果；不能把任何观察写入当前 `ucn_cluster_t`，更不能接入 production v4 RX/TX/FSM、Member 表、Head/Backup/Voter 选择、Authority、quorum 或 v4 发送。

当前 production `ucn_cluster_view_t` 与 `ucn_cluster_stats_t` 只代表 v3 运行态。现在没有 v4 RX Owner；若伪造“已观察 peer”的 Cluster View/Stats 写入，反而会掩盖未实现的接线。因此本项的 `view`、`trace reason`、`stats` 是独立的诊断对象：它们由未来 Owner 在完成严格 decode/admission 后显式调用，不读取或改变 Cluster FSM。

## 2. 目标

对一条已知 peer 的版本观察，稳定给出：

| 输出 | 用途 |
|---|---|
| `view` | 记录 peer Node ID、检测到的 v3/v4 format、是否携带 offer、解析后的 offer、调用方请求类别和 required capability 位。 |
| `reason` | 解释版本前置条件为何通过或拒绝，例如 Strict v4 拒绝 v3、v3 仅能 non-voting、v4 缺少 capability、offer 缺失/非法。 |
| `stats` | 由调用方持有的有界计数器，累计 evaluated / v4-compatible / legacy-compatible / rejected / invalid-input；不嵌入 `ucn_cluster_t`。 |

这些结果只说明 **wire compatibility precondition**，不说明节点已经是、或可以成为真实 Member/Voter/Backup/Head。

## 3. 设计合同

### 3.1 输入和无副作用

- 输入要求调用方显式给出 peer Node ID、已严格检测的 format、是否有 `wire_offer`、混合版本 policy、请求类别和 required capabilities。
- 诊断 helper 先验证所有输入；任何非法输入返回 `UCN_ERR_ARGUMENT`，并保持 `view` 与 `stats` 不写回。
- helper 不做 decode、不保存 peer 表、不使用时钟、不发包、不调用 Cluster API。
- `stats` 只有在 caller 明确调用 record API 且诊断已成功生成 view 后才变化；计数使用饱和递增，避免诊断自身回绕。

### 3.2 确定性 reason 优先级

为保证日志、Host 测试和未来 MCU trace 一致，判定顺序固定如下：

1. policy、requested class、peer Node ID、format、required bit 或 offer-present 组合非法：函数返回 `UCN_ERR_ARGUMENT` 且不写 view；调用方如需计数，显式记录 `INPUT_INVALID`；
2. `v3 + Strict v4`：`STRICT_V4_REQUIRES_V4`；
3. `v3 + 请求 Voter/Backup/Head`：`V3_LEGACY_NON_VOTING_ONLY`；
4. 合法 `v3 + explicit legacy + non-voting + required=0`：`COMPATIBLE_V3_LEGACY`；
5. `v4` 缺 offer：`V4_OFFER_MISSING`；offer 编码非法：`V4_OFFER_INVALID`；
6. 合法 v4 offer 未覆盖 required bits：`V4_REQUIRED_CAPABILITY_MISSING`；
7. 其余合法 v4：`COMPATIBLE_V4`。

`ucn_cluster_wire_v4_mixed_version_peer_is_compatible()` 仍是唯一 compatibility 前置条件实现。05-11 只能解释其结果，不得把解释替换为另一套策略；因此 v3 携带 offer 或任一 required v4 bit 仍是 `UCN_ERR_ARGUMENT`，而不是新增的普通拒绝 reason。

### 3.3 未来接线规则

未来 M06/M08/M09/M10/M13 的 RX Owner 必须在 strict decode、source/admission、Config/Epoch 等自身门禁后才建立该观察；它可把 `reason` 写入 trace 或 caller-owned counter，但不能以 `COMPATIBLE_*` 直接授权任何状态转换。真实 View/Stats 的持久 peer 表归 M06 后拥有生命周期/容量/过期语义的 Owner；本项不提前定义该表。

## 4. 实施拆分与自审

| 子项 | 修改 | 验收 |
|---|---|---|
| 11-A | 在 private semantic header 定义诊断输入、view、reason、stats 和纯函数声明。 | 不暴露到 public Cluster runtime API；不增 `ucn_cluster_t`。 |
| 11-B | 在 isolated v4 codec 实现诊断和 caller-owned stats record。 | 只复用现有 mixed-version helper；无 decode/TX/FSM 调用。 |
| 11-C | 定向测试覆盖 v3 Strict/legacy、v4 missing/invalid/insufficient/full offer、非法输入、输出不写回、stats 饱和。 | 每一种不可作为 Voter/Backup 的版本原因可稳定解释。 |
| 11-D | 进行完整回归与静态隔离审计。 | v3 production 仍 32 B；encoder 仍 0；production Cluster/Adapter 无 v4 reference。 |

## 5. 非目标

- 不改变 RFC4、v3 codec、默认关闭的 v4 encoder、Core Wire 或通用 Adapter。
- 不接入 `ucn_cluster_get_view()` / `ucn_cluster_get_stats()`，不创建 peer table、trace ring 或任何 runtime owner。
- 不执行真实资格判断，不决定 Join、Member、Voter、Backup、Head、Takeover、Handover、Rekey、quorum、persistence 或 Authority。
- 不把 Host 单元测试称为实机日志验证。

外部复审已签署 **GO（受限范围）**：诊断严格复用 05-08 的判定，v3+offer/required bit 未被降格，拒绝/无写回/显式饱和计数均通过；外审复跑 Windows Full `2/2`、WSL ASan/UBSan `25/25`。该签字只结束 05-11，M05 总体仍不得放行。
