# 系统边界

## 三个不混淆的概念

| 概念 | 说明 | 不是 |
| --- | --- | --- |
| UCN-Core | MCU 上的 Frame、Node、邻居、路由、Q0/Q1、固定表与安全 Provider 边界。 | Linux 服务、SDK 驱动或业务执行器。 |
| UCN-Extended Transfer | 按需链接的九档逻辑消息、固定 TX/RX Slot、分片/重组与 ACK。 | Core 前置条件、无限文件缓存或中继重组。 |
| Product Port + Adapter | 产品提供的时钟、临界区、RTOS 通知、UART/WiFi/CAN/USB 字节收发和指标采集。 | Core 的路由所有者或网络中心。 |
| UCN-Host | 后续将 Linux、ROS2、MAVLink、日志或运维受控接入的可选模块。 | MCU 网络的必经节点。 |

Nano/Lite/Full 是同一个 Core 在不同节点上的编译档案；Service ON/OFF 与是否链接 Transfer 都是正交选择。它们不等于目录，也不等于节点在网络中的角色。

## 运行链

    多个介质驱动 ISR/回调
      -> 各 Bearer 自己的 BSP 固定 ring（推荐）
      -> ucn_event_runtime_signal_source[_from_isr]
      -> 中断安全通知 / 事件对象合并唤醒唯一 Owner
      -> Source::service 有界 Drain / Carrier 解帧
      -> Transport RX Queue
      -> 唯一 Protocol Owner
      -> Node / Routing / Service Bridge
      -> Link send

一个 Node 只有一个 Protocol Owner。业务任务、日志任务与 ISR 均不能直接并发进入 Node。

V5-58 的 `ucn_event_runtime_t` 是公共、SDK 无关的调度边界：每个 UART、CAN 控制器、USB Endpoint 或无线 Adapter 占用一个固定 Source ID；事件位允许合并，数据始终留在各自 Driver Ring；Source 只有在唯一 Owner 上下文才执行 `service()`。V5-59 的 `ucn_stream_source_t` 统一 UART/RS-485/USB CDC 的调用者存储 Ring 与 COBS+0；V5-60 的 `ucn_can_source_t` 统一 CAN-FD Frame Ring、经典 CAN Carrier、Bus State 与 CAN ID→Link Resolver。两者都不包含 GPIO、驱动 Handle、DMA/控制器 SDK 类型或 RTOS 对象。现有单 Queue Platform Port 继续作为可选入口；V5-62 后两种入口均要求 Port API V2，旧编译对象不兼容。

事件唤醒是正常数据路径：收到完整帧、TX 队列释放或驱动状态变化后应立即通知
Owner，Owner 在固定轮数/时间预算内批量 Drain。定时等待只用于 Heartbeat、Deadline、
`UCN_MAX_STEP_INTERVAL_MS` 和漏通知保底；不允许让正常业务数据等待 Heartbeat 周期。
没有中断/事件设施的裸机可以轮询，但它属于兼容模式，不是 RTOS/现代 MCU 的默认实现。

若 ISR 直接把完整帧交给 Adapter RX Queue，产品必须提供独立的
`enter_critical_from_isr()` / `exit_critical_from_isr(token)`；缺失时入口
返回 `UCN_ERR_CONFIG`，绝不把 ISR 当成普通任务使用任务临界区。这个
token 用于恢复 ISR 进入前的中断掩码，适配 FreeRTOS 等不同 Task/ISR
临界区 API；它不证明真实 SDK/BSP 的嵌套中断时序已经验证。
ISR 只搬运有界数据、更新时间戳并发通知；Frame 解码、路由、解密、Transfer
重组、Endpoint 和日志都必须留在 Owner/其它任务。同步调试打印不得阻塞 Owner。

Port API V2 要求 `ucn_port_ops_t` 先携带完整 `struct_size` 和当前 `api_version`；Owner/Runtime/Source 读取回调前统一失败关闭。Transfer 配置另持有唯一权威单调时钟，Send/RX/Step 不再混用外部缓存时间。两项都是预发布源码/ABI 破坏，但不改变 v5 Wire。

## 未实现边界

公共 Event Runtime、Stream Ring/COBS Source、CAN/CAN-FD Frame Source 与经典 CAN Carrier 已通过 Host 软件门禁，但真实 UART DMA/USB CDC/RS-485 流控、ESP-NOW/WiFi、CAN 控制器/收发器、硬件过滤/仲裁/Bus-Off、各 RTOS SDK glue、生产 Host、Extended Gateway 和生产安全 Provider 不因存在接口而视为完成。Transfer 已有 Host 软件实现，但其真实多板吞吐、CPU、功耗、Path 切换和生产安全同样必须单独实测。
