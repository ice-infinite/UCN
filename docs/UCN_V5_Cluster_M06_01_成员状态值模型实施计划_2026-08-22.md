# CLV2-06-01：成员状态值模型与 legacy-v3 元数据桥实施计划

日期：2026-08-22

状态：DONE / 外部复审 GO（受限范围）

## 1. 目的

把“运行时表中存在一个节点”与“未来受保护 Voter Config 中是否有投票权”分开表示，为 M06-02/03 的 Runtime table 与 Voter set、M07 的 Joint Config 做数据准备。

本项不实现 v4 Join、不改变现有 v3 Join 的控制面含义、不创建 Voter set，也不触发 Authority/Backup 选择逻辑。

## 2. 固定模型

公共成员值类型定义四种状态：

| 状态 | 本项含义 | voting 约束 |
|---|---|---|
| `NONE` | 未占用槽位；仅用于零初始化/释放后状态 | 必须为 false |
| `PROVISIONAL` | 已占用 Runtime slot，尚未进入 Config | 必须为 false |
| `COMMITTED` | 已被某一已提交 Config/legacy bridge 认定 | 可为 true 或 false；v3 bridge 固定为 true |
| `REMOVING` | 已提出移除但 M07 Commit 前仍保留记录 | voting 可保持原值；M07 决定 quorum 语义 |

合法转换：`NONE→PROVISIONAL/COMMITTED`、`PROVISIONAL→COMMITTED/REMOVING/NONE`、`COMMITTED→REMOVING`、`REMOVING→COMMITTED/NONE`，以及同状态幂等。其他转换 fail-closed。

每个 occupied record 新增/明确：`status`、`voting`、`wire_version`、`capabilities`、`joined_at_ms`、`last_keepalive_at_ms`。Node ID 必须非零、非 broadcast；v3 record 必须 capability=0；PROVISIONAL 禁止 voting。

## 3. Current v3 兼容桥

当前 v3 没有 Wire 字段表达上述 metadata，且 Existing Backup/Takeover 仍按 `occupied` 工作。因此本项只在已有 producer 初始化 metadata：

- Head 接收 v3 `JOIN_REQUEST`：新 Member 标记 `COMMITTED + voting=true + wire=v3 + capabilities=0`。
- Backup 收到现有 mirror snapshot/delta、Recovery Head 记录 survivor：同样标记为 legacy committed/voting。
- v3 Join/Keepalive 仅更新 `last_keepalive_at_ms`；现有 nonce、lease、Backup/Takeover、成员循环和容量计算均不读取 status/voting。

这只是保证旧行为有显式 metadata 的桥。真正 v4 `JOIN_ACCEPT → PROVISIONAL`、Provisional timeout、v3 legacy non-voting 以及 Voter capacity 均严格后置到 06-04..09。

## 4. 禁止事项与验收

- 不包含 v4 wire header，不触碰 production v4 RX/TX/FSM、Adapter、Authority、quorum 或 Certificate。
- 不允许 status/voting 在本项改变任何现有 v3 sender、Backup candidate、Takeover 或 capacity 决策。
- 增加独立模型单测：合法/非法状态、转换、Node/wire/capability/voting 约束、legacy 初始化和 keepalive 更新。
- 完成时对 Full/Lite/Nano、Sanitizer、静态分析、资源增量和 production-v4 隔离做自审；随后保持 `CODE COMPLETE / AUDIT HOLD（待外部审计）`。

## 5. 实施与自审结果

- 新增公共 `include/ucn/ucn_cluster_membership.h`：成员状态值、紧凑 record、合法状态/转换/record 校验 API；该 header 只依赖 `ucn_types.h`，不依赖 Wire v4。
- 现有 Head Join、Backup mirror snapshot/delta 与 Recovery ACK 的创建点统一调用内部 legacy bridge；非法 `0`/broadcast Node ID 不会改写 slot。
- `members[]` 的既有计数、容量、Backup、Takeover 和选举循环仍只读取 `occupied`；本项没有让 `status` 或 `voting` 参与任何生产决策。
- 新增 `ucn_cluster_membership_model_tests`，并在原有 Cluster 三节点 Join→Backup failover→Recovery 路径中核对真实 metadata。
- 自审构建/测试：Windows GCC Full `30/30`、Lite `30/30`、Nano `20/20`、Service OFF `27/27`；WSL ASan/UBSan `20/20`、WSL `-fanalyzer -Werror` `7/7`。
- Host x64 Debug `sizeof(ucn_cluster_t)` 从 M04/R23 基线 `1200 B` 增至 `1392 B`（`+192 B`，默认 16 个成员槽各增加 12 B）。这是 Host ABI 观测，目标 MCU 仍需在其编译器/链接脚本下单独测量。

## 6. 外部复审签字

2026-08-22 的独立外部复审结论为 **GO（受限范围）**，未发现 P0/P1/P2。

- 复审确认四个状态值、完整 4×4 转换表与 record 合法域一致；空槽 canonical、v3 capability、Provisional voting、非法 Node ID 均 fail-closed。
- Join、Backup mirror、Recovery 的所有新槽创建点均通过 legacy bridge 写入 `COMMITTED + voting + wire=v3 + capabilities=0`；新元数据未被现有权限、选路、容量、Backup 候选或 Takeover 逻辑读取。
- 外部复跑通过 Full `30/30`、Lite `30/30`、Nano `20/20`、Service OFF `27/27`、WSL ASan/UBSan `20/20`、`-fanalyzer` `7/7`；64-node clean simulation 为 `converged_ms=8920`、Host `object_bytes=1392`。

本签字仅覆盖成员数据模型与 legacy-v3 元数据桥。M05 顶层仍为 `AUDIT HOLD`；不得启用 v4 Join/RX/TX/FSM、Voter quorum、Authority、资格选择或作出实机互通声明。
