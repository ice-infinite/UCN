# 故障诊断与产品验收

## 1. 先定位层级

没有数据时依次检查 Link readiness/Generation、Adapter queue/completion、Wire decode、Hop
Security/Replay、Binding/Session、RouteSet、QoS/Credit、E2E/ACL、Realtime/Journal 与业务。
不要仅看最终错误码就扩大超时或队列。

## 2. 关键统计

分别观察 RX/TX 入队、调度、Driver 提交、completion、丢弃原因、认证/Replay、Route 错误、
Candidate 重试、QoS 每类/每流、Transfer SACK/Credit/重传、Realtime phase/uncertainty、Cluster
Authority/Fence。统计应按饱和计数并保留错误分类。

## 3. 常见问题

- 队列有数据却不发：检查 Owner 是否被通知、Link ready、QoS selection 是否 complete；
- 多跳吞吐接近 1/n：检查是否停等、半双工共享介质、窗口/Credit 太小或中继不能流水；
- 路由看似发现但业务失败：检查 Binding/Session/Path Generation 与实际 Payload Budget；
- Deadline 经常失败：测量 timestamp/asymmetry/queue tail，不要降低 uncertainty 伪装精度；
- 重启后无法恢复：检查 Record/schema/Manifest、persist-before-promise 和 torn-write 证据。

## 4. 验收记录

每次测试记录 commit、固件/日志 hash、板号、供电、接线、引脚、SDK、编译器、配置、速率、
拓扑、消息等级、持续时间、阈值和结果。硬件拔插或接线改变后重新记录，不能沿用上一轮日志。
