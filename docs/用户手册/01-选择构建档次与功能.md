# 选择构建档次与功能

UCN 的 Build Profile 决定“本机编译进哪些能力”，Wire Profile 决定“一帧地址字段使用多宽”。两者不能混为一件事。

## 1. 先选 Build Profile

| 产品需求 | 推荐 | 具备能力 | 不具备能力 |
| --- | --- | --- | --- |
| 两个或少量 MCU，拓扑固定 | Nano | Frame、Endpoint、固定 Link/Route、Q0/Q1 | 自动入网、动态路由、安全、Path/Policy |
| 多节点自动加入，只需单条当前路由 | Lite | Nano + Neighbor、Heartbeat、AODV-Lite、Security接口 | Candidate、显式Path、负载均衡、高级诊断 |
| 多 UART/CAN/Wi-Fi、指定路径、故障回退 | Full | Lite + Candidate、Path、Policy、Q1均衡、诊断 | 无 Profile 内裁剪 |

### 选择流程

```text
拓扑是否完全固定？
  是 → 是否需要 Security Provider？
         否 → Nano
         是 → Lite
  否 → 是否需要指定路径/多候选/负载均衡？
         否 → Lite
         是 → Full
```

不要因为 MCU RAM 较大就无条件使用 Full，也不要为了省少量 RAM 用 Nano 后在应用层重新实现一套不受协议约束的动态路由。

## 2. CMake 配置

```powershell
# Nano
cmake -S . -B build_nano -DUCN_PROFILE=NANO

# Lite
cmake -S . -B build_lite -DUCN_PROFILE=LITE

# Full
cmake -S . -B build_full -DUCN_PROFILE=FULL
```

每个产品目标必须使用独立 build 目录。所有包含 UCN 公共头的翻译单元必须看到相同的 `UCN_PROFILE` 和 `UCN_FEATURE_SERVICE`，否则公共对象布局可能不一致并造成内存破坏。

## 3. 再选独立功能

### Service

Service 与 Profile 正交：

```powershell
cmake -S . -B build_lite_service `
  -DUCN_PROFILE=LITE `
  -DUCN_FEATURE_SERVICE=ON
```

不需要任务 Router/Bridge 时关闭：

```powershell
cmake -S . -B build_lite_core `
  -DUCN_PROFILE=LITE `
  -DUCN_FEATURE_SERVICE=OFF
```

### Transfer

Transfer 是独立 Archive，不使用就不链接：

```cmake
target_link_libraries(my_firmware PRIVATE ucn_core ucn_transfer)
```

### Cluster

Cluster 也是独立 Archive，但当前总体仍处于发布阻断状态。普通产品不要把“可以链接”理解成“建议生产启用”，详见 [Cluster 当前使用边界](15-Cluster当前使用边界.md)。

## 4. 选择 Wire Profile

Node 初始化后默认固定 W3 TX/W3 RX。产品通常将 TX 设为能表达本地域的最小档，RX 仍保留 W3，以便低资源节点接收高级节点的普通 Endpoint 数据：

```c
ucn_result_t result = ucn_node_set_wire_profiles(
    node,
    UCN_WIRE_PROFILE_W0_LOCAL,
    UCN_WIRE_PROFILE_W3_BACKBONE);
```

可用值：

| API 值 | 用途倾向 | 基础头大小 |
| --- | --- | ---: |
| `W0_LOCAL` | 小型本地网络 | 17 B |
| `W1_EDGE` | 边缘网络 | 21 B |
| `W2_MESH` | 较大 Mesh | 26 B |
| `W3_BACKBONE` | 最大地址域/兼容上限 | 30 B |

准确可表达范围由 [Wire v5 规范](../official/02-核心协议/02-Wire-v5-W0至W3帧格式.md)定义。不要只按“包越小越好”选择；Node ID、Sequence、Session、Path 等字段必须都能表示。

### 自动 Wire 选择

```c
ucn_node_set_wire_profile_auto(node, true);
```

自动模式仍受 Node TX 上限、对端 RX 上限和当前 MTU 限制。它不会把 Full 的高级能力自动降级给 Nano，只选择可表达当前 Frame 的编码宽度。

## 5. 产品全局配置头

推荐建立产品专属配置头，用 CMake 注入：

```powershell
cmake -S . -B build_product `
  -DUCN_USER_CONFIG_HEADER=product_ucn_config.h `
  -DUCN_USER_CONFIG_INCLUDE_DIR=E:/MyProduct/config
```

配置头只覆盖产品确实评估过的容量，例如：

```c
#ifndef PRODUCT_UCN_CONFIG_H
#define PRODUCT_UCN_CONFIG_H

#define UCN_MAX_LINKS 4U
#define UCN_MAX_ROUTES 16U
#define UCN_TX_Q0_DEPTH 4U
#define UCN_TX_Q1_DEPTH 8U
#define UCN_ADAPTER_RX_QUEUE_DEPTH 4U

#endif
```

不要复制整个默认配置文件。只覆盖需要变更的宏，保留库中的默认回退和编译期合法性检查。

## 6. 低 Profile 的 Stub

公共头为了让应用源码统一，会在低 Profile 保留高级 API 符号。但调用被裁剪的功能会明确失败：

- 修改类 API 通常返回 `UCN_ERR_CONFIG`；
- 查找类 API 返回 `NULL`；
- 布尔能力查询返回 `false`。

应用必须检查返回值。不能因为 `ucn_node_set_route_policy()` 在头文件中存在，就认为 Lite/Nano 已支持 Policy。

## 7. 选型验收

在确定 Profile 后至少验证：

1. 用该 Profile 全新 configure/build；
2. 运行对应 CTest；
3. 编译实际产品配置头；
4. 查看 map 中 RAM/Flash；
5. 确认应用没有忽略 Stub 返回值；
6. Service ON/OFF 与实际链接目标一致；
7. Wire TX 档能表达产品所有 ID 和控制字段；
8. 所有翻译单元的编译宏一致。
