# 五分钟快速开始

## 1. 构建库

```powershell
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Debug `
  -DUCN_PROFILE=LITE -DUCN_BUILD_TESTS=ON
cmake --build build --parallel
ctest --test-dir build --output-on-failure
```

默认启用 Realtime、Cluster 和 Adapter。简单端点可显式关闭不用的模块。不要沿用 v5 的
`UCN_FEATURE_SERVICE` 或 `UCN_BUILD_V6_EXPERIMENTAL`，它们已不存在。

## 2. 包含和链接

同仓库工程链接 `UCN::ucn`，安装后的外部工程使用：

```cmake
find_package(UCN 6 CONFIG REQUIRED)
target_link_libraries(my_firmware PRIVATE UCN::ucn)
```

应用代码包含：

```c
#include <ucn/ucn.h>
```

## 3. 最小准备

在真实收发前必须提供：单调微秒时钟、固定 Storage、Protocol Owner 通知、至少一条 Link
Driver，以及产品的身份/安全配置。只调用 Wire codec 可以不启动完整节点；一旦发送需要 ACL
或可路由业务，就不能跳过 Identity/Security/Capability。

先保存并打印 `ucn_v6_compiled_manifest()`。如果应用侧期望值与库不同，停止启动，不要尝试
降级继续运行。

## 4. 发送的真实含义

应用先用 `ucn_v6_message_validate()` 验证 Message Context。单帧消息按当前 Path Payload
Budget 编码；较大消息用 Transfer。进入 QoS 后由 Owner 立即调度，Adapter 可用时马上提交
Driver，不需要等心跳。

API 返回 `UCN_V6_OK` 可能只代表“已接受/入队/提交”，不一定代表远端已执行。Reliable 需要
ACK，Durable Request 需要 Result/Journal 状态，务必按对应完成事件判断。

## 5. 接收

驱动把一整个合法长度 frame 作为一个 RX item 发布；Owner 完成 Wire、Security、Replay、
Route 和 ACL 后才交给业务。业务不要直接消费 ISR buffer，也不要从未经认证的 Source 地址
推导设备身份。

完成最小 Host 测试后，再按[驱动接入](03-接入UART、CAN、Wi-Fi与USB.md)和
[产品验收](05-故障诊断与产品验收.md)上板。
