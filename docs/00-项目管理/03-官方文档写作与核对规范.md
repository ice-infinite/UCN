# UCN 官方文档写作与核对规范

> 文档级别：`NORMATIVE`
> 实现状态：`CURRENT`
> 适用范围：仓库内全部 `docs/official/` 文档
> 事实源：当前工作区源码、公共头、CMake、测试与版本绑定证据
> 最近核对：`codex/v5-adaptive-wire@a093862`，2026-08-25

## 1. 事实优先级

发生冲突时依次采用：

1. 当前公共头与生产源码；
2. CMake 实际编译、链接和 Feature 边界；
3. 当前测试与绑定 commit 的实机证据；
4. 官方文档；
5. 实验 RFC、任务表、审计记录与历史建议。

文档发现与源码不一致时，先修正文档并登记差异；不能为了维持旧文档表述而暗改协议代码。

## 2. 必填页首

每篇官方文档必须至少声明：

```text
文档级别：NORMATIVE / GUIDE / REFERENCE
实现状态：CURRENT / PARTIAL / DEFAULT-OFF
适用版本：项目、Wire、API 或 Storage 版本
事实源：公共头、源码、构建目标、测试
最近核对：commit 与日期
硬件状态：未测 / 部分实测 / 已实测，并写明平台
```

`CURRENT` 只表示文档与当前代码一致，不自动表示生产安全、硬件验收或发布就绪。

## 3. 用词规则

- “实现”必须能定位到源码和公开入口。
- “验证”必须写明是单元、Host 模拟、Sanitizer、静态分析还是实机。
- “支持某介质”必须区分通用 Carrier/Source 与真实 BSP/SDK Driver。
- “可靠”必须说明是本地入队、链路接收、Transfer 完整 ACK 还是业务任务执行成功。
- “安全”必须区分 Core 门禁、测试 Provider 和产品级身份/密钥/AEAD。
- “Cluster v4”必须说明 Codec/RFC、实验组件和生产 FSM 接线之间的边界。

禁止使用“全部完成、完全安全、零丢包、无缝切换、万级可用”等没有绑定条件和证据的绝对表述。

## 4. 引用与重复

- 版本号、结构尺寸、宏默认值、枚举值和 API 签名放入权威参考表或直接链接公共头，不在多篇文档手抄。
- 架构文档解释责任边界；API 文档解释调用合同；集成指南给出步骤；证据报告只陈述一次具体测量结果。
- 历史文档被替代后标记 `ARCHIVED / SUPERSEDED`，并链接新官方文档。

## 5. 每批验收

每完成一个一级目录至少执行：

1. 对照公共头、源码目录和 CMake target；
2. 搜索错误版本、旧路径、过期尺寸与错误成熟度表述；
3. 检查 Markdown 本地链接；
4. 执行相关 CTest 或文档契约；
5. 更新项目任务表和操作记录；
6. 记录仍未验证的硬件、安全和发布边界。

## 5.1 专题正文最低深度

除纯索引 README、自动生成表和极短枚举参考外，每篇专题不能只写“功能清单 + 一段限制”。应根据主题至少覆盖下列内容：

1. **为什么存在**：此前没有该模块时会遇到什么问题，UCN 在哪一层解决；
2. **解决什么与不解决什么**：给出职责边界，避免与相邻模块混淆；
3. **核心对象**：解释关键结构、字段关系、所有权和生命周期，而不是只列名字；
4. **完整流程**：从触发条件到成功/失败结束，说明每一步由谁执行、状态如何变化；
5. **时序与并发**：Owner、ISR、任务、回调和异步 Provider 的调用关系；
6. **配置与 API**：说明必要配置、调用顺序、返回值和输出写回规则；
7. **异常路径**：容量满、超时、断链、重放、版本不兼容和错误恢复；
8. **具体示例**：至少一个正常例子；复杂或安全主题还需一个失败例子；
9. **资源和性能影响**：说明固定表、队列、额外帧、时延或硬件责任；
10. **证据与成熟度**：指出源码/测试能够证明什么，以及哪些仍未实测。

若某一项对主题确实不适用，应在正文中明确说明原因，而不是省略后让读者猜测。

## 5.2 可读性标准

- 第一次阅读 UCN 的嵌入式开发者应能仅靠正文复述该模块的数据流和失败处理；
- 文档中的“它、这个状态、该接口”必须有明确指代；
- 先解释概念，再出现缩写和实现名；
- 表格用于精确对应，流程图用于跨三个以上步骤的状态/数据流；
- 示例必须标注是伪代码、真实 API 片段还是概念示意；
- 不用“按需处理、合理配置、视情况而定”替代实际规则；如果产品决策尚未冻结，应列出决策输入和默认失败方式。

## 6. 文档不是能力开关

写入官方文档不会启用任何 Feature、改变 Wire、修改 ABI 或解除 `AUDIT HOLD`。能力状态只由代码、构建配置、独立审计和实测门禁决定。
