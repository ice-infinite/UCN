# 原生认证后端接线实施计划

> For agentic workers: 使用 executing-plans 在当前开发分支逐项执行；每项先 RED 后 GREEN、自审，最后整体代码/架构审查。不操作实机，不自行提交推送。

**Goal:** 将真实 Security/Runtime 认证的数据交给原生发布订阅，而不是把配置身份标签升级成认证证明。

**Architecture:** Native 保留通道、实体、复制队列和应用执行器；独立 Coordinator 后端负责 Session/ACL、Wire、Replay 和 Adapter。静态 O0 后端仍有独立的信任含义，保护要求不得降级。C/Rust 共用准入、来源、时间、失效和退休合同。

**Tech Stack:** C99/C++17、Rust no_std、固定数组、现有 Security/Adapter 与运行时；不新增普通 Wire 字段。

**Spec:** [原生接口方案](../10-理论与规划/建议方案/UCN_v6_原生发布订阅与统一用户API简化详细设计方案.md)、[首轮计划](07-原生API最小闭环实施计划.md)。

执行收口合同：[认证后端共同合同](../10-理论与规划/建议方案/UCN_v6_C_Rust共用合同收口/23-原生发布订阅认证后端共同合同.md)。
Ruling：现有C缺认证业务端点，本轮采用单个固定Session/Service、H0直连，不冒充多Peer或动态多跳完成；
代价是高级路径还不能从该产品后端发出，后续须专门接线，而不是悄悄由Native复制路由/安全FSM。

## 全局约束

- 基线为 `v6-simplified-rust@099d55908ccc7d46d129bfa416cb015e4cdfc1b5`，开始时工作树干净。
- 本轮首先接固定通道、单帧、OneWay/BestEffort、明确 OriginAuth/Encrypted 的真实后端；不扩展 RPC、可靠交付、动态 Topic 或 Timed Command。
- C 的现有 Composition publish 仍委托 O0 Core，不能作为已经完成的认证数据端点。缺失的数据边界须显式实现和测试；不以 FakeBackend 的成功冒充实际接线。
- 不在 Native 中复制 Session、Replay、持久化承诺或 Origin 序列分配器。后端是可信产品装配接口，不是允许业务自行提供 `authenticated=true` 的入口。
- 普通业务头增加 0 B；使用既有安全格式和 Tag，必须披露其原有开销，不把 Tag 称作免费。
- C/Rust 同步修改合同；C++ 保持薄包装。旧签字候选哈希不重写。
- 原栈门限、分析器诊断、Feature OFF 及真实退休要求保持；不操作板卡、串口、烧录或 Vault。

## Review Focus

1. 认证后排队、dispatch 前 Session/Parent/ACL 失效：零业务回调。
2. O0 或错误 Principal/Binding/Service/保护级别：不能进入保护通道。
3. Latest 的旧序号和旧 Session 队列：不能覆盖或复活新来源流；摘要不作授权身份。
4. 原始接收时间、发送 Deadline 与背压：不得重新起算，失败不伪造交付/退休。
5. 停止、回调重入和物理 Unknown：关闭仍可执行，真实 Driver 义务保留。
