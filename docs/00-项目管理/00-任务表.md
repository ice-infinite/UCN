### V6 实施纪律

1. `V6-00` 外部审计前不修改协议版本或 Frame Codec；V6-03 只允许隔离 default-OFF Codec，生产 RX/TX/Encoder 必须等待 V6-07 外部 GO；
2. 每个子项都执行“设计 → 任务 → 实现 → 定向自审 → 全矩阵 → 外审”；
3. 不为旧固件增加 Runtime fallback；发现旧测试依赖时修改测试或在 v5 分支复现；
4. Security 从 Identity/Wire 阶段同步设计，不能最后补 Tag；
5. Capability、RouteSet、Transfer、Realtime 和 Cluster 不得各自再造不同 Identity、
   Generation、Deadline、Persistence 或 Callback Gate；
6. Host 测试不冒充目标 MCU、真实 Flash、无线、硬件 timestamp 或生产密码证据；
7. V6-07 是唯一 JOIN/ADMITTED Owner；V6-06 不得建立无认证 admission；
8. V6-11 Realtime 与 V6-12 Cluster 只共享基础设施，必须可独立编译、链接、运行和删除；
9. v6 当前分支不保留可编译旧源码；旧输入拒绝测试不是兼容层，不得误删。

## 本轮实现范围

最初一轮优先完成 `UCN-Core` 的可运行、可测试最小闭环；当前代码已继续扩展为固定帧、统一 Link、Q0～Q3 独立队列、固定路由缓存、受限 AODV-Lite、可选链路质量选路、邻居 Candidate/Admitted 生命周期、最小 HELLO 自动准入、虚拟多节点模拟和 Host 非中心化验证。

以下内容不在当前结果中伪造为“已完成”：真实 BLE/CAN 驱动、ESP-NOW-only 大消息性能、ROS2 Bridge、DroneCAN Gateway、生产级 AEAD/证书实现、OTA、动态服务目录，以及 Q0～Q3 到具体控制器硬件优先级/FIFO 的产品映射。Node 与 Service 已按 QOS4-01～07 完成四级固定队列和软件调度；业务消息另有独立 `ucn_transfer`，支持 T32～T8K、固定重组、CRC32、默认窗口 1/显式窗口 2～8、累计 ACK、有界 Go-Back-N 和固定资源。T32/T64 Direct 走 Q2 且仍不带端到端确认，Fragment 走 Q3，ACK 走 Q1；窗口能力尚未自动协商。ESP-NOW 四节点、多 Origin、完整 Path MTU、四级实机并发隔离、切换压力及其他介质/目标仍是硬件门禁，不能扩大表述为生产级可靠文件传输。

## 完成定义

一个任务只有同时满足以下条件才能标记“完成”：

1. 源码和公共接口已写入工程。
2. 相关单元测试已通过。
3. 对应模拟场景已通过。
4. 修改和验证结果已追加到 [项目操作记录](01-项目操作记录.md)。
5. 没有把测试 Provider、虚拟 Link 或模拟性能表述成真实硬件验证。
