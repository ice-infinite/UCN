## 1. 本分支的目的

`v6-simplified` 用于把当前完整 V6 按已经形成的低开销 Wire、模块化、统一公共 API、Coordinator 编排和 MCU-first 资源边界逐步重构为简化版。

本分支不是另起一套协议，也不从旧文档重新猜测需求。它继承完整 V6 的安全结论、失败关闭规则、测试资产和项目台账，只允许在明确冻结的简化合同下删除冗余、缩小默认开销、拆分模块依赖和收口接口。

完整 V6 已由远端备份分支和固定标签保留。简化版不得在本分支内复制一套可编译的旧源码归档；需要对照历史实现时直接读取备份分支或标签。

## 4. 当前源码的角色

共同起点保留了当前完整 V6 的 `include/ucn/v6`、`src/v6`、`tests/v6`、CMake 和工具脚本，目的是让简化重构具备可比较基线和回归证据。

这些源码可以作为：

- 已验证安全语义的参考实现；
- 行为回归和对抗测试来源；
- 简化前 RAM、Flash、Stack、符号和依赖基线；
- 重构过程中逐模块替换的输入。

但不能把“当前源码恰好这样实现”反向写成简化协议的规范。发生冲突时，必须先停止实现，按“最终架构 RFC → 冻结的专项合同 → 全局不变量/连接登记表 → 经过复审的伪代码”顺序裁决，并在操作记录中说明。

## 5. 开始实施前仍需关闭的门禁

当前分支创建不等于实现已经放行。以下事项仍按收口报告保持开放：

1. 低开销 Wire 的精确 Opcode Registry、bit/byte offset、Golden 和全量 Negative Matrix；
2. 公共 C API 的最终名称、结构大小、对齐、错误枚举与 Feature OFF 头文件面；
3. Full/Lite/Nano 的固定容量默认值、RAM/Flash/Stack/Timer/Queue 资源账；
4. Persistence Record 精确 schema、双槽布局和掉电恢复向量；
5. 简化文档尚未闭环的外部复审；
6. Host、Sanitizer、Analyzer、Release、MCU 和真实 Bearer/Flash 证据。

因此当前状态是：

```ini
V6_FULL_BACKUP              = COMPLETE / PUSHED
V6_SIMPLIFIED_BRANCH        = INITIALIZED
SIMPLIFIED_DOCS             = COPIED / SELF-REVIEWED
EXTERNAL_REVIEW             = REQUIRED
SIMPLIFIED_IMPLEMENTATION   = NOT STARTED
```

## 6. 分支恢复与对照

回到完整 V6 备份分支：

```bash
git switch v6-full-backup-20260912
```

只读检出固定快照：

```bash
git switch --detach v6-full-before-simplification-20260912
```

返回简化版开发分支：

```bash
git switch v6-simplified
```

比较简化版与完整 V6：

```bash
git diff v6-full-before-simplification-20260912..v6-simplified
```

## 7. 后续记录规则

后续每个简化子任务至少记录：

- 修改前的权威合同和目标；
- 删除、保留和替代的文件/符号；
- Feature OFF 的源码、符号、头文件、Storage 和任务证明；
- 正向、负向、资源耗尽、重入、重启和失败回退测试；
- Full/Lite/Nano 的实际资源变化；
- 自审结论、外审状态和仍未覆盖的硬件边界。

任何子任务未完成上述证据时，不得仅凭“代码更少”宣称简化完成。
