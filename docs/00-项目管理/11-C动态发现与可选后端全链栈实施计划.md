# C动态发现与可选后端全链栈实施计划

> 按用户“继续下一步”连续执行；使用测试先行、逐项独立审查和最终整体审查。不操作实机，不提交推送。

**Goal:** Native缺路由时由实际C0认证控制自动发现，再交付C1业务；完整计入可选后端间接协议调用链。

**Architecture:** 原生Facade不增加路由依赖；唯一数据Coordinator调度C0/C1、认证后才调用现有Route Owner。
新控制状态/工作区固定容量，计数器借用产品现有精确Session计数银行；不重建路由/密码FSM。
栈检查纳入编译器callgraph和经逐调用点核对的间接边，不能把未知边或有界动态栈静默略过。

**Tech Stack:** C99/C++17、Rust no_std，现有C0/0201/0202/0203/0206与C1/H1；Python门禁。

**Spec:** [合同14](../10-理论与规划/建议方案/UCN_v6_C_Rust共用合同收口/14-多邻居认证路由控制与局部小MTU合同.md)、[合同24](../10-理论与规划/建议方案/UCN_v6_C_Rust共用合同收口/24-原生多Peer与多跳认证后端共同合同.md)，本轮补充合同25。

## Global Constraints

- 当前v6-simplified-rust开发工作树原地续做，保留继承修改和失败证据，不暂存/提交/推送/改Vault；不操作COM/USB/Probe/实机。
- C首版仍使用已认证的封存身份/邻居、独占Link和固定Endpoint；动态“发现”指路由控制，不擅自扩成动态Admission/Session热换。
- 复用现有C0精确Opcode/Role/O1/H1 ACL及54/77/99B完整正文；小MTU必须按现有0206合同分片，不新增普通数据头字段。
- 原始发现域与逐跳Session分开；只有真实Driver终态/退休才完成RREP反向义务，Unknown不能假退休。
- C0事务与Hop/Origin计数唯一、不回绕、不因Native后端或控制重试从1重建；产品计数器回调必须在共同回调Gate内有界执行。
- 缺路由时保留Native原命令/绝对Deadline，不消耗业务Origin序号，不因控制重试续期；控制/数据固定池、预算和持久轮转游标。
- 原单函数门限保持256B（Route/Transport/Service1024B、Optional384B）；Nano/Lite/Full完整协议链门限768/1536/3072B，不放宽、不抑制诊断。
- 外部Driver/Provider/锁/应用函数不在协议源码内，必须显式标成产品边界并报告剩余预算/验证条件，不可把其任意实现宣称为0栈或实机已验证。

## Review Focus

1. A-B-C空路由表，经真实认证控制和Adapter建路，再由实际Native订阅收到；测试不得手工调用on_rreq/on_rrep或安装动态路由。
2. 丢包/背压/小MTU组包保持因果、原期限和精确反向物理义务；失败不能留下半条路由。
3. 错Opcode/Role/来源/Context/Tag/Replay与跨组迟到片不得进入Route Owner；多Peer控制限额不能饿死已可发业务。
4. 调用链不能漏掉Facade虚表、Security/Route/Adapter/C0Codec；新未知间接边、缺图、失效映射、递归及超限均要拒绝。
5. 精确边界通过/加1失败、Profile与优化构型变动、Provider重入前缀和stop/Unknown路径都必须有可区分门禁。
