# C动态接入与原生后端热续接实施计划

> For agentic workers: 使用测试先行和逐项自审；全部实施后独立整体代码/架构审查。用户已批准以下范围并要求直接实施，不再逐项请求继续。禁止提交、推送和实机操作。

**Goal:** 把已知身份对的首次JOIN、当前Session/Capability更新和安全热续接接到原生发布订阅后端。

**Architecture:** 唯一Coordinator编排已有Admission、Identity、Security、Capability、Foundation和Adapter。Native外观不实现新的认证状态机；控制正文沿用共同合同07～14，围栏/排空和后继沿用合同17～19。固定Realm、预期身份对、专用Link、静态业务通道；不扩展共享无线Link、动态Topic目录、地址Authority换主。

**Tech Stack:** C99、Rust no_std、CMake/CTest、Host Fake Driver/Provider；普通C1头新增0 B。

**Spec:** 用户批准的范围，以及[耐久JOIN合同09](../10-理论与规划/建议方案/UCN_v6_C_Rust共用合同收口/09-Bootstrap耐久发布与Session建立共同合同.md)、[当前Reauth合同13](../10-理论与规划/建议方案/UCN_v6_C_Rust共用合同收口/13-Reauth能力交接与耐久分歧恢复共同合同.md)、[热交接合同19](../10-理论与规划/建议方案/UCN_v6_C_Rust共用合同收口/19-邻居围栏真实排空与耐久后继Capability热交接合同.md)。

## Global Constraints

- 在当前`v6-simplified-rust`工作树续做；开始基线`b9913d4`。不暂存、不提交、不推送、不新建Tag、不改Vault，不枚举/操作串口、USB或Probe。
- 保留失败证据。Host回归、纯交叉编译不替代真实密码、Flash/Witness/掉电、物理打点或MCU任务栈验收。
- 所有跨Owner调用由Coordinator编排，唯一原子RX归属。Provider/Driver使用实际CallbackGate，不增加进程全局可变状态。
- 只使用既有C0/C1、Opcode、正文、Tag和分片合同；不增加普通数据头，不保留V1 Reauth兼容分支。
- 首次JOIN不能用Final或typed DTO冒充本端Identity/Security耐久Proof；回读前不发送相应Offer/Commit或激活Session。
- Challenge起点由Coordinator在原事务开始捕获并固定，迟到输入不得重建起点或延长原Deadline。
- 更新前先围栏；UNKNOWN、cancel失败、旧RX、Control/Relay证明和未消费App事件都不能靠清零伪造退休。
- 新Session不继承旧ACL、Profile、Capability、Route/Reverse或Nonce计数；既有独立Origin的计数不随Hop换代重置。
- 保持原单函数和完整协议链栈门限，Nano/Lite/Full为768/1536/3072 B；大暂存使用调用方固定存储，不在栈复制Owner。

## Review Focus

1. 受损/迟到/错身份/错阶段的Offer、Commit、Final不能造成权限发布；持久化异步失败不丢Holder。
2. 两端提交不一致后不得回退Session/Key；新Session必须有实际本地回读和当前父域证明。
3. Native排队样本在换代后不能凭旧scope交付，旧发送不得借新Session重放或延期。
4. 未知物理终态阻止交接，Link reopen不等于排空；回调重入及stop后不得复活。
5. C/Rust共同字节、方向、权限和期限一致；Feature OFF不把动态模块带进最小Core。
