## 1. 使用规则

本清单是 v6 破坏性重构的唯一兼容资产销账表。v5 只保存在上述 Git 分支和 Tag 中；
不得把旧源码复制到 v6 的 `archive/`、`legacy/` 或其他可编译目录。每个旧资产只有一个
`removal_stage`，完成该阶段时必须同时更新状态、提交号与负向门禁。

状态只允许：

- `PENDING`：仍存在于 v6 开发树；
- `REMOVED`：已删除且本行门禁通过；
- `REPLACED`：旧资产删除，v6 替代物和拒绝旧输入门禁均已通过；
- `EXTERNAL_GO`：最终统一外审确认；当前尚未填写。

V6-15 的 `REMOVED/REPLACED` 只表示当前工作树已经完成删除、替代和软件自审，不能替代最终
外审，也不能解除硬件/工具链 HOLD。

## 3. 必须保留的演进安全门

以下不是兼容层，禁止按本清单删除：

- Version、Magic、Schema、长度和保留位的严格拒绝；
- `struct_size/api_version` 或 v6 等价的 ABI 合同校验；
- Feature Manifest、Layout Hash 和跨 Translation Unit 一致性；
- v6 节点之间的认证 Capability 协商；
- Nano/Lite/Full 与 Optional Feature 的编译期裁剪；
- v4/v5 Frame、Record、Opcode 和配置输入必须失败关闭的负向测试。

## 4. V6-15 最终归零门禁

V6-15 必须把本表转换为仓库内可执行 denylist。至少覆盖：

```text
rg: 旧协议宏、枚举、函数、文件、CMake Option/Target
nm: v6 发布 archive/export 中的旧公共符号
```
