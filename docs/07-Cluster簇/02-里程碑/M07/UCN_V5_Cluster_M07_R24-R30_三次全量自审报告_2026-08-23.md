## R29：精确 Backup ACK 授权

原无上下文 `commit_allowed()` 只能表示“某个 Backup 曾经 stage/ACK”，不足以授权当前 Commit。现新增 `commit_allowed_for_tx(gate, tx, ...)`：

- 无 Backup 时仅允许显式 non-HA policy；
- 有 Backup 时同时验证 active `transaction_id`、由当前 Joint `C_new` 推导的 immutable config ref、当前绑定 Backup ID、实际 ACK source；
- `begin_commit()` 在 Config-store recovery 和 Provider `submit()` 前调用它；
- `joint_runtime_commit()` 在 durable Commit 后、写 runtime/member 前再次调用它；
- 旧 helper 降为诊断/单元测试状态查询，不能作为 Commit 许可证。

回归覆盖：旧 ACK transaction、相同 txid 但不同 C_new、ACK source/Backup 不同均拒绝；owner 路径均断言零 submit 与 durable `PREPARED` 不变；runtime 路径断言 runtime/member 逐字节不变。

## R30：初始化回调重入

`owner_init()` 接收的 owner 允许尚未初始化，不能读取其 `io_active`。因此 Provider foreign callback 的动态范围门移动到模块私有的 `provider_callback_owner`：

- init、load、submit、poll 在调用 Provider 前占用该门，返回后释放；
- 任一嵌套 Provider I/O（包括相同 owner 的递归 init）返回 `UCN_ERR_STATE`；
- 门采用单 callback fail-closed，嵌套不同 owner 也拒绝，避免外部 callback 在未定义的交错事务中改变任何 owner；
- 初始 load 中递归 init 会在复制、清零和任何字段写入前返回，因此外层 owner 状态不变。

fake Provider 在 load/submit/poll 中递归调用 init、Prepare、Joint、Commit、Abort、Poll；所有入口均返回 `UCN_ERR_STATE`。递归 init 额外比较调用前后 owner 的完整对象表示，证明无状态改变、无第二次 submit。
