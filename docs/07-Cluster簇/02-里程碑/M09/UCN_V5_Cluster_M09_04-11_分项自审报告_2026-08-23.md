# UCN V5 Cluster M09-04..11 分项自审报告（2026-08-23）

## 共同范围与隔离

本报告中的 `backup_mirror`、`backup_sync`、`backup_profile` 都是独立 value-model/实验 owner。它们不解析原始 v4 frame、不调用 `ucn_cluster_receive()`、不发送控制帧、不修改 `ucn_cluster_t`，更不授予 Authority 或 M10 Takeover。M05 顶层 `AUDIT HOLD` 不变。

## 09-04：SYNC_MEMBER / SYNC_END 与 atomic swap

- Snapshot 控制序列严格固定为 `SYNC_BEGIN=0`、`SYNC_MEMBER=1..N`、`SYNC_END=N+1`。每条 Member 必须是 assigned Head source、exact active SnapshotEpoch/Config、strict next sequence、unique ID、valid nonzero nonce。
- hash 逐字段编码，不对有 padding 的 C object 直接 `memcmp/hash`。
- END 只在 final sequence、count、hash、initial coverage 都相符时调用 mirror 的 candidate atomic swap；错误 END/Member 不污染 committed。
- 自审：nonzero BEGIN、把最后 Member sequence 冒充 END、空 Snapshot 的 `END=0`、乱序、hash 错、Config refresh 中 END、coverage `SUSPECT` 和 abort 后 committed 保留均已覆盖。**PASS**。

## 09-05：BACKUP_READY 精确绑定

- READY 验证 Backup source、完整 committed SnapshotEpoch（含 cluster/term/head/backup/generation/snapshot/config）、final sequence 和 hash。
- 验证为纯函数、零写回；旧 snapshot、错误 sender、错误 sequence/hash 都拒绝。**PASS**。

## 09-06：Delta

- Delta 必须 exact committed SnapshotEpoch、active Config 和 prior hash，sequence 必须连续，且只能命中已由 committed full Snapshot 证明的 member。
- Delta 仅可更新 nonce/lease/keepalive 等动态 freshness 字段；新增 member、改变 voting/status/wire/capability/provisional 等静态资格字段或 nonce 回退一律 no-write 拒绝。
- stale 无写回；gap 不改 committed，仅置 `resync_required`；staging 期间拒绝 Delta，避免旧 snapshot 与 refresh 交叉写入。
- candidate table/hash 成功后才替换 committed。**PASS**。

## 09-07：首次 Coverage

- Stable 检查唯一 voter set；Joint 同时检查 old/new set。每个受保护 voter 都必须有 sorted canonical coverage entry，且 state 为 `ADMITTED`。
- non-voter/provisional legacy 不属于 Config voter set，因此明确不参加首次 READY predicate；缺失/SUSPECT/REMOVED/脏 tail 均拒绝。**PASS**。

## 09-08：Coverage Grace

- 已有 committed mirror 后，受保护 voter 的**明确** `SUSPECT` 才 arm `UCN_CLUSTER_BACKUP_COVERAGE_GRACE_MS`；使用公共 modulo-32-bit deadline helpers。
- grace 内恢复清 deadline 且继续 eligible；到期后永久 `takeover_ineligible`。已 Core 确认的 `REMOVED` 或缺失的 protected-voter coverage entry 都立即设为永久 `takeover_ineligible`，不等待 grace；恢复 ADMITTED 也不能复活，只有新 assignment init 才可能恢复。
- `UINT32_MAX` 跨回绕、SUSPECT flap/恢复、REMOVED immediate fence、Stable/Joint missing voter、ADMITTED-after-missing no-revive 均覆盖。**R01 DONE / 外部复审 GO（受限范围）**；M09 整体仍等待 M08 外审依赖。

## 09-09：无回绕

- Snapshot serial 到 rotation boundary 前无法开始，返回 `UCN_ERR_EXHAUSTED` 且无写回。
- `next_generation()` 仅严格递增；新 owner 可从 Snapshot 1 发起 full sync。generation 即将耗尽时拒绝并指向 M13 Rekey，绝不 `MAX→1`。**PASS**。

## 09-10：Strict Backup Profile

- 需要 Runtime member、committed/eligible、Head-capable、Core ADMITTED、无 cooldown/blacklist、v4、Backup/Joint Config/Persistence bits、完整 mirror capacity 与合法 score。
- selector 以 `head_score DESC, node_id ASC` 为唯一结果；无候选时 output 保持 sentinel，返回每个候选可诊断 reason。**PASS**。
