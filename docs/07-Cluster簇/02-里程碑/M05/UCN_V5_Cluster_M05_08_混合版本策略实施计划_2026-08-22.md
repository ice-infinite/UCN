# CLV2-05-08 混合版本策略实施计划（2026-08-22）

## 1. 目标与范围

本项把 M05 已冻结的双版本事实收敛为一个**私有、无状态、fail-closed** 的判定合同：

- `Strict v4`：v3 节点不得承担 Head、Backup 或 Voter；
- `v4 + 显式 legacy`：v3 仅可请求 `LEGACY_NON_VOTING_MEMBER`，不能静默升级为任何安全角色；
- v4 节点的 capability 是否满足某项后续角色要求，由调用者显式传入的 required-bit 集合判断；本项不自行选举、不读取 Member 表、不授予 Authority。

本项不是 M06 的 Member 生命周期实现，也不是 M08/M10 的资格、quorum 或 Authority 实现。它不改变 RFC4、v3 生产消息、默认关闭的 v4 encoder，且不得向 `src/extended/ucn_cluster.c`、生产 RX/TX/FSM 或 Adapter 接线。

## 2. 设计合同

### 2.1 私有输入

在 private semantic header 中新增：

| 值 | 含义 |
|---|---|
| `STRICT_V4` | 只接受 v4 peer；任何 v3 请求均拒绝。 |
| `ALLOW_V3_NON_VOTING_LEGACY` | 仅显式允许 v3 的 legacy non-voting 请求。 |
| `V3` / `V4` | 已由严格 32B/v3、40B/v4 dispatcher 得出的 format，不接受未知 format。 |
| `LEGACY_NON_VOTING_MEMBER` | v3 唯一可通过的请求类；它不是 M06 的 Runtime Member 状态。 |
| `VOTER` / `BACKUP` / `HEAD` | 未来 owner 想要求的安全类；本 helper 只判版本/能力前置条件，不产生角色或资格。 |
| `required_v4_capabilities` | 未来流程为所请求的 v4 类显式给出的 RFC4 六位 capability 子集；本 helper 不硬编码选举策略。 |

### 2.2 纯函数规则

1. `policy`、`peer_format`、`requested_class` 和 `required_v4_capabilities` 任一非法，返回 `UCN_ERR_ARGUMENT`。
2. 对 `V3`：要求的 capability 必须为零；只有 `ALLOW_V3_NON_VOTING_LEGACY + LEGACY_NON_VOTING_MEMBER` 返回 `UCN_OK`。所有 Strict v4 请求、Voter、Backup、Head 和其他请求类返回 `UCN_ERR_STATE`。
3. 对 `V4`：仅当 peer offer 是有效 RFC4 offer、其范围包含 format 4，且 offer 的 capability 覆盖调用者传入的 required-bit 集合时返回 `UCN_OK`；缺 capability 返回 `UCN_ERR_STATE`。
4. 成功只说明“满足混合版本 wire 前置条件”，不等于 Join、Committed Member、Voter、Backup、Head、Takeover 或 Authority 获准。
5. 函数不保存 peer、没有时钟、没有 I/O、没有 output state；因此拒绝路径天然无副作用。

这样能避免在 M05 过早把 capability bit 当成真实角色授权，同时为 M06 的 explicit legacy member 与 M10/M13 的 exact capability requirements 提供单一、可测的前置合同。

## 3. 实施拆分与自审点

| 子项 | 修改 | 自审要点 |
|---|---|---|
| 08-A | private enum + pure helper declaration | 不进入 public header；不扩大 `ucn_cluster_t`。 |
| 08-B | codec 内实现 | 使用既有 wire-offer validator；未知 bit/format fail-closed；不触碰 FSM。 |
| 08-C | 混合矩阵测试 | Strict v3 全拒绝、explicit legacy 只放行 non-voting、v4 required-bit pass/fail、非法输入无副作用。 |
| 08-D | 隔离与回归 | grep `src/extended/ucn_cluster.c` 无 v4 helper 引用；encoder 默认仍为 0；完整构建矩阵。 |

## 4. 验收矩阵

| policy | peer | requested class | expected |
|---|---|---|---|
| Strict v4 | v3 | legacy / voter / backup / head | 全部拒绝 |
| Explicit legacy | v3 | legacy non-voting | 通过（required bits 必为 0） |
| Explicit legacy | v3 | voter / backup / head | 拒绝 |
| 任一模式 | v4 | non-voting / voter / backup / head | 仅在有效 offer 覆盖调用方 required bits 时通过 |
| 任一模式 | unknown format、未知 policy/class、未知 required bit | 拒绝为参数错误 |

## 5. 固定边界与后续归属

- **M06** 才把允许的 legacy 请求变成 bounded Runtime/Provisional Member，并规定它不计入 voter set。
- **M08/M10/M11/M13** 才能根据 Config、quorum、持久化、epoch 与 transaction 决定 Head/Backup/Takeover/Handover/Rekey；本项不得越权。
- **M14** 才允许将 Strict v4 作为推荐默认并裁剪 v3 compatibility。

完成代码和自审后，`CLV2-05-08` 只能标为 `CODE COMPLETE / AUDIT HOLD（待独立审计）`。M05 整体在混合策略、bytes migration、fuzz、diagnostics 和 compatibility gate 均完成并通过独立审计前，始终保持 `AUDIT HOLD`。
