# UCN V5 Cluster M05-06：冻结字段顺序外审 P1 整改计划

- 日期：2026-08-22
- 状态：`DONE / 外部复审 GO（受限范围）`
- 来源：05-06 外部审计 P1；05-07 为受限 GO，不受本整改回退影响。

## 问题确认

原 Type 20..33 registry test 只固定编号、payload 长度、role/flag、zero-tail，并让
`semantic_from_frame()` 与 `semantic_to_frame()` 做往返。原构造样本多处复用 `1`，所以
如果 parser 与 builder 同时交换同一 Type 的两个字段，往返仍可能通过，不能证明 RFC4
的 P0..P5 字段顺序没有漂移。

## 整改范围

只改 focused codec test：

1. **DONE**：建立独立于 `make_valid_frame()` 的 Type 20..33 fixture table；每个可写 P0..P5 均选用
   彼此可区分且能通过 RFC4 structural gate 的值。
2. **DONE**：将每个 fixture raw frame 解析为 semantic message，并逐项断言对应的具名 payload 字段。
3. **DONE**：使用该 semantic message 重新 builder，并逐项断言 P0..P5 与 fixture table 完全一致。
4. **DONE**：保留原 Type ID、role、flag、zero-tail 和错误无写回检查。

## 明确非目标

- 不改变 RFC4、public header、raw codec、private payload struct、v4 encoder 开关或生产
  RX/TX/FSM。
- 不实现 Config/Handover/Rekey 的业务状态机、Authority、quorum、persistence 或 mixed-version policy。

## 外部复审结论

2026-08-22 外部复审确认：fixture 独立于 `make_valid_frame()`；每个可写字段取值可区分且
通过 raw gate；Type 20..33 的具名 parser 字段与 exact builder P0..P5 全部对应 RFC4。
05-06 获 `GO（受限范围）`。该签字不接通任何生产 v4 RX/TX/FSM，也不解除 M05 的
`AUDIT HOLD`。

## 验收

- 任一 Type 的 parser 字段调换会由具名字段断言失败。
- 任一 Type 的 builder word 调换会由独立 P0..P5 断言失败。
- Full/Lite/Nano/MSVC/WSL ASan/UBSan/`-fanalyzer` 回归通过，production v4 接线仍为零。
