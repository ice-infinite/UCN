# CLV2-05-10 外审 P1 整改计划：RFC4 全字段 Parser Contract（2026-08-22）

## 审计结论核实

**成立。** 原 05-10 矩阵只对每个 Type 破坏一个必填 word、至多一个 zero-tail word，并仅把 Role 改为 `DISABLED`。它不能稳定锁住同一 Type 的其余 payload 域、范围/计数、专属 Node ID、全部 zero-tail 字段，或“枚举合法但该 Type 不允许”的 Role。

本次整改只加强测试，不放宽/修改 v4 parser 和生产路径。M05 继续 `AUDIT HOLD`。

## 整改设计

建立独立的 RFC4 fixture table，不从 `ucn_cluster_wire_v4_frame_is_valid()` 或其他被测 validator 推导规则。每条 Type 记录：

1. Type、允许 sender-role 集合与 flags 合同；
2. `P0..P5` 的逐字段类别：zero、nonce、serial、可选 serial、Node ID、Cluster ID、successor Cluster、duration、score/capacity、wire offer、selected offer、reason、count/ordinal、capability、certificate mask/descriptor 或不受 codec 约束的 raw carrier；
3. Type 12 marker 与成员记录两种 flags/尾字段模式；Type 27 跨 Cluster Head 与同 Cluster Backup 两种 Role 模式。

每条规则各自生成 raw 负例，并同时要求：

- raw v4 decode 拒绝且 output 不写回；
- strict dispatch 拒绝且 output 不写回；
- direct semantic parser 拒绝且 output 不写回。

Role 测试枚举全部现有 `ucn_cluster_role_t` 值：允许集必须接受，其他合法枚举值必须拒绝。flags 按 RFC4 合同遍历全部 byte 值；Type 12 先生成合法 marker/record 基线，再验证其 flags/zero-tail 分支。

## 验收

- Config Begin 等多字段 Type 的 P0..P5 每项都有独立、确定性反例；
- ADVERTISE/HEAD_DECLARE 的 P4 与 P5、以及所有其他 zero field 均单独污染；
- Node ID、serial、duration、reason、score、offer、count/ordinal、certificate descriptor 等域都直接覆盖；
- 每 Type 的非归属 Role 均确定性拒绝；
- 原 fixed-seed fuzz 保留为补充，而不是字段覆盖唯一证据；
- Windows Full、WSL ASan/UBSan、WSL analyzer 通过；无生产 v4 接线。

## 整改完成与自审

- 已新增 `v4_rfc4_fixture_t`：33 行固定 Type、sender-role 集合、flag contract 与 `P0..P5` 字段类别，来源是冻结 RFC4 Type 表而非 `ucn_cluster_wire_v4_frame_is_valid()`。
- 每个 Type 遍历所有当前 `ucn_cluster_role_t` 枚举值；允许集合须通过，其余（包括枚举合法但不属于该 Type 的角色）须在 raw decode、strict dispatch、semantic parser 三层拒绝且 output 不写回。
- 每个 Type 遍历完整 `0..255` flag 域；Type 12 的 `BEGIN/END` 先切为合法 marker 零尾，再逐项验证 marker P3/P4/P5 的 non-zero 污染。Config Member 与 Certificate 的两个各自合法 flag 也都经过正向路径。
- 每个受 codec 约束的 P 字段均按类型分别注入 zero、serial threshold 外、broadcast、duration 上界、score/capability reserved bit、offer 保留位、reason、count/ordinal、mask/descriptor 等反例。`HEAD_TAKEOVER.P5` CRC carrier 与 `TAKEOVER_CERTIFICATE.P5` bitmap raw carrier 标为 `ANY`：RFC4 把 CRC/quorum/bitmap 上界留给后续 M10，codec 不能伪造不存在的本地 Config 约束。
- `JOIN_ACCEPT.selected_wire_offer` 只在 codec 层验证 selected 非零、保留高位和 capability reserved bits；其是否位于双方 offer 交集需 M05-07 之后的 peer context，故不把 `selected=3` 误判为 raw malformed。

自审门禁：Windows GCC Full `28/28`、WSL ASan/UBSan `18/18`、WSL `-fanalyzer -Wall -Wextra -Werror` `5/5` 均通过。外部复审随后确认本项 **GO（受限范围）**，并独立复跑 Windows Full `2/2`、WSL ASan/UBSan `25/25`；05-10 已为 **DONE**。M05 总体不解除 hold。
