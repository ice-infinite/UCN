# CLV2-05-08 混合版本策略自审报告（2026-08-22）

## 1. 自审范围

本次只实现和核对 `CLV2-05-08` 的 private codec policy predicate 与 focused tests。审计基线是当前未提交工作区；不将此前未提交的其他 M04/M05 修改归因于本项。

明确排除：RFC4 字节变化、public API、v3 生产报文、v4 生产 encoder、Cluster RX/TX/FSM、Member/Config/Quorum/Authority、Adapter 与实机测试。

## 2. 实现核对

| 项目 | 实际结果 |
|---|---|
| 私有位置 | `src/extended/cluster/ucn_cluster_wire_v4_semantic.h`；没有加入 `include/ucn/`。 |
| 状态/资源 | 只含 enum 和纯函数；未增加 `ucn_cluster_t` 字段、静态 peer 表、动态内存、定时器或 I/O。 |
| Strict v4 | 对 v3 的 non-voting、voter、backup、head 四类请求全部返回 `UCN_ERR_STATE`。 |
| Explicit legacy | 只允许 `V3 + NON_VOTING_MEMBER + required_bits=0`；voter/backup/head 均拒绝。 |
| v3 capability | v3 输入携带 offer 或 required v4 bit 一律 `UCN_ERR_ARGUMENT`，不能伪造 v4 能力。 |
| v4 capability | v4 必须带合法、包含 format 4 的 RFC4 offer；只检查调用方明确要求的六位 capability 子集。缺 bit 返回 `UCN_ERR_STATE`。 |
| 角色边界 | helper 的 `requested_class` 只是未来 transaction 的 contract label；它不读取任何 Cluster state，也不决定真实 Member/Voter/Backup/Head/Authority。 |
| 失败副作用 | API 没有 output/state 参数；所有拒绝均在无写入、无发送、无持久化的纯判定中结束。 |

关键设计选择：没有把 BACKUP/TAKEOVER/PERSISTENCE 等 bit 硬编码成当前 Head/Backup 资格规则。05-07 已冻结这些 bit 只是 Wire capability；真正的 member status、Config、quorum、epoch、persistence 与 Authority 条件仍由 M06、M08、M10、M11、M13 的 owning FSM 实现。这样避免 M05 在缺少 frozen Config 和持久化事务的条件下提前产生授权路径。

## 3. 定向矩阵

`test_mixed_version_policy()` 已覆盖：

1. Strict v4 + v3：non-voting、voter、backup、head 全拒绝；
2. explicit legacy + v3：仅 non-voting 通过，三类安全请求全拒绝；
3. v4：普通、Backup required-bit、Head/Takover required-bit 正例，以及缺 Persistence bit 的拒绝；
4. v3 伪造 offer/required bit、未知 policy/format/class/required bit、非法 v4 offer、v4 缺 offer 全部 fail-closed。

这不是正式 Join 或选举覆盖；矩阵只证明版本/offer 前置条件，不声称运行期角色转移已实现。
