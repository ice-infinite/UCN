# CLV2-05-12：Host 双格式兼容门禁自审报告

日期：2026-08-22

## 结论

**DONE / 外部复审 GO（受限范围）。** Host 双格式验证、生产隔离验证以及外审指出的默认 encoder output 覆盖 P1 均已闭环；这不是 M05 整体放行，更不是生产或实机结论。

## 外审 P1 整改

外审指出：原 encoder-closed 回归只检查 output 首尾，不能支撑“无 output 写入”的完整表述。该判断成立。

整改后，测试在调用前复制完整 `expected_output[40]` 哨兵，再对 `memcmp(output, expected_output, sizeof(output)) == 0` 做唯一的完整断言；任何中间字节写入都会导致回归失败。整改没有改动 encoder 实现或任何生产收发路径。

整改后实际重跑：Windows GCC Full `29/29`、Lite `29/29`、Nano `19/19`；WSL ASan/UBSan `19/19`；WSL `-fanalyzer -Wall -Wextra -Werror` `6/6`。生产/Adapter/runtime 静态隔离扫描与 `git diff --check` 同步通过。

外部复审随后确认 P1 完整关闭，独立复跑 Windows Full `3/3`、WSL ASan/UBSan `26/26` 通过；并复核 `UCN_CLUSTER_WIRE_V4_ENCODER_ENABLED=1` 仅存在于两个测试 target、production Cluster/Adapter 无 v4 API 接线。该外审 GO 仅覆盖 05-12 的 Host 兼容门禁。

## 已知边界

- 本测试只验证 codec/dispatcher 的 Host 行为；没有生产 v4 RX owner，也没有把任何 v4 frame 写入 `ucn_cluster_t`、View 或 Stats。
- v4 `encode` 在生产库仍关闭；新 target 的局部 macro 不构成生产发送授权。
- Member、Voter、Backup、Head、Authority、quorum、Config、Certificate CRC/验证、真实 Bearer/硬件互通仍分别属于后续受控里程碑。
- 因此 M05 顶层继续 **AUDIT HOLD**；外部审计通过前，不得开始生产 v4 RX/TX/FSM 接线。
