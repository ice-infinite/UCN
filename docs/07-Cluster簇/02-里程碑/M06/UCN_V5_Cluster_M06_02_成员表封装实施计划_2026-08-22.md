# CLV2-06-02：Primary Member Table 封装实施计划

日期：2026-08-22

状态：CODE COMPLETE / AUDIT HOLD（待外部审计）

## 1. 目的与范围

把当前散落在 `ucn_cluster_t.members[]` 上的成员存储收敛为固定容量的 `ucn_cluster_member_table_t primary_members`，让存储对象本身具有明确的表语义，而不再以一个无上下文的裸数组表达 Head Runtime Member 与 Backup mirror。

本项仍是**等价结构重构**：同一时刻只有一个 primary 表，不增加 staging 表，不改变现有 v3 Join、Backup sync、Takeover、容量或成员循环的判定。Head/Recovery Head 将该表解释为 Runtime Member table；Backup 将同一块受限存储解释为已同步的 committed mirror。M09 才会增加独立 committed/staging 双表，M07/M08 才会让 Config/Voter/Authority 使用新模型。

## 2. 固定数据合同

```text
ucn_cluster_member_table_t primary_members
  slots[UCN_CLUSTER_MAX_MEMBERS]
```

- table 只保存固定数组，不保存动态指针、堆对象、隐藏容量计数或 Wire v4 frame。
- 全零 table 为 canonical empty table；每个 slot 必须满足 06-01 的 `ucn_cluster_member_record_is_valid()` 合同。
- 公开成员 summary API 的 `table_index` 语义保持“primary table 的固定 slot index”，不改 ABI 行为。
- 所有当前 producer/consumer 均显式访问 `primary_members.slots[]`；删除生产代码中的 `cluster->members[]`。

## 3. 角色解释与禁止事项

| 当前运行角色 | `primary_members` 的解释 | 本项禁止行为 |
|---|---|---|
| Head / Recovery Head | Runtime Member table | 不将 `voting/status` 变成资格、容量或 Authority 判定 |
| Backup | 已同步 committed mirror | 不增加 staging mirror，不修改 Takeover quorum 语义 |
| Member / Candidate / Detached | 当前 legacy 状态遗留/清理表 | 不创建 v4 Provisional Join 或 Voter set |

特别地，`primary_members` 是受限 RAM 过渡对象，不表示“已经有 committed voter table”。所有 v4 RX/TX/FSM、真实资格选择、Voter quorum、Authority 与 production v4 encoder 都不属于本项。

## 4. 执行步骤与自审门禁

1. 在成员模型公共头定义固定 `ucn_cluster_member_table_t`，并提供只读的空表/record 合法性与 occupied-count 合同。
2. 将 `ucn_cluster_t.members[]` 替换为 `primary_members`；Membership、Backup、Recovery、Merge、Facade 与测试使用显式 `primary_members.slots[]`。
3. 把内部 helper 改名为 primary-table 语义，避免后续把 Runtime、committed mirror 与 staging table 混入同一个无语义 helper。
4. 扩展独立成员模型测试：全零 table、非 canonical slot、occupied count、固定 slot 数据保持；保留真实 v3 Join → Backup failover → Recovery 回归。
5. 每个修改小结后做代码自审：无 `cluster->members` 残留、无新增 v4/Adapter 引用、无 status/voting 决策读取；最后重建 Full/Lite/Nano/Service OFF、ASan/UBSan、`-fanalyzer` 与 64-node clean simulation。

完成自审后仍保持 `CODE COMPLETE / AUDIT HOLD（待外部审计）`；不得进入 06-03 或解除 M05 顶层 `AUDIT HOLD`。

## 5. 实施与自审结果

- `ucn_cluster_membership.h` 新增固定 `ucn_cluster_member_table_t`、逐槽合法性和 occupied-count API；它仍不含 Wire v4 或权限语义。
- `ucn_cluster_t.members[]` 已收敛为 `primary_members.slots[]`。Membership、Backup、Recovery、Merge、Facade、Federation 测试和 Cluster 测试不再访问旧裸数组；内部 helper 全部采用 `primary_member_*` 命名。
- 结构封装不改变存储容量：Full/Lite/Nano/Service OFF 的 Host `cluster_bytes` 均保持 `1392 B`；相对 06-01 为 `+0 B`。
- 详细的测试、低资源修正和隔离证据见 `UCN_V5_Cluster_M06_02_成员表封装自审报告_2026-08-22.md`。
