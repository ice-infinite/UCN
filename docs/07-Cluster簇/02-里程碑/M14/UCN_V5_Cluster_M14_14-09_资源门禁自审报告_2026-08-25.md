# CLV2-14-09 资源门禁自审报告

## 结论

`CLV2-14-09` 软件范围完成并自审通过。当前门禁证明 Host Release 构建满足预设静态预算、Cluster 路径没有动态内存调用、Core-only 产品不承担 Cluster archive 成本；它不等于 MCU linker map、任务栈水位或真实控制流量实测。

## 固定门禁

| 项目 | 当前结果 | 阈值 |
|---|---:|---:|
| Cluster storage object | 1608 B | 2048 B |
| Cluster archive `.text` | 133559 B | 147456 B |
| Cluster archive `.rodata` | 992 B | 16384 B |
| Cluster archive `.bss` | 8 B | 128 B |
| 最大 GCC 静态栈帧 | 1840 B | 2048 B |
| 动态分配调用 | 0 | 0 |

资源脚本曾检出最大静态栈帧 2688 B。通过阻止持久化状态比较和 Config 序列化 helper 在 Release 下被过度内联，最终降至 1840 B；Cluster text 同时由 138023 B 降至 133559 B。未修改 Wire 或状态机语义。

## Profile 与模块结果

`docs/results/M14/cluster_resource_profiles_2026-08-25.csv` 显示 Full/Lite/Nano 在“显式链接 Cluster”场景下均为 1608 B object、133559 B text。当前 Profile 不裁剪 Cluster 内部能力，这是已知限制，不能声称 Lite/Nano 的 Cluster 成本更低。

Feature-OFF 的已验证含义是：Cluster 继续 `EXCLUDE_FROM_ALL`，core-only 构建不生成/不链接 Cluster archive。Wire v3、Wire v4、dual dispatcher、Takeover/Handover/Rekey 实验模块的独立 archive 成本记录在 `cluster_resource_modules_2026-08-25.csv`。

## 自动化

- `UCN_CLUSTER_STORAGE_BUDGET_BYTES` 提供默认 2048 B 编译期预算，可由产品全局配置覆盖；
- `tools/check_cluster_resource_contract.py` 拒绝 Cluster 源码出现 `malloc/calloc/realloc/free`；
- `tools/m14_resource_gate.sh` 从干净 Release 构建生成 Profile、模块、静态栈和 archive section 结果，并执行硬阈值；
- CTest 注册 `ucn_cluster_resource_contract_gate`；
- 14-10 docs gate 加入后的最终矩阵为 Full 57/57、Lite 50/50、Nano 40/40、Service-OFF 50/50，均通过。

## 证据边界

- `.su` 是 GCC 静态栈帧估算，不含 ISR 嵌套、RTOS 调度和调用链总栈；
- archive section 是 Host object 证据，不是 ESP32/STM32 最终固件 map；
- 14-07 的控制发送峰值 13/14 条每 Node 每秒来自模拟，不是射频环境实测；
- MCU RAM/Flash、任务栈水位和真实吞吐仍由 14-08 验证。
