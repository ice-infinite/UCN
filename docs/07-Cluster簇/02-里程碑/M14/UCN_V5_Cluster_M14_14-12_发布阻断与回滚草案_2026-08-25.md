# CLV2-14-12 发布阻断、兼容矩阵与回滚草案

## 当前决定

**BLOCKED / NO TAG / NO RELEASE**。本文件只是为后续发布准备可审计的兼容与回滚边界，不创建 tag，也不声称 Target v2 可生产使用。

## 兼容矩阵

| 维度 | 当前值 | 兼容策略 |
|---|---|---|
| Core UCN protocol | v5 | Cluster format 独立演进 |
| Cluster API | v2 | 源码/ABI 破坏性升级，必须全量重编译 |
| Cluster storage | layout v2 | 唯一 Owner 包含 storage header；禁止跨版本复用对象 image |
| production Cluster Wire | v3 / 32 B / Type 1..19 | 当前默认；Authority 类 v3 frame fail-closed |
| recommended Cluster Wire | v4 / 40 B / Type 1..33 | 隔离 codec；production 未启用 |
| Persistence writer | schema v4 / 388 B | v1/v2 280 B、v3 292 B 只读迁移 |
| Profile | Full/Lite/Nano | 显式链接 Cluster 的当前成本相同 |

## 回滚层次

1. **构建回滚**：不链接 `ucn_cluster` 与实验 archive，Core-only 不承担 Cluster 成本；
2. **Wire 回滚**：保持默认 v3 encoder/RX，不启用 v4；禁止同一网络混用未协商的 32/40 B；
3. **组件回滚**：Takeover/Handover/Rekey 均为独立 default-OFF archive，可从产品链接表移除；
4. **介质回滚**：升级 writer 前保存原始槽；schema v4 写入后，旧固件若不理解 388 B 必须拒绝启动或先执行明确降级迁移，禁止盲写；
5. **固件回滚**：记录 Git commit、toolchain、配置、固件 SHA256 和介质 schema；不得只保存二进制文件名。

## 最终发布包必须包含

- baseline→release diff 与审计签字；
- 构建工具链锁定信息和干净构建命令；
- Full/Lite/Nano/Service-OFF、Sanitizer、Analyzer、Release 优化矩阵；
- 资源 CSV、MCU linker map、栈水位和控制流量；
- 四板拓扑、固件 Hash、原始串口/掉电/介质日志；
- Wire/API/storage/persistence 兼容矩阵；
- 已验证的回滚演练记录。

上述任一项缺失时不得建立 Cluster v4/Target v2 release tag。
