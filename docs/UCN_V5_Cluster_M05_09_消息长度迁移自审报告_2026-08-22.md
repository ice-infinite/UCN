## 真实 Carrier 回归

回归均使用普通 W0 UCN Frame 和 40 B payload，不调用 v4 Cluster decoder/encoder，不进入 Cluster FSM。

| Bearer | 实测链路 | 结果 |
|---|---|---|
| Stream | COBS → Stream Source → Adapter Queue → Node endpoint | 40 B 完整逐字节交付。见 `tests/test_stream_source.c:316`。 |
| CAN-FD direct | 57 B W0 frame → 64 B DLC → CAN Source → endpoint | 40 B 完整逐字节交付；7 B 零 padding 与非零 padding 拒绝均已回归。见 `tests/test_can_source.c:420`。 |
| Classic CAN carrier | 57 B W0 frame → 12 个 START/CONTINUE 物理帧 → reassembly → endpoint | 40 B 完整逐字节交付，固定断言 12 段。见 `tests/test_can_source.c:420`。 |

W0 header 是 17 B，故 40 B payload 的 encoded UCN Frame 为 57 B。带更长路由/安全头的 UCN Frame 可能超过 CAN-FD direct 的 64 B 上界；本项保留既有 `UCN_ERR_TOO_LARGE` fail-closed 行为，产品必须改用 Classic Carrier、其他可分片 Bearer 或更大 MTU，不能将其误称为 CAN-FD direct 自动兼容。

## 自审边界

- `src/extended/ucn_cluster.c` 未出现 `ucn_cluster_wire_v4` 调用；生产 Cluster 仍只走 v3 32 B alias。
- `UCN_CLUSTER_WIRE_V4_ENCODER_ENABLED` 仍默认 `0`。
- 没有变更 Core Wire W0-W3、Node、Adapter runtime、Cluster endpoint、资格、quorum、Authority、Config 或 FSM。
- 没有扩大 `ucn_cluster_t`，没有引入动态内存。

因此，本项证明的是**承载准备完成**，不是 v4 控制协议、v4 Authority 或 mixed-version 网络已经上线。
