# 08 · 自动分簇与簇头选举可行性与当前实现

> 结论：自动分簇适合 UCN 的 MCU-first、固定资源和局部自治方向。当前已完成一个**可选单层 Cluster Extended 首阶段**：本地邻居输入、分布式评分选举、成员加入/容量拒绝、租约保活和簇头失效重选。它还不是簇间路由，也不能单独带来万级通信能力。

## 1. 为什么要分簇

分簇的目标不是让每个节点知道全网，而是让每个节点只承担有限职责：

- 普通成员只维护一跳邻居、当前簇头和必要业务路线；
- 簇头维护有界成员租约，并代表本簇接入上层；
- 上层只识别簇 Locator/网关，不保存所有成员的逐节点 Route；
- 拓扑变化优先在簇内消化，避免全网泛洪。

## 2. 现有 Core 原语与正确边界

| 原语 | 分簇用途 | 边界 |
| --- | --- | --- |
| HELLO/Neighbor/Bearer | 提供一跳、已准入、存活的候选集合 | 不是簇成员关系 |
| LC-1/产品评分 | 产品计算簇头能力与稳定性 | 当前 Cluster 接受静态 `head_score`，动态评分待后续接入 |
| Endpoint + Security Policy | 承载 Cluster 控制消息并要求保护 | 生产 AEAD/身份仍归 S02 |
| PATH_INSTALL | 可安装少量严格骨干路径 | 不能替代簇级聚合目录 |
| Node Snapshot | 低频人工诊断 | 不作为实时选举输入，不允许周期全网泛洪 |
| JOIN_PROVIDER | 邻居/网络准入 | 不等同于 Cluster 的 JOIN_REQUEST/ACCEPT |

为避免 Cluster 读取 `ucn_node_t` 私有布局，Core 只新增了 Owner 上下文的只读 `ucn_node_copy_neighbor_summaries()`。该 API 不改变 Wire，也不让 Extended 修改 Neighbor 表。

## 3. 当前首阶段实现

实现位置：

- 公共 API：`include/ucn/ucn_cluster.h`
- 状态机：`src/extended/ucn_cluster.c`
- 单元/集成模拟：`tests/test_cluster.c`
- 规模模拟：`tools/ucn_cluster_sim.c`

`ucn_cluster_t` 是独立静态对象，`ucn_core` 不链接时不增加 Cluster RAM。默认固定容量为 8 Peer、8 Candidate、16 Member；当前 Host x64 对象为 880 B，目标 MCU ABI 必须另测。

控制面使用静态 Endpoint `0xA0`、格式版本 1、固定 28 B Payload。消息包括 ADVERTISE、JOIN_REQUEST/ACCEPT/REJECT、KEEPALIVE、LEAVE 和预留的 Head 宣告/接管/退位类型。所有消息只在已准入一跳 Peer 之间处理；产品可设置 `require_protected_control=true` 失败关闭。

## 4. 选举和成员状态机

```text
DETACHED
  └─观察期到→ CANDIDATE
       ├─本机评分最高→ HEAD
       └─发现更优 Head→ JOIN_PENDING
             ├─JOIN_ACCEPT→ MEMBER
             ├─JOIN_REJECT/超时→ 重试或重新选举
             └─Head 租约失效→ DETACHED

HEAD
  ├─接受成员并刷新租约
  ├─容量已满→ 明确 JOIN_REJECT
  └─成员租约过期→ 释放固定槽
```

比较规则为：更高 `head_score` 优先；同分时较小 Node ID 优先，保证确定性。广告采用轮转 Peer，每次 Step 最多面向一个邻居，避免同一时刻向全部邻居突发。成员发送 Keepalive，簇头和成员都使用权威单调时钟维护租约；Term 与 Nonce 拒绝陈旧控制消息。

当前默认参数：观察 5 s、选举窗口 3 s、广告 1 s、加入重试 1 s、成员保活 2 s、租约 8 s。它们是软件默认值，不是所有无线环境的最佳参数。

## 5. 已验证结果

| 测试 | 当前结果 |
| --- | --- |
| Codec/坏版本/安全门禁 | 通过 |
| 4 节点确定性选举与 3 成员加入 | 通过 |
| 首簇头失效、次优节点接管、其余节点重入簇 | 通过 |
| 簇头容量 1 与额外成员显式拒绝 | 通过 |
| 64/256/1000 节点隔离分组收敛 | 均在确定性模拟约 8.91 s 收敛 |
| 受损链路 64/256/1000 | 15% 丢包、0～40 ms 抖动、5% 重复、短时单向阻断下约 39.66/40.70/41.84 s 收敛 |
| 重复 Head 消解 | 初版受损测试复现永久双 Head；修复后使用确定性排序、连续样本和最小任期消解 |
| 64 节点 Head 故障/成员返回/评分变化 | 分别在事件后约 16.16 s/0.41 s/4.91 s 达到目标状态 |
| 四块 ESP32-S3 单层实测 | 容量 1/2、4/4 Head 故障恢复、120 s 稳定性和 156/156 Ping 通过；独立 Bearer、小时级长稳、功耗与生产安全未完成 |

1000 节点模拟由 125 个互不干扰的 8 节点组构成，用于验证固定状态机不会因总对象数量失效。受损模式已经加入协议消息丢包、延迟/乱序、重复和短时非对称，但仍没有模拟共享无线信道争用、隐藏节点、持续跨簇移动或跨簇竞争。

## 6. 尚未实现

- 从真实电源、能力、邻居质量、队列压力和稳定时长计算/滤波 Head Score 的产品实现；协议侧更新 API 已完成；
- 备用簇头同步和无等待接管；
- 跨边界相邻簇发现、容量协商、完整簇拆分与合并；局部重复 Head 的最小消解已完成；
- 成员 `Node ID → Cluster Locator` 目录；
- 簇间隧道/聚合转发和多级簇；
- Cluster Endpoint 的生产安全策略及密钥生命周期；
- 共享无线争用、隐藏节点、持续跨簇移动和控制风暴压力；协议消息受损/临时离开已完成首轮；
- 独立 Bearer 插拔/冗余介质切换、小时级长稳、功耗和受保护控制；四块 MCU 的真实选举、容量与四轮 Head 复位恢复已完成首轮。

`BACKUP`、`HEAD_TAKEOVER`、`HEAD_STEPDOWN` 已在首版类型空间中保留，但不能据此宣称上述功能已经完成。`head_min_tenure_ms` 当前只用于重复 Head 的本地有界消解；完整簇合并/协同退位仍未闭环。
