## 2. Cluster durable transition 闭环

Transition proof 增加 `started_boot_incarnation` 与 `deadline_us`，二者进入 canonical Record
编码、解码、校验和 reload 语义比较。普通 Vote、READY、Commit 和 Authority 使用点都要求：

```text
proof.boot_incarnation == current snapshot boot_incarnation
now_us < proof.deadline_us
```

`ucn_v6_cluster_step()` 在推进其他租约前处理遗留 transition：Deadline 到达，或 Record 来自
旧启动代际时，构造精确 next snapshot、清空 transition、按原操作类型回到安全角色并持久提交。
公开 `ucn_v6_cluster_abort_transition()` 还要求调用方给出 exact kind/transaction ID，不能用
模糊 Abort 清除另一个并发事务。Provider 失败继续保持 Cluster fault/fail-closed，不把未证明
的 RAM 状态当作 durable 结果。

测试覆盖：显式 exact Abort、恰好 Deadline、重启恢复后旧 Commit 拒绝、随后 step 持久 Abort、
对象和 durable Record 一致。Cluster Record Version 升为 2；Storage Layout 升为 7，不兼容
旧布局，也不提供 v5/v6 迁移猜测。

## 3. Realtime 真正四事件模型

旧 48 B Sample 同时携带远端声称的 `local_sample_us` 与 `offset_us`，虽然经过 E2E 认证，仍
无法证明这些值来自本机物理事件。本轮删除该公共结构、Codec 与 ingest API，替换为：

```text
12 B TIME_SYNC announce = {version, domain, generation, sequence}
40 B TIME_DELAY_RESPONSE = {same key, T1, T4, T1/T4 uncertainty}
local T2 = current Adapter RX atomic item
local T3 = exact Adapter TX completion of DELAY_REQUEST
offset   = ((T1 - T2) + (T4 - T3)) / 2
```

旧 `TIME_FOLLOW_UP` Opcode 同时删除，后续两个 Opcode 连续收敛为 513/514；当前 v6 仍未发布，
因此不保留一个无人消费的兼容编号。

T2/T3 的 event token、Link ID、Link Generation、hardware 标志和 uncertainty 必须有效且互异；
反向 Path、Master Principal、Binding、Session、Route/Path Generation 与响应键必须全部仍是
当前值。差值、求和、绝对值和 uncertainty 聚合使用 checked arithmetic；任一未知、溢出、
过期或错绑都在 Domain 滤波状态写入前拒绝。标准 Runtime 保存固定数量的 exchange slot，
替换/超时会取消自己仍持有的 TX reservation，绝不靠两个 Ring 的顺序配对。

Host 单测只证明事件所有权和算术合同，不证明真实 Driver 给出的 T1～T4 或 uncertainty 上界
正确。该能力仍须在各 Bearer/MCU 上做硬件打点校准。

## 4. 标准 Runtime Owner

`ucn_v6_runtime_owner_t` 只在 Adapter Feature 开启时发布。它持有各模块 Owner 的引用，但不
复制第二份网络状态。`ucn_v6_runtime_make_stack_hooks()` 返回唯一固定顺序：RX ingress、TX
completion、Timer、Security/Capability invalidation、核心失效扇出和 QoS/Adapter submit。

核心所有权规则如下：

1. RX item 在应用返回 CONSUMED/DROP 前不退休；RETRY 保留同一 item；
2. TX completion 先进入固定 release slot，再从 Adapter 精确退休；应用释放暂时失败可重试；
3. Realtime T3 只在 Adapter retirement 成功后提交，避免时间戳与 Buffer 所有权分叉；
4. `ucn_v6_runtime_reopen_link()` 先 quiesce Driver，收集旧 Buffer token，再发布 exact old
   Link Generation invalidation；应用不能绕过扇出直接恢复新代际；
5. Runtime 只让产品提供最终认证 ingress dispatcher、Buffer release 和可选 Endpoint fence，
   不把路由、超时或依赖顺序重新外包给每个产品。

固定 release/time slot 均由编译期 Profile 决定；表满不覆盖。Runtime Storage 已进入 Layout
Hash 和资源报告。Realtime/Cluster 仍按 Feature 条件链接，二者不互相依赖。

## 5. 初始化别名合同

`ucn_v6_memory_ranges_overlap()` 采用半开区间并检查地址加法溢出；无法证明不重叠时保守返回
overlap。零长度不占范围，非零长度要求非空指针。所有 16 个公开 `*_init_in_place` 在第一次
写 Storage 前分别检查 output pointer、Manifest、配置、Ops、Store、Provider、Policy 或父
Owner 引用是否与目标 Storage 重叠。

`tools/v6/check_v6_init_overlap_guards.py` 从独立固定清单检查每个公开入口的函数体，防止未来
新增或重构时漏掉 gate。功能回归还验证重叠 Runtime config 返回配置错误，完整 Storage 哨兵
和 output 保持不变。
