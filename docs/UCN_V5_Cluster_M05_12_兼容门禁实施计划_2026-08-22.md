# CLV2-05-12：Host 双格式兼容门禁实施计划

日期：2026-08-22
状态：IN PROGRESS / M05 AUDIT HOLD

## 1. 目标

在不接入任何生产 Cluster 状态机的前提下，冻结 Host 测试层的双格式接收边界：一段输入只能是精确 `32 B + format v3` 或精确 `40 B + format v4`；连续交替的两种格式不能污染下一次判定。

这不是生产 RX Owner，也不是混合版本成员准入、Head/Backup 资格、Authority、quorum 或实机互通验证。

## 2. 实现边界

新增独立 CTest target `ucn_cluster_wire_v4_host_dual_stack_tests`：

- 仅编译 `ucn_cluster_codec_v3.c`、`ucn_cluster_codec_v4.c` 和测试源；只链接 `ucn_core`。
- 该 target 局部定义 `UCN_CLUSTER_WIRE_V4_ENCODER_ENABLED=1`，只为制造受验证的 40 B v4 字节；它不改变 `ucn_cluster` archive 或默认生产配置。
- 默认 `ucn_tests` 中保留 `test_cluster_wire_v4_encoder_closed()`，验证正常编译的 encoder 返回 `UCN_ERR_CONFIG` 且不写 caller buffer。
- 不包含 private semantic header，不调用 `ucn_cluster_init/step/receive/send`，不触碰 `ucn_cluster_t`、runtime View/Stats 或 Adapter。

## 3. 兼容门禁

1. 用固定合法 v3 ADVERTISE 字节与 test-only encoder 生成的合法 v4 ADVERTISE 字节，按照 `v3 → v4 → v3 → v4` 次序调用 `ucn_cluster_wire_decode()`。
2. 每次均逐字段确认 format 与所属 raw/semantic body，证明 dispatcher 没有 sticky version state，也没有依赖上一帧。
3. `32/v4`、`40/v3`、v3/v4 版本改写、`31/39/41 B` 必须严格拒绝；失败时整个 dispatch output 保持哨兵字节不变。
4. 构建/源代码复扫必须确认 production `src/extended/ucn_cluster.c` 没有 v4 API，generic Adapter 没有 Cluster/v4 引用，公共 header 的 encoder 默认值仍为 `0`。
