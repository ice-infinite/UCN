## 验收门禁

每个可交付阶段都必须按以下顺序推进，任一项失败不得标记完成：

```text
实现 → 单元测试 → 模拟测试 → 记录结果 → 进入下一阶段
```

最终再执行完整集成测试。测试证明当前实现符合已定义的协议范围，不等同于真实无线、电磁兼容、密码实现或飞行安全认证。

## 本轮实现范围

本轮优先完成 `UCN-Core` 的可运行、可测试最小闭环：固定帧、统一 Link、Q0/Q1、固定路由缓存、受限 AODV-Lite、可选链路质量选路、邻居 Candidate/Admitted 生命周期、最小 HELLO 自动准入、虚拟多节点模拟和 Host 非中心化验证。

以下内容不在本轮伪造为“已完成”：真实 WiFi/BLE/CAN 驱动、实际无线性能、ROS2 Bridge、DroneCAN Gateway、生产级 AEAD/证书实现、OTA、Q2/Q3、业务分片、服务目录与小 MTU Carrier 分段。这些功能将保留明确接口或后续任务，不把未验证能力写成已支持。

## 完成定义

一个任务只有同时满足以下条件才能标记“完成”：

1. 源码和公共接口已写入工程。
2. 相关单元测试已通过。
3. 对应模拟场景已通过。
4. 修改和验证结果已追加到 [项目操作记录](01-项目操作记录.md)。
5. 没有把测试 Provider、虚拟 Link 或模拟性能表述成真实硬件验证。
