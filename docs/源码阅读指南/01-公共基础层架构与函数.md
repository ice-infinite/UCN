# 公共基础层架构与函数

本章解释 Nano、Lite、Full 都会编译的基础代码。三档差异主要发生在 Node 和 Routing；Frame、Adapter、Owner、Event Runtime、Stream/CAN Source 的基本合同相同。

## 1. 公共基础层架构

```text
产品驱动 / ISR
   │
   ├─ Packet型介质 ── submit_frame[_from_isr]() ─┐
   │                                              │
   └─ Stream/CAN ── Source Ring ── service() ─────┤
                                                  ↓
                                            Adapter RX Queue
                                                  ↓
                                            Protocol Owner
                                                  ↓
                                         ucn_node_receive()

业务发送：Node → Frame Encode → Link Ops → 产品驱动
周期维护：Event Runtime → Protocol Owner → Node step
```

这里有四个所有权边界：

1. 产品驱动拥有硬件、DMA 和 SDK 对象；
2. Source 拥有字节/物理帧 Ring，不在 ISR 中解析 UCN；
3. Adapter Queue 拥有完整 UCN Frame 的固定副本；
4. Protocol Owner 是唯一执行 Node、Service Bridge 和协议状态机的上下文。

## 2. Core 与 Endpoint 函数

源文件：`src/core/ucn_core.c`、`src/core/ucn_endpoint.c`。

| 函数 | 参数 | 谁调用 | 作用 |
| --- | --- | --- | --- |
| `ucn_version()` | 无 | 应用、诊断 | 返回库拥有的版本字符串 |
| `ucn_validate_config(config)` | `config`：只读基础配置 | `ucn_node_init()`、产品启动 | 校验 Network ID、Node ID、默认 Hop |
| `ucn_endpoint_is_static(endpoint)` | `endpoint`：业务 Endpoint | Node、Service Bridge、应用 | 判断能否注册静态 Endpoint handler |
| `ucn_message_type_is_control(message_type)` | `message_type`：Frame 类型 | Node TX/RX | 防止业务 API伪造控制帧 |

阅读重点：`ucn_validate_config()` 只校验基础域；容量、MTU、Security、Link Ops 等必须由各自入口继续检查，不能误以为一次配置校验已经覆盖所有运行条件。

## 3. Frame 函数族

源文件：`src/core/ucn_frame.c`。三个 Profile 使用同一个 W0～W3 Decoder。

### 3.1 Profile 与容量查询

| 函数 | 参数 | 返回/输出 | 典型调用位置 |
| --- | --- | --- | --- |
| `ucn_wire_profile_get_descriptor(profile)` | `profile`：W0～W3 | 只读 descriptor 或 `NULL` | 配置、Encode、Decode |
| `ucn_frame_header_size_for_profile(profile, flags)` | Wire 档、Frame flags | Header 字节数，非法为 0 | MTU 预检 |
| `ucn_frame_max_payload_for_profile(profile, flags)` | Wire 档、flags | 当前档最大 payload | Node send 参数检查 |
| `ucn_frame_max_payload(flags)` | flags | 默认 W3 最大 payload | 兼容查询 |
| `ucn_frame_encoded_size(frame)` | 内存 Frame | 精确 Wire 长度，非法为 0 | Encode 前容量检查 |

### 3.2 自动最小档与安全 AAD

| 函数 | 参数 | 作用 |
| --- | --- | --- |
| `ucn_frame_select_min_wire_profile(frame, maximum_profile, mtu, selected_profile)` | Frame、允许最高档、逻辑 MTU、输出档 | 从 W0 向上选择能够表达全部字段且装入 MTU 的最小档 |
| `ucn_frame_e2e_aad_size()` | 无 | 返回固定 E2E AAD 长度 |
| `ucn_frame_write_e2e_aad(frame, output, output_capacity, output_length)` | Frame、调用者 Buffer/容量、输出长度 | 生成安全 Provider 认证但不加密的规范字段 |

### 3.3 Wire 编解码

| 函数 | 参数 | 调用顺序和边界 |
| --- | --- | --- |
| `ucn_frame_encode(frame, output, output_capacity, output_length)` | 内存 Frame、输出 Buffer、容量、长度输出 | Node 已选档后调用；成功才允许交给 Link |
| `ucn_frame_peek_wire_profile(input, input_length, profile)` | 至少固定 Prefix | RX 最早调用，用于在完整 CRC 前拒绝超出本地接收上限的档次 |
| `ucn_frame_peek_encoded_size(input, available_length, encoded_length)` | 可能含载体 Padding 的 Buffer | CAN-FD 等先找真实 UCN 长度，不代表 CRC 已通过 |
| `ucn_frame_decode(input, input_length, frame)` | 精确 UCN Buffer、输出 Frame | 验证完整格式、长度和 CRC；失败不得交给 Node 控制面 |
| `ucn_crc16_ccitt(data, length, seed)` | 字节、长度、初值 | Frame CRC helper |

Frame 的人工审计顺序应固定为：Prefix → Profile → Flags → 可表达长度 → 精确长度 → 字段域 → CRC → 输出提交。任何提前写入输出、先减后校验或窄整数截断都应作为缺陷检查。

## 4. LC-1 Link Cost 函数

源文件：`src/core/ucn_link_cost.c`。

| 函数 | 参数 | 作用 |
| --- | --- | --- |
| `ucn_link_cost_ewma_update(previous, sample)` | 旧 EWMA、当前样本 | 按规范权重和整数取整更新平滑值 |
| `ucn_link_cost_resolve(input, result)` | 基础 Cost、状态、队列/失败/RTT/介质指标；输出结果 | 计算当前 Link Cost 和原因；不可用链路 fail-closed |
| `ucn_link_cost_is_sufficiently_better(active_cost, candidate_cost)` | 当前、候选 Cost | 执行固定滞回门槛，防止轻微变化频繁切路 |

这里要区分：LC-1 计算单条 Link 的代价；Route 总 Cost、Candidate 比较和 Policy 选择在 Node/Routing 层完成。

## 5. Adapter 函数族

源文件：`src/transport/ucn_adapter.c`。

### 5.1 地址与 Peer 绑定

| 函数 | 参数 | 作用 |
| --- | --- | --- |
| `ucn_adapter_address_is_valid(address)` | 类型化物理地址 | 校验长度和类型 |
| `ucn_adapter_address_equal(left, right)` | 两个地址 | 确定性比较 |
| `ucn_adapter_find_peer(bindings, binding_count, address)` | 固定绑定表、数量、地址 | 查找物理地址对应 Link |
| `ucn_adapter_bind_peer(bindings, binding_count, address, link)` | 固定表、地址、Link | 插入或更新绑定；表满返回 `NO_SPACE` |

### 5.2 固定 RX Queue

| 函数 | 参数 | 调用上下文 |
| --- | --- | --- |
| `ucn_adapter_rx_queue_init(queue, port_ops, port_context)` | Queue、临界区 Port、上下文 | 启动时 |
| `ucn_adapter_rx_enqueue(queue, ingress_link, data, length)` | 完整 Frame 副本 | 任务/驱动任务 |
| `ucn_adapter_rx_enqueue_from_isr(queue, ingress_link, data, length)` | 完整 Frame 副本 | ISR；必须有 ISR 专用临界区合同 |
| `ucn_adapter_rx_pump(queue, node, max_frames, pumped)` | Queue、Node、预算、输出数量 | 唯一 Owner；逐帧调用 `ucn_node_receive()` |
| `ucn_adapter_rx_get_stats(queue)` | Queue | 返回实时只读统计视图 |

### 5.3 HELLO Scheduler

| 函数 | 参数 | 作用 |
| --- | --- | --- |
| `ucn_adapter_hello_scheduler_init(scheduler, config, adapter_token, random_seed, now_ms)` | 调度器、周期/抖动配置、Adapter token、随机种子、当前时间 | 建立初始错峰计划 |
| `ucn_adapter_hello_scheduler_restart(scheduler, random_seed, now_ms)` | 新随机种子、当前时间 | 断开/恢复后重排 |
| `ucn_adapter_hello_scheduler_step(scheduler, now_ms, adapter_has_admitted_peer, hello_due)` | 当前时间、是否已有准入 Peer、输出是否到期 | 只给出“应发 HELLO”，不直接发送 |
| `ucn_adapter_hello_scheduler_get_stats(scheduler)` | 调度器 | 返回统计 |

## 6. Protocol Owner 函数族

源文件：`src/transport/ucn_protocol_owner.c`。

| 函数 | 参数 | 作用 |
| --- | --- | --- |
| `ucn_protocol_owner_init(owner, config)` | Owner、Node、RX Queue、Port、预算、可选 Bridge | 绑定唯一协议执行上下文 |
| `ucn_protocol_owner_rx_enqueue(owner, ingress_link, data, length)` | Owner、入口 Link、完整 Frame | 任务入口，只入队，不运行 Node |
| `ucn_protocol_owner_rx_enqueue_from_isr(owner, ingress_link, data, length)` | 同上 | ISR 入口，只入队 |
| `ucn_protocol_owner_step(owner, pumped, bridged)` | Owner、RX/Bridge 工作量输出 | 读一次时间，依次 Pump RX、Bridge、Node Step |
| `ucn_protocol_owner_get_stats(owner)` | Owner | 返回只读统计 |

Owner 的核心不变量是：同一个 Node 只能有一个执行 `receive/step/Service Bridge` 的上下文。多个 UART、CAN、USB、Wi-Fi Source 可以同时产生事件，但不能各自直接进入 Node 状态机。

## 7. Event Runtime 函数族

源文件：`src/transport/ucn_event_runtime.c`。

| 函数 | 主要参数 | 调用者/作用 |
| --- | --- | --- |
| `ucn_event_runtime_init(runtime, config)` | Runtime、Owner 配置、scheduler hooks、预算 | 启动时初始化固定 Source 表和 Owner |
| `ucn_event_runtime_bind_source(runtime, source_id, config)` | 固定 Source ID、`service()` 回调和上下文 | 启动时绑定一条 UART/CAN/USB/无线输入 |
| `ucn_event_runtime_signal_source(runtime, source_id, events)` | Source ID、RX/TX/状态事件位 | 任务上下文合并事件并通知 Owner |
| `ucn_event_runtime_signal_source_from_isr(...)` | 同上 | ISR 版本 |
| `ucn_event_runtime_signal_owner(runtime, events)` | Service/Timer/Application 等 Owner 事件 | 非物理 Source 工作通知 |
| `ucn_event_runtime_signal_owner_from_isr(...)` | 同上 | ISR 版本 |
| `ucn_event_runtime_submit_frame(runtime, ingress_link, data, length)` | 完整 Frame | Packet 型任务入口：入 Adapter Queue 并通知 Owner |
| `ucn_event_runtime_submit_frame_from_isr(...)` | 完整 Frame | Packet 型 ISR 入口 |
| `ucn_event_runtime_has_pending(runtime)` | Runtime | 判断能否跳过阻塞等待 |
| `ucn_event_runtime_run(runtime, fallback_scan, result)` | 是否保底扫描、运行结果 | Owner 中按轮次和每 Source 预算 Drain |
| `ucn_event_runtime_task_cycle(runtime, requested_wait_ms, result)` | 最大等待、运行结果 | RTOS 标准循环：有工作立即跑，无工作有界等待 |
| `ucn_event_runtime_get_stats(runtime)` | Runtime | Runtime 统计 |
| `ucn_event_runtime_get_owner_stats(runtime)` | Runtime | 内嵌 Owner 统计 |

## 8. Standard Adapter 配置函数

源文件：`src/transport/ucn_standard_adapter.c`。

| 函数 | 参数 | 作用 |
| --- | --- | --- |
| `ucn_standard_preset_resolve(preset, profile)` | 介质/速率 Preset、输出 Profile | 得到默认 MTU、基础 Cost、速率等初值 |
| `ucn_standard_link_config_resolve(config, resolved)` | 产品覆盖配置、输出解析值 | 合并 Preset 和显式覆盖并严格校验 |

它只解析配置，不创建 UART/CAN/Wi-Fi 驱动，也不读取实时硬件指标。

## 9. Stream Source 函数族

源文件：`src/adapters/stream/ucn_stream_source.c`。

| 函数 | 参数 | 作用 |
| --- | --- | --- |
| `ucn_stream_carrier_encode(frame, frame_length, wire_output, wire_capacity, wire_length)` | 完整 UCN Frame、输出 Carrier Buffer | COBS 编码并追加分隔符 |
| `ucn_stream_source_init(source, config)` | Source、Ring/Runtime/Ingress 解析配置 | 绑定固定 Byte Ring 和 Event Runtime |
| `ucn_stream_source_write(source, data, length)` | 收到的原始字节 | 任务上下文写 Ring、发事件 |
| `ucn_stream_source_write_from_isr(source, data, length)` | 原始字节 | ISR 写 Ring、发事件 |
| `ucn_stream_source_reset(source)` | Source | Owner 下清理解码/Ring 状态 |
| `ucn_stream_source_pending_bytes(source)` | Source | 观察待处理字节数 |
| `ucn_stream_source_free_bytes(source)` | Source | 观察可用 Ring 空间 |
| `ucn_stream_source_get_stats(source)` | Source | 返回统计 |

真正的 Source `service()` 通过私有函数注册给 Event Runtime：它从 Ring 找 `0x00` 分隔、COBS 解码、解析 ingress Link，再调用 `ucn_event_runtime_submit_frame()`。

## 10. CAN Source 函数族

源文件：`src/adapters/can/ucn_can_source.c`。

| 函数 | 参数 | 作用 |
| --- | --- | --- |
| `ucn_can_source_init(source, config)` | Source、模式、物理帧 Ring、重组槽、Runtime | 初始化 CAN-FD 或 Classic CAN Source |
| `ucn_can_source_write(source, frame)` | 归一化物理 CAN Frame | 任务上下文入 Ring |
| `ucn_can_source_write_from_isr(source, frame)` | 归一化物理 CAN Frame | ISR 入 Ring |
| `ucn_can_source_set_bus_state(source, state)` | ACTIVE/BUS_OFF/RECOVERING | 任务上下文更新状态并按合同清理 |
| `ucn_can_source_set_bus_state_from_isr(...)` | 同上 | ISR 版本 |
| `ucn_can_source_reset(source)` | Source | Owner 下复位 Ring/重组状态 |
| `ucn_can_source_get_health(source, health)` | Source、输出快照 | 返回总线、队列、重组健康度 |
| `ucn_can_source_get_stats(source)` | Source | 返回统计 |
| `ucn_can_fd_carrier_encode(frame, frame_length, output, output_length)` | UCN Frame、CAN-FD 输出 | 选择合法 DLC 并规范零 Padding |
| `ucn_can_classic_carrier_segment_count(frame_length)` | UCN 长度 | 返回 Classic CAN 段数 |
| `ucn_can_classic_carrier_encode_segment(frame, frame_length, transfer_id, segment_index, output, output_length)` | Frame、Carrier ID、段序号 | 生成 START/CONTINUE 物理段 |

## 11. Service ON 时的公共函数

Service 与 Nano/Lite/Full 正交。关闭 `UCN_FEATURE_SERVICE` 时，这两个源文件不会进入 `ucn_core`。

### Router

| 函数族 | 参数核心 | 作用 |
| --- | --- | --- |
| `ucn_service_router_init(router, config)` | Router、Binding/Inbox/Remote TX 固定存储 | 初始化任务通信路由器 |
| `ucn_service_set_ready(router, endpoint, ready)` | Endpoint、就绪状态 | 控制本地消费者准入 |
| `ucn_service_send_ex(..., acceptance)` / `ucn_service_send(...)` | 目标 Node、源 Service、Endpoint、QoS、payload | 本地直投或进入 Remote TX Queue |
| `ucn_service_deliver_remote(router, frame)` | 已由 Node 验证的远端 Frame | 投递本地 Binding/Inbox |
| `ucn_service_inbox_take(...)` | owner service、Endpoint、消息输出 | 消费本地 Inbox |
| `ucn_service_remote_tx_take(router, message)` | 消息输出 | Bridge 取待发送远端消息 |
| `ucn_service_get_stats(router)` | Router | 统计 |
| Command/Result helpers | guard/header、Buffer、时间/ID | 编解码命令守卫与结果匹配 |

### Protocol Bridge

| 函数族 | 参数核心 | 作用 |
| --- | --- | --- |
| `ucn_service_protocol_bridge_init(bridge, router, node)` | Bridge、Router、Node | 绑定远端业务边界 |
| `...set_validator()` | Endpoint、validator、context | 设置远端 Q0/业务校验 |
| `...install_endpoint_handlers()` | Bridge | 将 Node Endpoint 接收转给 Router |
| `...set_inbound_hooks()` | Hook 表 | 接收前后产品回调 |
| `...set_q0_backpressure_policy()` | 重试策略 | 配置关键消息背压 |
| `...set_outbound_observer()` / `...event_observer()` | observer、context | 观察远端发送和状态 |
| `...step()` / `...step_at()` | 预算；后者显式当前时间 | 从 Remote TX Queue 取消息并调用 Node enqueue/send |
| `...get_stats()` | Bridge | 统计 |
| Replay helpers | source Node、Session、Endpoint、Command ID | 防止命令跨 Session 重放 |
