# v6 核心阅读顺序

## 1. 从配置和身份开始

先读 `include/ucn/v6/ucn_v6_config.h` 和 `src/v6/config/ucn_v6_config.c`，理解 Profile、Feature、
Storage 和 Layout Hash。随后读 `ucn_v6_identity.h/.c`：Principal、Binding、Generation、lease
和 callback gate 是后续 Route/Security/Cluster 的共同安全域。

审计点：所有 serial 是否 no-wrap；高水位损坏是否 fail-closed；初始化是否先核对容量/对齐；
不同 TU 是否可能得到不同 Manifest。

## 2. 再读 Wire 和 Message

按 `ucn_v6_wire.h/.c` 的 semantic frame → size → encode → decode → canonical AAD 顺序。不要
从结构体布局猜 Wire。然后读 `ucn_v6_message.h/.c`，分清 Traffic、Delivery、Interaction、
Operation ID 和 Journal。

审计点：所有长度/Flag/保留位；失败输出不写回；AAD 是否覆盖语义；Journal 在执行与持久化
之间的掉电窗口；表满和 Tombstone 回收。

## 3. Owner 与 Security

`ucn_v6_owner` 说明事件单 Owner 模型。`ucn_v6_bootstrap` 和 `ucn_v6_security` 展开 Cookie、
JOIN transcript、Session、ACL、Replay 与 protect/open。沿 callback 调用检查 gate 是否在进入
Provider 前建立，PENDING 时是否冻结相关状态。

## 4. Capability、Route、QoS

Capability 的顺序是 authenticated record → peer/path cache → derived budget。Route 的顺序是
candidate begin → add path → probe → prepare activation → record send → commit ACK → select。
QoS 则从 metric ingest/score 到 enqueue/select/complete/completion retire。

审计点：Candidate 路径是否冻结；ACK 是否精确绑定；Session/Binding 失效是否跨模块清理；
Q1 多流是否轮转；Hop Budget 是否可能提权或侵占别类配额。

## 5. Transfer

先读 codec，再读 Owner。跟踪一个 TX slot 从 begin 到 fragment submit、SACK、retire；再跟踪
RX 从 fragment 到 completed/retire。最后看 Credit reserve/finish 与 session invalidation。

审计点：offset/length 算术、重复/重叠、位图宽度、窗口边界、Path rebind、迟到 ACK 和表满。

## 6. 可选模块和 Adapter

Realtime 与 Cluster 分别阅读，确认没有互相 include/link。最后读 Adapter、每种 Bearer、
FreeRTOS 和 ESP32-S3 参考层，把驱动 callback、Ring item、Owner notification 与 completion
串起来。

## 7. 最后读测试

对每个模块把 `tests/v6/test_v6_*.c` 与公共入口一一对应。优先找负向、边界、重入、掉电、
回绕、失败不写回和低容量 Profile，而不是只看 happy path。运行 `v6_source_boundary_gate`、
全部 CTest 和安装消费者，确认读到的确实是当前发布面。
