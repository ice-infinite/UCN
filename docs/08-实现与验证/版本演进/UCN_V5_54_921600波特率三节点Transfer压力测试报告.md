# UCN V5-54 921600 波特率三节点 Transfer 压力测试报告

## 结论

在 V5-53 相同的三节点两跳 UART 台架上，仅将节点间 UART 从 `115200` 提升至 `921600`，Link Cost 保持 34，九档继续各发送 8 KiB：

- T128～T8K 三轮共 `21/21` 个阶段全部完整交付，无无效/重复/CRC 错、Transfer 失败或 Fragment 重传。
- 七个可靠等级平均有效吞吐由 `2.825 KiB/s` 提升至 `10.296 KiB/s`，平均 `3.63×`；端到端耗时平均下降 `72.3%`。
- T8K 由 `3.110 KiB/s / 2572 ms` 提升至 `11.860 KiB/s / 676 ms`，提升 `3.81×`。
- 没有达到理论 8 倍，因为逐片 Stop-and-Wait、Owner 循环、中继处理和同时运行的 Heartbeat/Ping 仍占用固定时间。
- T32/T64 使用固定 12/11 ms 节拍且没有端到端 ACK，三轮完成率为 `98.57%/97.92%`；它们不能用于评价物理 UART 上限，也不能承诺持续流可靠交付。

## 实际边界

三轮 UART 的 COBS decode、length、overflow、no-space 和 partial 错误均为 0，表明当前短线接法在 921600 下没有观察到物理帧损坏。固定 RX Queue 仍有少量 Drop，主要影响无 ACK 的 T32/T64；可靠 Fragment 全部完成。

后台 Ping 第一轮为 `70/70`，第二轮 A/C 只有 `55/70`，第三轮恢复到约 `69～70/70`。所以大包可靠完成不代表并发背景业务完全不受影响，后续应优先做 Transfer 与 Q0/Q1 并发调度门禁。

压力镜像 RAM/Flash A/B/C=`63,756/602,631 B`、`48,756/596,127 B`、`55,796/598,431 B`；RAM 与 115200 相同。最小 Heap 保持约 294～304 KiB，无重启、Panic 或 Watchdog；最终 A→C 仍为 UART 两跳 Cost 68。

原始证据保存在外部 PlatformIO Bench：三轮 `v5_transfer_stress_921600_20260814_run*.log`、27 行 921600 汇总 CSV 和 115200/921600 对比 CSV。本结果只覆盖当前三板、短线、两跳 UART，不代表长线、不同 UART 硬件、CAN-FD、ESP-NOW-only、热插拔或生产 EMC。
