# 日志、统计与状态快照

> 文档级别：`GUIDE`
> 实现状态：`CURRENT（诊断方法）`
> 适用版本：UCN 5.0.0 / Core Wire v5
> 事实源：状态视图、统计 API、测试与现有实测记录
> 最近核对：`codex/v5-adaptive-wire@a093862`，2026-08-25
> 硬件状态：部分实测；未测项不得推断

建议日志包含时间、Node ID、Link、方向、错误码和 sequence，不输出密钥或完整敏感 payload。统计按模块读取：Source 字节/carrier、Adapter queue、Node RX/TX/duplicate、Route discovery、Transfer fragment、Service request、Cluster phase/persistence。

状态快照使用复制 API 获取一致的只读视图；满 buffer 要显示截断。统计计数采用饱和增长，不能依赖整数回绕判断健康。

## 日志分层

| 层 | 必备字段 | 典型事件 |
| --- | --- | --- |
| Driver/Source | time、instance、IRQ/DMA、bytes/frame、health | overflow、COBS错误、CAN bus-off |
| Adapter/Link | link ID、peer、MTU、up、queue | enqueue满、send down、metrics更新 |
| Core | local/source/destination、type、endpoint、session/sequence | decode、duplicate、TTL、forward |
| Route/Policy | destination、next hop、Cost、reason、path/flow | discover、RERR、candidate、switch |
| Service/Transfer | service/endpoint、command/transfer ID、stage | inbox满、ACK、retry、completion |
| Cluster | role、phase、Epoch、Config、Authority、Fence、operation | election、persist pending、recovery |

日志应记录“发生了什么”和“为什么拒绝”，不需要打印完整业务payload。对加密帧最多打印长度、hash截断或诊断ID；auth tag、key、nonce材料和明文不得进入普通串口日志。

## 事件格式建议

```text
123456 node=0x21 mod=route event=switch dst=0x88
old_link=1 old_cost=72 new_link=3 new_cost=48 reason=verified_20pct
```

固定key=value便于脚本统计；时间使用Owner单调时钟，并在文件头记录boot session、firmware hash和wall-clock映射（如果有）。多板日志后处理时先按各板启动事件/同步包校正时间，不能直接假设USB串口到达顺序等于网络顺序。

## 统计读取

统计值通常是自启动累计饱和计数。运维工具应保存上一次snapshot并计算差值，同时处理饱和值不再增长。不要通过把统计对象清零来“开始新一轮”，这可能破坏Owner数据；在外部工具分段即可。

### 关键关联

- Source `frames_submitted` 与 Adapter `dequeued` 不等：看queue积压；
- Node RX增加但Endpoint handler不增：看duplicate/security/route/endpoint拒绝；
- Transfer fragments sent高但ACK少：看Link/Route/远端RX slot；
- Service remote queued高但link accepted低：看Bridge/Node背压；
- Cluster role=HEAD但authority=false：看quorum/lease/fence/persistence。

## 快照一致性

在Owner上下文调用copy/get view，或让Owner把snapshot复制到诊断邮箱。输出结构应带：snapshot time、generation、returned count、total count/truncated。两步`count→allocate→copy`在动态网络中可能变化，小MCU更适合使用产品最大静态buffer并显示截断。

## 日志级别

- ERROR：安全/持久化/不变量/不可恢复Driver错误；
- WARN：容量满、超时、断链、降级、重试耗尽；
- INFO：启动配置、入离网、route/path/role变化；
- DEBUG/TRACE：逐帧/逐片，仅短时启用。

性能和实时测试应关闭TRACE并记录日志开关；同步串口printf可能成为最大的延迟来源。
