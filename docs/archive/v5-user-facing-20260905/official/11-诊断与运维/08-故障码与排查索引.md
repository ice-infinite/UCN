## 从症状反查

### 能发不能收

看对端Source bytes→Carrier errors→Adapter enqueue→Node decode/security→Endpoint handler。若Node RX不增，问题在物理/Source；RX增但handler无，问题在协议/授权/Endpoint。

### 两板能直连，多跳失败

看中继Neighbor两侧、Route next hop、TTL、MTU/Wire capability、forward security policy和中继TX queue。Path帧还要查每个relay的install entry。

### 偶发重启/USB反复枚举

先测试最小串口固件，检查供电、watchdog、stack overflow、引脚冲突和panic reset reason；不要直接把它归为UCN路由问题。恢复到已知固件能区分硬件/协议。

### 速度低

分层测raw Driver、Carrier、Core单帧、Transfer窗口、多跳和应用消费；关闭日志。报告payload goodput，不把baud/PHY rate当结果。

### Cluster不稳定

看Role变化时间线、Authority/Fence、Lease/quorum、Persistence和控制预算。单看各节点最终状态可能漏掉短暂双Authority。

## 运维原则

错误计数突然增加时保存snapshot、最近N条事件和固件hash；不要自动无限重试、自动降级安全或自动擦Flash。恢复动作必须与错误类别匹配。
