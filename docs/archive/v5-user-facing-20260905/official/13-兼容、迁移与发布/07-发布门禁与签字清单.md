## 签字角色

| 角色 | 负责签什么 |
| --- | --- |
| 协议/代码 | 合同、P0/P1、默认/实验边界 |
| 测试 | 矩阵、原始结果、回归区分度 |
| 平台/硬件 | Driver、资源、长稳、功耗、掉电 |
| 安全 | 算法/key/ACL/replay/update threat model |
| 文档/发布 | 版本、迁移、已知问题、artifact一致 |

同一人可以承担多个角色，但签字范围必须明确，不能用“团队已看过”替代。

## GO/NO-GO判定

### 自动NO-GO

- 未关闭P0/P1；
- 顶层`AUDIT HOLD`；
- default-OFF实验代码泄漏生产；
- Wire/Storage破坏但无迁移/回滚；
- required硬件/安全/掉电项未测；
- 测试基线与候选commit不一致；
- 文档将实验/Host结果描述为生产能力。

### 可接受已知问题

只有低严重度、已有明确规避、不会破坏安全/数据/兼容且产品负责人签字的P2/P3，才能随release保留，并写入支持矩阵/CHANGELOG。不能把延期P1改名为已知限制。
