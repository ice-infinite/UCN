## 成熟度说明

| 标记 | 含义 |
| --- | --- |
| Current | 默认源码路径存在，仍受本文限制 |
| Partial | 一部分实现/测试存在，完整集成或实机未完成 |
| Experimental | 独立target/Archive，默认关闭或签名可变 |
| Interface-only | 只有通用合同，产品Driver/Provider未包含 |
| Audit Hold | 禁止扩大到生产路径 |
| No-Go | 当前候选不能正式发布 |

## 平台支持口径

通用C99/Host构建是Current；裸机/FreeRTOS/Zephyr/NuttX/RT-Thread有独立Port壳层/指南，但具体板卡、SDK、Driver只有完成对应实测才能列“verified”。Linux可作为Host/网关，不是Core依赖。

## Bearer支持口径

- UART/RS-485/USB：Stream Source/COBS合同Current，部分ESP32-S3 UART实测；
- CAN/CAN-FD：Source/Carrier软件测试Current，具体控制器/实总线仍按报告；
- Wi-Fi/ESP-NOW：自定义packet Adapter合同，部分ESP-NOW实测；
- BLE/LoRa/Ethernet/802.15.4：preset/接口，厂商Driver与完整实测未内置。

## 已知高层限制

1. Cluster Wire v4生产RX/TX/FSM与Authority未放行；
2. 真实Flash双槽掉电/磨损未形成发布级证据；
3. 产品Security Provider/密钥生命周期未由库提供；
4. ESP-NOW四节点、多源并发、真实CAN/多RTOS和完整多Bearer长稳仍有未测；
5. Transfer跨簇大消息/Federation产品化未完成；
6. 万级是层次化可行性目标，不是已验证容量；
7. Host资源数字不能直接当MCU占用；
8. 5.0.0仍开发中，公共API/ABI可能继续破坏性优化。

## 如何引用支持

准确写法：“UCN提供Classic CAN Carrier软件实现和测试，目标CAN控制器实机需产品接入”；错误写法：“UCN已支持所有CAN板”。每个产品README只列实际安装和验证能力，未接的兼容代码不写成产品功能。

关闭限制需要：任务/修复、定向回归、全矩阵、目标硬件（若适用）、外审和本表同步。只完成代码不自动升级成熟度。
