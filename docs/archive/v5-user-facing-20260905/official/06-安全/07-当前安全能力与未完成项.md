# 当前安全能力与未完成项

> 文档级别：`NORMATIVE STATUS`
> 实现状态：`PARTIAL / RELEASE BLOCKED FOR PRODUCTION SECURITY CLAIMS`
> 最近核对：`a093862`，2026-08-25

## 已进入源码和软件测试

- Lite/Full Security Feature 与 Nano 裁剪；
- Node/Endpoint Policy；
- TX/RX authorize、Auto protection、seal/open Provider 调用；
- 16 B E2E Tag 和冻结 AAD；
- 透明密文中继和 Path ID 绑定；
- Source/Session 重复窗口；
- Sequence/Session 持久化和轮换接口；
- Security-required 初始化/发送失败关闭；
- Service Q0 Validator/Command Guard/Result 语义；
- 管理诊断 authorizer；
- Cluster Persistence/Authority 的软件安全门禁与不变量测试。

## 尚未由仓库通用实现闭环

- 真实设备身份和证书/信任根；
- 通用生产密钥存储、分发、吊销；
- 经外部审计的具体 AEAD Provider；
- 跨全部目标 MCU 的持久 Sequence/Session 掉电测试；
- Link 层逐跳认证标准实现；
- 真实无线攻击、故障注入、侧信道和物理调试口门禁；
- Cluster Wire v4 生产 RX/TX/FSM/Authority 的端到端安全接线；
- Federation 与跨簇 Transfer 的完整安全验收。

## 官方结论

UCN 当前具备**可集成生产安全实现的协议接口和大量失败关闭门禁**，但仓库本身不能被描述为“开箱即用的生产加密网络”。产品必须实现并验证 Provider、身份、密钥、持久化和业务安全。

## 默认构建不等于默认安全产品

Security Feature 编译进 Lite/Full，只表示 API/状态存在。产品必须配置 required gate、Provider、Policy 和 Endpoint ACL。若保持允许 Plain 的测试配置，不能在宣传中省略该事实。

Nano 裁掉 Security Feature 时，应在网络角色和 Endpoint 权限上限制其用途；不能让 Nano 因“能解码高档 Frame”自动获得敏感命令角色。

## 当前证据类型

仓库测试主要证明：字段/AAD、Policy 矩阵、Provider 调用失败、重放窗口、透明中继、required gate、Service Validator、管理 authorizer 和部分 Cluster Persistence/Fence 的软件合同。

它们不包含真实 secure element、Flash 磨损/撕裂、RF 攻击、侧信道、Key provisioning 和外部密码审计。因此证据报告必须使用“Host 软件/模拟”标签。

## 进入产品安全实现的下一步

1. 冻结产品威胁模型和必须保护 Endpoint；
2. 选择具体 AEAD/Key hierarchy/nonce；
3. 实现目标 MCU Provider 与持久存储；
4. 开启 required-by-default，关闭未授权 Plain/legacy；
5. 接入 Service/诊断/Path/Cluster authorizer；
6. 真实掉电、攻击和故障注入；
7. 独立代码/密码评审；
8. 形成可发布安全配置和运维流程。

## 保持阻断的条件

- 测试 Key/固定全网 Key；
- nonce/Sequence 可能掉电复用；
- Provider 失败会降级明文；
- 高风险 Q0 无 Validator/幂等；
- 远端诊断默认开放；
- Cluster v4 生产路径仍 AUDIT HOLD；
- 只跑 Host 测试而无目标 MCU/Flash；
- 无 Key 吊销/升级回滚/Debug 口策略。

任何一项存在，都不应使用“生产安全完成”的版本标签。
