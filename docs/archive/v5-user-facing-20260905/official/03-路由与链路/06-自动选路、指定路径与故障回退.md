# 自动选路、指定路径与故障回退

> 文档级别：`NORMATIVE`
> 实现状态：自动 Route 为 Lite/Full；四种 Policy 为 Full
> 最近核对：`a093862`，2026-08-25

## 四种模式

| 模式 | 行为 |
| --- | --- |
| `AUTO_BEST` | 使用当前满足约束的最佳 Route/Link |
| `PINNED_STRICT` | 只走指定主 Path；失效立即失败 |
| `PINNED_FAILOVER` | 主 Path→备 Path；两者硬失效后可按配置允许发现 |
| `AUTO_BALANCE` | Q1 在多条已验证 Path 间按 Flow/Cost 分担 |

Policy key 由 Destination、Endpoint 和 Traffic Class 组成。Traffic Class 可使用显式 wildcard，但 Destination 和 Endpoint 必须明确，避免一条规则误控制全节点全部业务。

## 指定路径

固定 Path 适用于：

- 关键控制要求走独立 CAN/UART；
- 主链路拥塞但业务想主动分流；
- 调试/测量固定拓扑；
- 某 Endpoint 有介质或安全约束。

`PINNED_STRICT` 不会因另一路“看起来更优”自动切走。`PINNED_FAILOVER` 只在硬失败使用备 Path。

## 自动最佳

Auto 先检查 Route/Path 约束，再以基础/动态 Cost、Hop、确定性 tie-break 选择。当前选择结果通常缓存使用，不每帧重新发 RREQ。

## 故障回退

硬失败包括 Link Down、Path Down、能力/MTU 不匹配和显式 revoke。软质量下降需要达到滞回/连续样本条件；不会在一次 RSSI 抖动后立刻换路。

正在 Driver 发送的物理帧不能被协议原子搬到另一条 Link；后续尚未提交帧按新状态处理。需要恢复完整消息时使用 Transfer/业务幂等。

## Policy 匹配和优先级

发送 Endpoint 消息时，Full Node 以 `(Destination, Endpoint, Traffic Class)` 查找最具体规则。Destination 与 Endpoint 必须是明确值，Traffic Class 才可按合同使用 wildcard。这样可以让同一目标节点的不同业务采用不同路径：

```text
Node C / Servo Command / Q0 -> PINNED_STRICT(CAN path)
Node C / IMU Stream    / Q1 -> AUTO_BALANCE(UART, Wi-Fi)
Node C / Diagnostics   / Q1 -> AUTO_BEST
```

没有匹配 Policy 时使用 Node 的默认 Route/约束。规则表固定，配置失败必须保留旧有效规则或原子拒绝，不能生成半个 Policy。

## 四种模式的实际发送流程

### AUTO_BEST

收集满足目标、Hop、MTU、Profile、capability 和安全约束的 Route/Candidate，计算本地有效 Cost，使用滞回和确定性 tie-break 选择。已有合法结果时直接发送，不先做全网发现。

### PINNED_STRICT

本地 handle 必须解析到已经验证的 Wire Path。主 Path 不可用时立即返回失败，不使用“差不多的 Route”。适合安全域、物理隔离控制链和可重复测试。

### PINNED_FAILOVER

先验证主 Path，硬失效才尝试已配置备 Path。只有 Policy 明确允许时，两者都失败后才可回到自动发现。软质量变差不会跳过主 Path 的固定意图。

### AUTO_BALANCE

仅对 Q1 Flow 建立固定容量 Binding；首次选择后在 Lease 内保持 Path 粘滞，持续拥塞或硬失效才重绑。它是按 Flow 分担，不是逐帧随机轮询。

## 手动固定路线不等于硬编码节点列表

业务配置引用本地 Path handle，Path Control 再把它绑定到当前 Wire Path ID 和逐跳表项。这样设备替换某一中继或重新安装 Path 时，产品可更新 handle 解析，而不需要重编所有调用业务。

真正“写死 A→B→C”的逻辑属于部署配置/管理面，不应散落在传感器任务源码里。

## 负载分担示例

节点 A 有 UART 和 Wi-Fi 到网关 G：

- 舵机 Q0 固定 UART，确保与大数据隔离；
- IMU1 Q1 Flow 绑定 Wi-Fi；
- IMU2 Q1 Flow 绑定 UART；
- Wi-Fi queue 持续过阈值时 IMU1 可重绑到 UART；
- UART 因舵机负载升高后，LC-1 也会反映 queue pressure；
- 所有合格路径都不足时 Q1 返回背压/不可达，不静默挤进禁止路径。

## 故障切换的精确边界

| 阶段 | 旧 Link 上的数据 | 新发送 |
| --- | --- | --- |
| 候选探测 | 继续使用当前活动路径 | 当前路径，探测仅控制流量 |
| 候选达到门限 | 已提交 Driver 的不迁移 | 更新后进入新 Link |
| 硬 Down | 结果可能失败 | 立即走备份/重新发现 |
| Transfer 未 ACK | 等待超时/ACK 后重试 | 可在新 Route 上发送后续重试片 |
| 业务命令超时 | 由 Command ID/Deadline 判定 | 不得盲目重复执行 |

“无缝”只能指在给定业务/Driver 下观测到的丢包、乱序和时延满足指标，不能理解为旧链路中的任意字节都原子搬到新链路。

## 配置错误与失败关闭

- handle 不存在或未验证：Pinned 拒绝；
- 主备 handle 相同或能力不匹配：配置拒绝；
- Q0 请求 AUTO_BALANCE：拒绝，不擅自改成 Q1；
- Flow 表满：返回容量错误；
- 路由发现被 Policy 禁止：明确不可达；
- 备 Path Down：不会把 `PINNED_FAILOVER` 解释为任意可用 Link。
