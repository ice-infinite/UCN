# 对象所有权、生命周期与静态存储

> 文档级别：`NORMATIVE`
> 实现状态：`CURRENT`
> 最近核对：`a093862`，2026-08-25

## 基本规则

UCN 不调用 `malloc/free`。对象、表、队列和缓冲由产品静态分配、栈分配或放入产品管理的固定内存区。

| 对象 | Owner | 外部借用内容 | 关键生命周期 |
| --- | --- | --- | --- |
| `ucn_node_t` | 唯一 Protocol Owner | 配置、Link ops、安全 ops、回调上下文 | init 后由同一 Owner step/receive |
| `ucn_link_t` | 产品/Adapter | Driver context、send/open/close | 注册期间地址和 ops 必须有效 |
| Adapter/Source | 产品协议层 | Ring/Frame storage、Driver 通知 | ISR push 与 Owner service 分离 |
| Service Router | 服务 Owner | immutable binding table | Binding table 全生命周期不变 |
| Transfer | Transfer Owner | Node、Endpoint handlers、调用者 TX data | TX 完成前输入数据必须有效；RX handle 要释放 |
| Cluster | Cluster Owner | Node、ID provider、Persistence provider | init/load/step 按持久化和 Authority 门禁 |

## Opaque 与 Storage

公开业务代码只需要 `ucn_node_t *`。静态分配 Node 的唯一 owner 翻译单元包含 `ucn_node_storage.h`；应用其他文件不依赖内部字段布局。

Cluster 采用相同思路：公共 API 与 storage 头分开，并通过 API 版本防止调用者把内部结构当 ABI。

## 借用与复制

- Node Send 会按队列契约复制当前帧 Payload；成功只表示本地队列接管。
- Service Router 将消息复制进固定 Inbox/Remote Queue，调用者可复用输入缓冲。
- Transfer 的大消息 TX Slot 持有调用者数据指针，直到 completion 前不得释放或修改。
- Binding/config 表若标注 borrowed immutable，必须保持地址和内容稳定。

## 初始化和失败

初始化失败时对象不得被当作可用。公共 API 对非法参数、未初始化状态、版本不符和容量不足返回明确错误。失败路径是否保证 output 不写回，由 API 合同和测试冻结；调用者不能假定部分输出有效。

## 多实例

一个 Node 可拥有多个 Link/Source；每条串口或 CAN 实例使用独立 Ring、Carrier、统计和 Driver context。不能让两个物理接口共享一份可变重组状态。

## 1. 生命周期阶段

UCN 对象通常经过以下阶段：

```text
未初始化存储
  -> 配置/依赖准备
  -> init（完整校验）
  -> register/bind
  -> Owner运行
  -> 停止新输入
  -> 排空/取消在途事务
  -> deinit或重新初始化
```

不能在对象仍有 Transfer handle、Service binding 或异步 Persistence pending 时直接覆盖存储。

## 2. 静态分配不等于全放全局变量

“无 malloc”表示容量和生命周期由产品决定。对象可以是：

- 静态全局区；
- RTOS task context 中的长期固定区；
- 产品内存池中的固定 slot；
- 生命周期足够长的上层对象成员。

不能把 Node、Link ops 或 borrowed binding 配置在初始化函数的临时栈上然后返回。

## 3. 借用、复制与接管

| API 行为 | 返回后调用者能否改原数据 | 示例 |
| --- | --- | --- |
| 立即复制 | 可以 | 小 Frame Payload 入 Node 队列、Service Inbox |
| 借用只读 | 不可以，直到对象销毁/解绑 | Link ops/config、Binding table |
| 借用到完成 | 完成前不可以 | Transfer TX 大消息 buffer |
| 组件接管 slot | 只能通过 release 归还 | Transfer RX handle |
| Provider 必须复制 | submit 返回 PENDING 后调用栈会消失 | Cluster Persistence request |

API 文档若未明确，应通过公共头注释和测试确认，不能凭经验假设。

## 4. 初始化失败的原子性

初始化先验证 magic/version、结构大小、必需 callback、容量和配置关系。失败后对象保持不可用或被清零到明确状态，调用者不能继续调用 step。典型错误包括：

- Port API version 不匹配；
- Cluster REQUIRED 模式没有 Provider；
- Link MTU 为无效值；
- Profile/Feature 组合冲突；
- Storage layout 与头文件不一致。

## 5. 注销和重配置

移除 Link 前先标记 Down，使 Route/Path/Transfer 得到故障事件，再停止 Driver 回调。直接释放 Link context 会让队列中的发送项引用无效地址。

Service Binding 若需要更新，应先阻止新请求、排空 Inbox/Remote queue，并确保没有任务仍持有旧 binding 指针。当前静态设计不承诺任意时刻热替换所有表。

## 6. Node ID 的生命周期

Node ID 在 `ucn_node_init()` 前由产品确定。默认可从芯片唯一标识派生，但为了管理方便，产品可以从 Flash/NVS 读取手工分配 ID。修改 Node ID 相当于更换网络身份，必须同步处理 Route、Security Session、Cluster/Persistence 和远端缓存，不能只在运行中改一个字段。

## 7. 资源估算

对象总 RAM 不只包含 `sizeof(ucn_node_t)`：还应加 Driver DMA buffer、Source Ring、Adapter Queue、应用 Inbox、Transfer payload storage、RTOS task stack 和 SDK heap。配置文档中的 Host `sizeof` 只用于协议对象回归。
