## 命名规则

- 公共 C 符号统一以 `ucn_` 开头，宏以 `UCN_` 开头。
- 文档中的“v5”若未限定，指 Core Wire v5；Cluster Wire 必须显式写 v3 或 v4。
- “Full/Lite/Nano”只指 Build Profile；“W0/W1/W2/W3”只指 Wire Profile。
- “支持”必须附带层级：Codec 支持、Core 支持、产品 Driver 支持或实机验证支持。

## 1. 最容易混淆的四组概念

### 1.1 Node、MCU 与任务

Node 是协议寻址实体，通常一个 MCU 运行一个 Node，但这不是语法上的强制关系。一个高资源 MCU 可以托管多个隔离 Node 实例；一个 MCU 内的多个任务通常不应伪装成多个 Node，而应通过 Endpoint/Service 区分。

```text
MCU A
└─ UCN Node 0x1001
   ├─ Endpoint IMU
   ├─ Endpoint Barometer
   ├─ Service ServoControl
   └─ Service Health
```

因此“给 IMU 发消息”和“给节点 A 发消息”不是同一层概念：先用 Node ID 找到 MCU A，再用 Endpoint/Service 找到 IMU 业务。

### 1.2 Link、Bearer、Adapter 与 Source

- Link 是 Core 可选择的一条逻辑出口，包含发送 ops、MTU、状态和 Cost；
- Bearer 是某个 Neighbor 上的具体承载实例，例如“UART1 到节点 B”或“ESP-NOW 到节点 B”；
- Adapter 连接逻辑 Link 和产品物理地址/驱动；
- Source 负责把 ISR/DMA 收到的字节或 CAN 帧整理为完整 UCN Frame。

一个 UART 控制器通常对应一个 Stream Source 和一个 Link；同一无线控制器也可能面向多个 peer 形成多个邻居 Bearer。具体映射由 Adapter 决定。

### 1.3 Route、Candidate 与 Path

Route 是“到目标的当前下一跳缓存”，节点只需知道下一站，不必保存完整端到端路线。Candidate 是同一目标的备选下一跳。Path 是显式安装、带 Path ID 的逐跳转发表，适合固定路线或策略路由。

普通自动路由：

```text
A 的 Route[C] = next B
B 的 Route[C] = next C
```

A 不必知道完整路径是 A→B→C。只有 Path Trace 诊断才按需收集完整经过节点。

### 1.4 Wire Profile 与 Build Profile

Wire Profile W0～W3 决定单帧地址、Cost 等字段宽度和头长度；Build Profile Nano/Lite/Full 决定编译哪些状态机和表。

低 Build Profile 节点可以解码较高 Wire Profile 的普通 Endpoint Frame，只要接收上限允许；但它不会因此获得 Path、Policy 或 Diagnostics 代码。

## 2. 消息语义相关术语

### Q0～Q3

Q0 表示关键消息：使用 FIFO，强调不能被新消息覆盖，并可进行有界本地背压重试。Q1 表示实时状态：可以使用 Latest 语义和流亲和负载均衡，允许新值替代尚未发送的旧值。Q2 是普通 FIFO，Q3 是批量 FIFO。四级按 `6:3:2:1` 有界调度；任何一级都不自动等于完整业务可靠性协议。

### Frame、Message 与 Transfer

- Frame 是一次 Core Wire 编码单元；
- Message 是业务希望交付的逻辑内容；
- 小 Message 可以放在一个 Frame 中；
- 大 Message 由 Transfer 拆成多个 Fragment Frame，目标重组后才交付。

“一帧”不是“一次请求和应答”。应答是另一帧或另一个 Transfer/Service Result。

### Acceptance、Delivery 与 Execution

- Acceptance：本地 API 接受请求；
- Link delivery：某一跳发送完成；
- Transfer completion：目标完整重组并 ACK；
- Service execution：目标任务真正执行并返回结果。

文档和日志必须明确使用哪一级，不能只写“发送成功”。

## 3. Cluster 术语关系

Role 是人类可读身份，Phase 是更精确的状态机位置。Epoch 定义权威身份域；Config 冻结 voter 集合；Quorum 说明多数派是否成立；Lease 说明票是否仍新鲜；Authority 是以上条件共同允许的外部副作用资格；Fence 在条件失效后阻止旧权威继续工作。

```text
Role=HEAD
并不自动推出 Authority=true

Authority=true 还要求：
Phase允许 + Epoch一致 + Config一致 + Quorum成立 + Lease有效 + 无Fence
```

## 4. 版本术语

“UCN v5”默认只指项目/Core Wire 主版本。下列表述必须写完整：

- Core Wire v5；
- Port API v2；
- Cluster Current Wire v3；
- Cluster Target Wire v4；
- Cluster Persistence Record v4；
- Transfer format v1。

这些版本可以同时存在，数值不同不代表矛盾，因为它们管理不同兼容域。

## 5. 文档状态词

| 状态词 | 含义 |
| --- | --- |
| Current | 与当前源码一致，不等于生产就绪 |
| Partial | 只有部分路径、平台或证据完成 |
| Default-off | 有代码，但默认构建不包含或不启用 |
| Audit Hold | 暂停扩大集成，等待审计问题关闭 |
| Release NO-GO | 不满足正式发布门禁 |
| Software verified | 软件测试范围通过，未替代硬件验收 |
| Hardware verified | 只对报告中的板卡、固件和场景成立 |

这些词用于阻止“源码里有一个文件”被误读为“产品已经具备完整能力”。
