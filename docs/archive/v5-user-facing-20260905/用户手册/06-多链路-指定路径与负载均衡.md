# 多链路、指定路径与负载均衡

本篇只适用于 Full。Lite能维护一个Neighbor的多Bearer并选择当前Route，但显式Path、Policy和Q1 Auto Balance属于Full能力。

## 1. 五种常见选择

| 需求 | 模式 |
| --- | --- |
| 完全自动选择当前最佳路 | `AUTO_BEST` |
| 必须走指定通道，断了就失败 | `PINNED_STRICT` |
| 优先指定通道，断了走备用/自动 | `PINNED_FAILOVER` |
| 多条已验证路径分摊不同Q1 Flow | `AUTO_BALANCE` |
| 仅固定下一跳、拓扑静态 | 静态Route，不一定需要Path |

Q0关键命令不参与自动负载均衡，避免跨路径乱序和不可预测迁移。

## 2. 多Link配置

例如Node A到B有CAN和Wi-Fi：

```text
CAN Link: 低延迟、低带宽、base cost较低
Wi-Fi Link: 高带宽、质量波动、queue pressure变化大
```

两条Link都注册到同一个Node，分别提供status/metrics。不要创建两个Node来代表同一个MCU的两个接口。

## 3. 建立显式 Path

Path是端到端身份，但每个节点只安装自己的下一跳：

```text
A → B → C

A保存：destination=C, next_hop=B, remaining=2
B保存：destination=C, next_hop=C, remaining=1
C保存：destination=C, terminal, remaining=0
```

本地安装示例：

```c
check(ucn_node_install_local_path(
    node,
    path_id,
    destination,
    next_hop,
    remaining_hops,
    lease_ms));
```

远端安装通过授权控制帧：

```c
check(ucn_node_send_path_install(
    controller_node,
    control_target,
    path_id,
    destination,
    next_hop,
    remaining_hops,
    lease_ms));
```

接收端必须安装Path Control Authorizer。未授权来源不能改写转发表。Capability-aware版本还可绑定整条路径的最大Wire和最小MTU瓶颈。

## 4. 将 Wire Path 映射为本地 Policy Path

```c
ucn_policy_path_config_t path = {
    .local_path_id = 1U,
    .wire_path_id = path_id,
    .destination = destination,
    .egress_link = can_link,
    .verified = true,
    .route_cost_valid = true,
    .route_cost = 50U,
    .verified_rtt_valid = true,
    .verified_rtt_ms = 3U
};

check(ucn_node_set_policy_path(node, &path));
```

`local_path_id`是本节点策略表句柄，`wire_path_id`是线上Path身份。Pinned发送要求可用、已验证且绑定非零Wire Path。

## 5. Pinned Strict

```c
ucn_route_policy_config_t policy = {
    .key = {
        .destination = destination,
        .endpoint = PRODUCT_EP_SERVO_COMMAND,
        .traffic_class = UCN_TRAFFIC_Q0_CRITICAL
    },
    .mode = UCN_ROUTE_POLICY_PINNED_STRICT,
    .primary_local_path_id = 1U
};

check(ucn_node_set_route_policy(node, &policy));
```

适合“舵机命令只能走独立CAN”。指定Path不可用时直接失败，不会偷偷使用Wi-Fi。

## 6. Pinned Failover

```c
policy.mode = UCN_ROUTE_POLICY_PINNED_FAILOVER;
policy.primary_local_path_id = 1U;
policy.backup_local_path_id = 2U;
policy.allow_discovery_on_hard_failure = false;
check(ucn_node_set_route_policy(node, &policy));
```

顺序是主Path→备用Path。只有明确开启 `allow_discovery_on_hard_failure` 时，两个Path硬失败后才允许走自动发现；Q0不会因为这个选项自动启动Discovery。

## 7. Auto Best

```c
policy.mode = UCN_ROUTE_POLICY_AUTO_BEST;
policy.primary_local_path_id = 0U;
policy.backup_local_path_id = 0U;
check(ucn_node_set_route_policy(node, &policy));
```

选择只在当前满足安全、MTU、约束和状态的候选中进行。Cost降低不等于立即切换；连续样本、改善阈值、probe和hold共同抑制抖动。

## 8. Q1 Auto Balance

```c
policy.key.traffic_class = UCN_TRAFFIC_Q1_REALTIME;
policy.mode = UCN_ROUTE_POLICY_AUTO_BALANCE;
policy.balance_flow_lease_ms = 2000U;
check(ucn_node_set_route_policy(node, &policy));
```

负载均衡按Flow绑定，不是每包轮询：

```text
(destination, endpoint, Q1)
  → selected local path
  → lease期间保持
```

不同Endpoint或不同目标可分到不同Path，同一个IMU流保持顺序。Path硬Down或持续拥塞达到样本门槛时才重新绑定。

也可以显式绑定：

```c
check(ucn_node_bind_q1_flow(
    node, destination, PRODUCT_EP_IMU_SAMPLE,
    local_path_id, lease_ms));
```

## 9. 查看质量和统计

```c
const ucn_policy_link_quality_snapshot_t *quality =
    ucn_node_get_link_quality(node, link);

const ucn_policy_stats_t *stats =
    ucn_node_get_policy_stats(node);
```

重点观察：

- 当前effective cost及分项；
- metrics是否过期或非法；
- Policy match hits；
- pinned失败和failover次数；
- balance绑定、拥塞迁移和down迁移；
- Path state是否Verified/Suspect/Down。

## 10. 推荐业务策略

| 业务 | 推荐 |
| --- | --- |
| 急停/舵机Q0 | CAN Pinned Strict |
| IMU Q1 | UART主Path + CAN Failover，或Auto Best |
| 多路传感器Q1 | Auto Balance按Endpoint/Flow分摊 |
| 参数/日志Transfer | Wi-Fi/USB固定或Failover，不占控制CAN |
| 诊断 | 低频、显式授权，不参与高优先级流量 |

## 11. 分阶段验收

1. 每条Link单独收发；
2. 两条Link同时在线但不启Policy；
3. 每条Path逐跳安装、查询和撤销；
4. Pinned Strict断链必须失败；
5. Pinned Failover按顺序切换；
6. Auto Best面对抖动不频繁切换；
7. Auto Balance多个Flow分布且单Flow有序；
8. Q0+Q1+Transfer并发时Q0尾延迟达标；
9. 恢复链路不会未经验证立即抢占主路。
