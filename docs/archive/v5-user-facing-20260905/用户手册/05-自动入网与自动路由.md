# 自动入网与自动路由

本功能只在 Lite/Full 原生可用。Nano 使用预配置 Link/Route，不执行动态 Neighbor 和 AODV-Lite。

## 1. 使用前提

- 每个物理输入已注册为Link；
- Link status和MTU可靠；
- 动态介质能够发送/接收一跳发现Frame；
- 所有节点Network ID一致；
- Node ID唯一；
- 产品已选择Join Policy；
- Owner持续推进，维护间隔满足配置。

## 2. 选择 Join Policy

```c
ucn_result_t result = ucn_node_set_join_policy(
    node,
    UCN_JOIN_PROVIDER,
    authorize_neighbor,
    &product_acl);
```

| Policy | 行为 | 适用 |
| --- | --- | --- |
| `MANUAL` | Candidate必须由产品显式admit | 固定白名单、调试网络 |
| `OPEN` | 合法发现可自动准入 | 可信封闭台架，不建议外部无线默认使用 |
| `PROVIDER` | 回调决定是否准入 | 正式产品、按身份/接口/配置授权 |

Provider 示例：

```c
static ucn_result_t authorize_neighbor(
    void *context,
    ucn_node_id_t local_node_id,
    ucn_node_id_t peer_node_id,
    const ucn_link_t *link)
{
    const product_acl_t *acl = context;
    (void)local_node_id;

    return product_acl_allows(acl, peer_node_id, link->link_id)
        ? UCN_OK : UCN_ERR_ACCESS;
}
```

## 3. 启动发现

固定点对点Link可以直接probe/broadcast：

```c
check(ucn_node_observe_neighbor(node, link, now_ms));
check(ucn_node_probe_neighbor(node, link, now_ms));
```

或按Adapter Hello Scheduler决定什么时候发送：

```c
bool hello_due = false;
check(ucn_adapter_hello_scheduler_step(
    &hello_scheduler,
    now_ms,
    adapter_has_admitted_peer,
    &hello_due));
if (hello_due) {
    check_or_count(ucn_node_broadcast_hello(node, link, now_ms));
}
```

动态无线不要在所有节点同一时刻固定周期广播。初始jitter、快速重试和退避可降低启动风暴。

## 4. Neighbor 状态

```text
EMPTY
 → CANDIDATE
 → ADMITTED
 → SUSPECT
 → REMOVED/EXPIRED
```

同一个Neighbor可以通过多个Bearer被看到。Neighbor身份只有一份，各Link freshness和quality独立维护。

手动模式：

```c
check(ucn_node_admit_neighbor(node, peer_node_id));
/* 或 */
check(ucn_node_reject_neighbor(node, peer_node_id));
```

查询：

```c
size_t admitted = ucn_node_neighbor_count(
    node, UCN_NEIGHBOR_ADMITTED);

ucn_neighbor_summary_t summaries[8];
size_t copied = ucn_node_copy_neighbor_summaries(
    node, summaries, 8U);
```

这些查询只在Owner上下文使用。

## 5. 发起 Route Discovery

```c
ucn_result_t result = ucn_node_discover_route(
    node, destination, now_ms);
```

Node通过有界Expanding Ring发送RREQ，收到RREP后安装Route。调用者可查询：

```c
if (ucn_node_route_pending(node, destination)) {
    /* 仍在发现，不重复启动相同请求 */
}
```

获得Route后普通业务仍使用：

```c
ucn_node_send_endpoint(
    node, destination, endpoint,
    UCN_TRAFFIC_Q1_REALTIME, payload, length);
```

应用不需要在每次发送前重走寻路。Route Cache命中时直接使用；接近过期时由维护逻辑刷新。

## 6. Route Constraints

对Q0等关键业务可设默认门槛：

```c
ucn_route_constraints_t constraints = {
    .max_hops = 4U,
    .max_route_cost = 500U,
    .max_verified_rtt_ms = 30U,
    .require_verified_rtt = true
};

check(ucn_node_set_default_route_constraints(node, &constraints));
```

未知Cost或未验证RTT在要求开启时会失败关闭，不会猜测为合格。

查看当前质量：

```c
ucn_route_quality_t quality;
ucn_result_t result = ucn_node_get_route_quality(
    node, destination, &quality);
```

## 7. 链路断开后发生什么

```text
Driver报告Link Down
 → Neighbor Bearer Down/Suspect
 → 依赖Route失效
 → 必要时发送RERR
 → 新业务无有效Route
 → 重新发现或使用备用策略
```

硬断链不应等待Route缓存自然过期。产品Driver必须及时更新status；否则Core无法知道物理链路已经消失。

## 8. 常见失败

| 现象 | 检查 |
| --- | --- |
| 节点看得见但不能通信 | 是否admitted、Network ID、Endpoint、Security |
| 一直`NOT_FOUND` | RREQ是否发出、控制帧MTU、Hop上限、Link status |
| 只能一跳不能多跳 | 中继是否Owner持续step、TTL、RREQ/RREP过滤 |
| 节点频繁离网 | Owner延迟、Heartbeat、Driver队列、误码、时间基准 |
| 启动瞬间网络抖动 | Hello是否jitter/backoff、控制预算是否触发 |
| 路由存在但Q0拒绝 | Route Constraints、未知Cost、RTT未验证 |

## 9. 分阶段测试

1. 两节点一跳发现和准入；
2. A-B-C三节点自动寻路；
3. 无路由时发现，第二次发送直接命中缓存；
4. 中间Link断开，RERR和重寻路；
5. 新节点批量加入的jitter/控制开销；
6. 多Bearer同一Neighbor；
7. Q0 Constraints通过和失败；
8. 长时间无业务后Route刷新。
