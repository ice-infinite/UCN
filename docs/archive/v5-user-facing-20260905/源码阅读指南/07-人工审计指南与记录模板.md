# 人工审计指南与记录模板

## 1. 审计目标

人工审计不是重新描述代码，而是验证：

```text
公共合同
  == 实际实现
  == 调用顺序
  == 失败语义
  == 测试所证明的范围
```

只看到“现有测试全绿”不能结束审计。必须主动寻找未被测试覆盖的相邻状态、回绕、满载、重入和失败分支。

## 2. 审计一个公共函数的固定流程

### A. 定位合同

记录：

- 公共声明；
- 参数注释；
- Profile 条件；
- 调用上下文；
- 返回值和失败写回承诺。

### B. 找所有实现

同一符号可能有：

- Nano 原生实现；
- Lite/Full 条件编译实现；
- `ucn_profile_stubs.c`；
- 测试专用 target 实现或宏分支。

不能只看搜索结果中的第一个定义。

### C. 找所有调用者

把调用者分成：

- 应用公共调用；
- Protocol Owner；
- Node 内部；
- ISR/Source；
- 测试专用桥；
- 可选 Archive/实验组件。

### D. 标出状态提交点

在源码中明确标记：

```text
最后一个结构/权限校验
  ↓
第一个状态写入
  ↓
外部回调/Provider/Link发送
  ↓
成功后的最终提交
```

如果状态在验证前写入，或外部回调位于半提交窗口，就要构造对抗用例。

### E. 检查测试能否区分旧错误实现

一个好的回归测试必须在“修复前失败、修复后通过”。如果换回旧错误实现仍然全绿，这个测试没有钉住问题。

## 3. 参数审计清单

| 类别 | 必查值 |
| --- | --- |
| 指针 | NULL、别名、输入输出指向同一对象 |
| 长度 | 0、1、最小合法、最大合法、最大+1 |
| ID | 0、本机、广播、最大值、跨 Profile 不可表达值 |
| 枚举 | 每个合法值、未定义值、保留值 |
| Flags | 每一位、冲突组合、保留位、全 0/全 1 |
| 容量 | 空表、最后一个槽、满表、删除后复用 |
| 时间 | 0、deadline-1、deadline、deadline+1、`UINT32_MAX` 回绕 |
| Cost | Unknown、0、最大、饱和相加、同分、滞回边界 |
| Hop | 0、1、默认上限、编译上限、超过上限 |
| Profile/MTU | 正好装下、差1字节、Peer ceiling、本地 ceiling |

## 4. 输出不写回审计

错误返回时，不能只检查输出首尾字段。标准做法：

```c
Output before;
Output output;

fill_with_distinct_sentinel(&output);
before = output;

result = api(invalid_input, &output);

TEST_ASSERT(result != UCN_OK);
TEST_ASSERT(memcmp(&output, &before, sizeof(output)) == 0);
```

Buffer 同样应比较全部字节。Parser/Builder 还要使用彼此可区分的字段值，防止两个字段同时交换后 round-trip 仍通过。

## 5. 状态机审计

对每个状态机建立二维表：

| 当前状态 | 输入/事件 | 期望状态 | 输出动作 | 持久化/发送前置条件 |
| --- | --- | --- | --- | --- |

然后检查：

- 每条合法边；
- 每条非法边；
- 终态能否被 Reset/Begin 绕过；
- 重复相同消息是否幂等；
- 相同 txid 不同内容是否拒绝；
- 旧 Epoch/Session/route_epoch 是否回放；
- 超时与完成同时发生时谁优先；
- 异步完成后同一 Step 是否继续运行旧状态。

## 6. 时间和回绕

UCN 使用 32 位毫秒时间。正确实现应复用 `ucn_deadline_*`，Duration 必须在安全半域内。

重点反例：

```text
now = UINT32_MAX - 10
deadline = now + 20  （发生回绕）

检查：
  回绕前未到期
  回绕后正确到期
  now == deadline 的规范一致
```

还要检查“初始化后先 send、第一次 step 时系统 uptime 已很大”和“长时间空闲后再次发送”，防止使用陈旧 `now_ms` 建绝对 deadline。

## 7. 固定容量和内存

UCN 以固定表和固定 Queue 为主。每个表至少审计：

- count 是否始终不超过 capacity；
- slot 索引是否在读取前验证；
- 满表是拒绝、替换还是淘汰；
- 安全状态是否允许被普通新请求淘汰；
- 删除后相关引用是否同步清理；
- 遍历时删除是否跳过后一项；
- `memcpy` 长度是否来自已验证值；
- 栈上 Frame/Carrier/Transfer 临时数组是否适合目标 MCU。

## 8. 并发、ISR 和重入

### ISR

ISR 只允许：

```text
复制到固定Ring/Queue
设置事件位
通知Owner
```

ISR 不应执行 Frame Decode、Route、Security、Endpoint handler 或 Link 发送状态机。

### Provider/回调重入

外部回调前检查：

- `io_active`/Owner 门是否已经建立；
- 回调内递归调用同一 API 是否返回 `UCN_ERR_STATE`；
- 回调内递归 `step()` 是否可能推进半完成事务；
- 回调返回 PENDING 前是否已经冻结收发；
- 回调失败是否与后续网络发送失败分开统计。

## 9. Wire 和 Carrier

### Frame

- Prefix 长度不足；
- Profile 与长度错配；
- Flags 冲突；
- 地址/Cost/Path 超出当前档；
- CRC 只覆盖部分字段；
- Decode 失败输出污染。

### Stream

- 空 Carrier；
- 超长无分隔符；
- COBS 断帧；
- Ring 满后恢复；
- 多帧连续输入。

### CAN-FD

- DLC 扩展 Padding 必须全零；
- 真实 UCN 长度与物理长度区分；
- 非零 Padding 拒绝。

### Classic CAN

- START 覆盖未完成槽的合同；
- 完成槽不能被下一 START 静默覆盖；
- transfer ID、segment index、CAN ID 绑定；
- timeout 后槽可复用。

## 10. 路由和 Policy

### Route

- RREQ New/Better/Replay 分类后才提交缓存；
- Cost 饱和，不允许溢出变小；
- RREP 只更新匹配发现/有效 Epoch；
- RERR 只删除真正依赖它的方向；
- Link Down 不删除无关静态 Route；
- Candidate 未验证不能取代 Active。

### Path

- Identity 必须完整绑定 owner/session/path/destination；
- remaining hops 每跳递减；
- 能力和 MTU 每跳验证；
- revoke 不能只凭短 Path ID；
- 过期 Path 不可发送/转发。

### Policy

- `PINNED_STRICT` 不得自动回退；
- `PINNED_FAILOVER` 只在规定硬失效时回退；
- Balance 只对允许的 QoS/Path 集合；
- Flow 在 lease 内稳定；
- 动态质量变化要经过 EWMA、连续样本和滞回。

## 11. Security

检查顺序：

```text
Security Required Ready总门
  → 入站结构/Network/Hop
  → Provider授权/解密
  → Replay
  → Route/控制/业务状态写入
```

还要检查：

- E2E AAD 是否与 Encode 字段完全一致；
- 中继是否能透明转发密文且不需要解密业务内容；
- Endpoint override 是否可能放宽 Node Required Policy；
- Session 轮换是否清理旧 Replay/授权域；
- 管理诊断是否有独立 ACL 和 Token；
- 产品没有安装密钥时文档是否仍误称“已安全”。

## 12. Profile 审计

每个公共 API 变化后至少检查：

```text
Nano + Service ON/OFF
Lite + Service ON/OFF
Full + Service ON/OFF
一个低容量产品配置
```

被裁剪函数不仅要能链接，还要有严格返回值和无写回测试。默认关闭 Archive 需要同时验证 ON 时功能和 OFF 时 archive 不含 object/symbol。

## 13. 问题记录模板

```markdown
### UCN-AUDIT-XXX｜标题

- 等级：P0/P1/P2/P3
- 合同来源：头文件/规范/任务 ID
- 源码位置：绝对或仓库相对路径 + 行号
- 触发前置状态：
- 最小输入序列：
- 实际结果：
- 期望结果：
- 影响范围：Nano/Lite/Full、默认产品/实验组件
- 可复现探针：
- 修复方向：
- 必须增加的正向/负向测试：
- 当前门禁：AUDIT HOLD / GO（受限范围）
```

## 14. 审计完成标准

一个问题只有同时满足以下条件才算闭环：

1. 源码修复真实存在；
2. 修复前可失败的回归已经进入正式测试；
3. 正向合法路径没有被误伤；
4. 三档和相关 Feature 组合构建通过；
5. Sanitizer/Analyzer/Release 等与风险相称的门禁通过；
6. 文档状态与代码一致；
7. Host 软件通过没有被写成实机或生产完成。
