# 项目定位与成熟度

## 1. UCN 解决什么问题

UCN v6 面向资源受限 MCU 上的异构多跳通信。应用面对统一的消息、Endpoint、RouteSet 和
Transfer 语义，而 UART、CAN、Wi-Fi、USB 等差异被限制在 Adapter/Bearer 边界。节点不依赖
Linux 才能寻路、转发或恢复；Linux/ROS 2 只能作为普通 Host、网关或诊断参与者。

目标不是复制 TCP/IP 的全部能力，而是在固定内存、可预测时序和多介质环境中提供：身份不
随地址复用而混淆，路由切换不半提交，优先级不被远端提权，大消息不需要无限缓存，掉电后
不会把不确定副作用伪装成成功，实时元数据和簇管理可按产品需要独立裁剪。

## 2. 当前软件能力

当前树只含 v6 运行时。基础模块包括 Config、Identity、Wire、Message、Owner、Security、
Capability、Route、QoS 和 Transfer；可选模块包括 Realtime、Cluster、Adapter。所有生产
对象使用调用方提供的固定 Storage，初始化前核对大小、对齐、API Version、Storage Layout
和 Feature Manifest。

Nano、Lite、Full 使用同一协议和解析器。低档节点不会因为容量较小而看不懂高档节点发出的
合法 v6 帧；差异在于可保存的表项、并发事务和最大主动发送 Message Class。对端必须通过
Capability/Path Budget 得知发送上限，不能把 Full 的容量假设强加给 Nano。

## 3. 成熟度分层

| 证据层 | 能证明 | 不能证明 |
|---|---|---|
| 合同/源码 | API、状态机和失败语义已写入当前树 | 目标硬件时序、资源和电气行为 |
| Host 软件 | 单元、负向、模型、规模与安装消费通过 | ISR/DMA、Flash 撕裂写、RF、总线仲裁 |
| 实机证据 | 指定板卡、固件、接线和时长下达到阈值 | 未测平台、未测规模或不同物理环境 |
| 发布签字 | 同一候选提交关闭全部 required gate | 后续任意改动仍需重新验证 |

当前处于“软件实现和多轮自审”层。V6-13/14 的硬件与部分工具链门禁仍为 HOLD，所以项目
不能被称为 1.0 RC、生产安全或全平台兼容。

## 4. 不承诺的内容

- 不自动选择芯片引脚、DMA channel、CAN filter 或 Wi-Fi SDK 参数；
- 不内置产品密钥注入、证书颁发、硬件 Root of Trust 或经过认证的 AEAD 实现；
- 不保证任意拓扑下零丢包、恒定带宽或硬实时；
- 不把 10k 模拟解释为一块 MCU 保存 10k 节点；
- 不把可选 Cluster/Realtime 变成基础转发的依赖；
- 不兼容 v4/v5 Wire、Record、公共 ABI 或构建开关。

## 5. 产品化判定

产品必须先固定 Profile、Feature、容量、Security Suite、Address Authority 模式、Bearer、
最大拓扑和消息等级，再生成 Manifest 并完成对应矩阵。只有所有 required gate 都绑定同一
commit、固件 SHA-256、原始日志与阈值后，才能讨论发布。
