> 文档级别：`REFERENCE`
> 实现状态：`CURRENT`
> 适用版本：UCN 5.0.0 / Core Wire v5
> 事实源：ucn_config.h、ucn_profile.h、CMake 与资源门禁

UCN 默认不依赖动态分配，运行容量由编译期固定表决定。

## Core 默认示例

| 参数 | 默认值 | 作用 |
| --- | ---: | --- |
| `UCN_MAX_LINKS` | 4 | 一个 Node 同时注册的 Link |
| `UCN_MAX_ROUTES` | 8 | 路由缓存 |
| `UCN_MAX_NEIGHBORS` | 8 | 邻居表 |
| `UCN_MAX_BEARERS_PER_NEIGHBOR` | 2 | 单邻居可记录 Bearer |
| `UCN_MAX_ROUTE_DISCOVERIES` | 4 | 并行发现事务 |
| `UCN_MAX_CANDIDATE_ROUTES` | 8 | 候选路由 |
| `UCN_MAX_ENDPOINT_HANDLERS` | 8 | Endpoint handler |
| `UCN_MAX_PATH_FORWARD_ENTRIES` | 8 | Path 转发表 |
| `UCN_MAX_ROUTE_POLICIES` | 8 | 路由策略 |
| `UCN_MAX_POLICY_FLOWS` | 8 | Policy flow |

默认最大 Core Frame 为 256 B，默认最大 hop 为 16。Transfer 的 T32～T8K 是上层有界消息类，不等于把 Core 单帧扩成 8 KiB。

### 其他默认容量

| 类别 | 参数 | 默认 | 含义 |
| --- | --- | ---: | --- |
| TX | `UCN_TX_Q0_DEPTH` / `UCN_TX_Q1_DEPTH` | 4 / 4 | 控制/业务队列深度 |
| RX | `UCN_ADAPTER_RX_QUEUE_DEPTH` | 2 | Adapter 完整帧提交槽 |
| Event | `UCN_EVENT_RUNTIME_MAX_SOURCES` | 8 | 可注册事件源数 |
| Transfer | TX/RX slots | 1 / 1 | 并行发送/重组事务 |
| Transfer | max window | 8 | 未确认 Fragment 上限 |
| Transfer | endpoints/peers | 4 / 4 | 传输端点和对端状态 |
| Security | endpoint policies | 8 | Endpoint 安全策略数 |
| Service | bindings | 6 | 本机/远程服务绑定 |
| Cluster | peers/candidates/members | 8 / 8 / 16 | 默认簇控制面容量 |

这些值来自当前 fallback，仅用于说明量级；某个 Profile 可能裁掉相关对象，产品配置也可以覆盖。

## 容量调整原则

每增加槽位都可能同时增加主对象、候选、统计或 scratch 开销。先用目标拓扑计算最低度数和并发，再运行 Profile/产品配置构建与资源报告。容量不足应明确返回 `NO_SPACE`，不能覆盖活跃槽或无界扩容。

### 如何计算最低值

- `MAX_LINKS`：同一节点同时启用的物理实例数，不是介质种类数；两个 UART、两个 CAN 和一个 Wi-Fi 至少需要 5 个 Link；
- `MAX_NEIGHBORS`：节点可同时直连并需要保持状态的对端数；
- `MAX_BEARERS_PER_NEIGHBOR`：同一对端并行保留的 UART/CAN/Wi-Fi 路径数；
- `MAX_ROUTES`：需要同时活跃/缓存的远端目的地数，加上诊断和故障切换余量；
- `ROUTE_DISCOVERIES`：同一时刻可能触发的未知目的地查询数；
- `TX_Q*`：在最坏 Owner 延迟内到达的消息数，而不是平均速率；
- Transfer slots/window：应用允许并行的大消息数和带宽时延积；
- Cluster members/voters：单簇硬上限，不能用全网总节点数直接代入。

### 队列深度示例

若业务任务峰值每 1 ms 产生一条消息，而 Owner 最坏 10 ms 才得到一次运行机会，则仅吸收该突发就需要约 10 个槽，还未计入正在发送、重试和跨任务竞争。更合理的选择可能是让应用只保留最新传感器样本，而不是把队列盲目扩到很大。

### 满载语义

不同对象的满载处理必须预先定义：Q0 可有界重试，Q1 可返回背压；路由发现槽满应拒绝新发现但保留已有事务；证书 pending 槽不得被未通过 admission 的帧抢占；成员/voter 表满不得淘汰仍有 Authority 关系的记录。
