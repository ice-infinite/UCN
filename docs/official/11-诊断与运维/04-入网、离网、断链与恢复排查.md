# 入网、离网、断链与恢复排查

> 文档级别：`GUIDE`
> 实现状态：`CURRENT（诊断方法）`
> 适用版本：UCN 5.0.0 / Core Wire v5
> 事实源：状态视图、统计 API、测试与现有实测记录
> 最近核对：`codex/v5-adaptive-wire@a093862`，2026-08-25
> 硬件状态：部分实测；未测项不得推断

入网依次确认 Link Up、HELLO/Neighbor admission、Endpoint/Route 建立和业务收发。离网依次观察 heartbeat 缺失、SUSPECT、REMOVE、RERR、Route/Path 清理与重新发现。

节点突然接入不应触发无界全网洪泛；检查 HELLO schedule、RREQ rate limit 和固定表是否满。断链恢复要区分物理 Link、Neighbor、Route 和 Cluster lease 四个时间尺度。

## 入网状态链

```text
Driver ready
  → Link UP/有效MTU
  → HELLO交换与physical peer binding
  → Neighbor CANDIDATE
  → Join authorize/challenge
  → Neighbor ADMITTED
  → Route discovery或直达Route
  → Endpoint/Service业务
  → 可选Cluster Join
```

记录每一步时间戳即可计算入网耗时并定位停在哪层。Cluster加入晚于Core Neighbor，不要把Cluster Role未稳定误判为底层无法通信。

## 入网失败索引

| 停止点 | 重点检查 |
| --- | --- |
| Link不UP | 引脚、baud/channel、Driver、USB枚举、CAN bus state |
| 无HELLO | RX Source/Carrier、scheduler、Network ID/Wire |
| Candidate不Admit | Join policy、MAC/Node binding、安全challenge |
| 已Admit无Route | RREQ限流/槽、hop/Cost constraints、单向链路 |
| Route有但业务无 | Endpoint、Security、duplicate/session、应用ready |
| Core正常Cluster不入 | v3/v4、保护、Persistence、Role/Lease |

## 正常离网

计划离网应先停止新业务，必要时撤销Path/Locator/Cluster membership，再关闭Link。突然断电则靠Heartbeat freshness：到SUSPECT后不立即删除，REMOVE后清Neighbor并撤销依赖Route/Path；源收到RERR后按需重新寻路。

## 四个故障时间尺度

- Driver Link Down：可以毫秒级立即知道；
- Neighbor Suspect/Remove：通常秒级Heartbeat窗口；
- Route Cache：Link显式失败立即失效，否则按lease/expiry；
- Cluster Lease/Recovery：有quorum/观察/选举窗口，通常更长。

所以“节点多久掉线”必须说明问的是哪一层。

## 节点突然加入的网络代价

正常只在直连范围发送HELLO/Join，再由有业务的节点按需Route discovery。检查control token、RREQ cache和每秒峰值；若一个节点加入导致全网广播风暴，说明实现/配置违背按需原则。

## 恢复

Link重连后先清半帧/reassembly，重新HELLO、绑定session和验证Neighbor。旧Route若next hop/session不再匹配应失效。Path需重新probe/install或确认lease；Cluster遵守稳定Authority优先，旧高分Head不应立刻抢占。

## 故障注入记录

明确断开“哪一段Link/哪个Node”、时长、重连顺序和预期状态。至少做瞬时抖动、超过suspect未remove、超过remove、长期分区、同时断两条Bearer、节点重启换session。
