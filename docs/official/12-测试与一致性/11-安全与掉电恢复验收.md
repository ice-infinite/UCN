# 安全与掉电恢复验收

> 文档级别：`NORMATIVE`
> 实现状态：`CURRENT（测试规范）`
> 适用版本：UCN 5.0.0 / Core Wire v5
> 事实源：CMake、tests、tools、results 与审计门禁
> 最近核对：`codex/v5-adaptive-wire@a093862`，2026-08-25
> 硬件状态：实机证据按具体报告；规范本身不代表已验收

安全测试使用生产候选 AEAD/密钥后端，覆盖已知向量、篡改、重放、乱序、Session rollover、密钥错误、ACL 和透明密文转发。

掉电测试使用真实双槽 Flash，在 load、submit、erase/program、commit marker 前后可控断电；重启验证旧记录或新记录二选一，不能出现零结构伪成功、Term/sequence 回退或重复 promise。

软件 mock 的 torn-write 测试是前置门禁，不是实机验收替代品。

## 安全矩阵

### 密码正确性

使用算法标准/产品已知向量验证key、nonce、AAD、plaintext、ciphertext、tag。分别篡改30 B AAD的每类字段、ciphertext首中尾和tag，全部拒绝且明文不写回。

### 身份/授权

合法/非法source、Endpoint、Role、Link、Plain/E2E policy；中继opaque转发；Terminal-only；远端Q0 validator。验证低权限节点不能调用诊断/Path/执行器。

### Replay/轮换

重复、旧sequence、窗口内乱序、跨session、重启、Sequence阈值、rotate掉电、旧key撤销。确保任何路径不复用`key+nonce`。

## Flash掉电夹具

最好由外部控制器切断目标板电源，并能在Provider的erase/program/marker阶段通过GPIO触发。每个断点重复多轮，不能只用软件reset模拟断电。

## 双槽验收

```text
初始记录A有效
 → 写B各偏移断电
 → 重启只能加载A或完整B
 → generation/CRC/journal一致
 → 再反向写A验证磨损轮换
```

覆盖空Flash、单槽坏、两槽一新一旧、commit marker撕裂、CRC碰撞不可假设、generation回绕门禁和坏块/写失败。

## 协议级掉电

- Vote submit前/中/后：未durable不ACK；
- Config Prepare/Joint/Commit/Abort各阶段；
- Rekey/Tombstone；
- boot incarnation/sequence预留；
- durable成功后发送队列满/断链：状态仍可重试，不误报persistence fault。

重启后不仅看init成功，还检查Term/Config/sequence不回退、旧promise不重复、PREPARED恢复/迁移正确、Authority在证据建立前保持Fence。

## 介质寿命

估算每秒/每天写次数、擦除周期、预留sequence块和产品寿命；跑加速磨损及错误注入。真实Flash缓存/电源保持时间纳入Provider设计。

## 证据

保存每轮断点、供电波形/trigger、刷写次数、启动日志、原始槽dump/hash和最终状态。没有真实夹具时明确标记“软件fault injection”。
