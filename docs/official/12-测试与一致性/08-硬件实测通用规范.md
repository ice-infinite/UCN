# 硬件实测通用规范

> 文档级别：`NORMATIVE`
> 实现状态：`CURRENT（测试规范）`
> 适用版本：UCN 5.0.0 / Core Wire v5
> 事实源：CMake、tests、tools、results 与审计门禁
> 最近核对：`codex/v5-adaptive-wire@a093862`，2026-08-25
> 硬件状态：实机证据按具体报告；规范本身不代表已验收

每轮记录：板卡型号/数量、端口和 Node ID、固件 commit/hash、编译配置、接线表、供电、Bearer 参数、测试动作、开始/结束时间、原始串口/抓包、统计和结论。

故障测试明确拔哪一段线、断电哪个节点、持续多久和恢复顺序。重复至少给出轮数，不能只写“按了/好了”。

修改固件后重新记录 hash；不同构建不可混在同一对比表。

## 台架清单

| 类别 | 必须记录 |
| --- | --- |
| 设备 | 芯片/板卡/Flash/PSRAM、序列号或标签 |
| 固件 | commit、dirty patch、env、binary SHA256 |
| 地址 | COM口、Node ID、MAC/CAN ID、Cluster角色 |
| 接线 | A pin→B pin、GND、收发器、终端电阻、供电 |
| Bearer | baud/bitrate/channel/MTU/preset/security |
| 工具 | PlatformIO/SDK/编译器、串口抓取/分析仪版本 |
| 环境 | 距离、屏蔽/干扰、温度、电源电压 |

烧录同一固件但Node ID可由Flash/MAC/编译配置派生；报告必须写清每块板最终启动日志中的ID，不能只用COM口猜。

## 测试前自检

先烧最小打印固件确认板卡/USB稳定，再烧单Bearer loopback，再运行UCN。检查交叉TX/RX、共地、CAN终端、RS-485方向和USB供电。若USB反复枚举，先排查供电/watchdog/引脚冲突，不继续跑协议压力。

## 自动采集

尽量用脚本同时打开多个COM，给每行加host receive timestamp并保存原始文件。测试动作另写event log：`t=... unplug B-C`、`reset node B`。终端界面显示不是证据替代，原始日志应可重新解析。

## 重复与对照

每项至少多轮，报告成功数/总轮、min/median/max/p95。优化前后使用相同板、接线、固件差异和动作；若只换一个参数，其他条件固定。

## 故障恢复

分别测试短断、超过suspect、超过remove、节点重启、逐段断、多段断、恢复顺序。记录业务流是否中断、丢多少/乱序、Route/Authority何时切换与最终状态。

## 数据完整性

payload含sequence/pattern/CRC，接收端统计missing/duplicate/out-of-order/corrupt。仅统计发送/接收字节数无法发现重排或重复。

## 结论边界

明确“已测板卡/接口/速率/时长”与“未测无线、CAN、其他RTOS、功耗”等。一次UART三跳通过不能证明所有Bearer或零丢帧。
