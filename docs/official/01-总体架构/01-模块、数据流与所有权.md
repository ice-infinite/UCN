# 模块、数据流与所有权

## 1. 分层

```text
业务调用
  ├─ Message / Operation Journal
  ├─ Transfer（需要分片时）
  └─ Realtime Envelope（Endpoint 明确要求时）
        ↓
Security → RouteSet → QoS → Wire Encode
        ↓
Adapter Queue → Bearer Driver → 物理链路

物理中断/回调
        ↓
原子 RX Item → Protocol Owner Event
        ↓
Wire Decode → Hop Security → Route/本地分派
        ↓
E2E Security → Endpoint ACL → Realtime/业务副作用
```

Config 决定容量和可编译 Feature；Identity 建立不依赖临时地址的 Principal 与 Binding；
Capability 决定一条 Path 上双方真实可用的 Frame/Payload/Feature 交集。Cluster 与 Realtime
共享这些基础层，但彼此不链接。

## 2. 单 Owner 原则

协议状态只由一个 Protocol Owner 推进。ISR/驱动回调只负责把固定大小事件放进有界队列并
唤醒 Owner，不在中断中运行 Route、Security、Transfer 或 Cluster 状态机。Owner 收到通知
后立即处理预算内事件；timer 只是超时和无中断平台的保底，不要求等心跳才发送队列数据。

公开 Provider/Driver 回调可能重入，所以每个需要外部 I/O 的对象必须使用调用方持有的共享
callback gate。Gate 必须覆盖多个对象、任务与 ISR/SMP 场景，不能用未同步静态指针或
`volatile` 冒充并发安全。

## 3. 固定内存

公共对象是不透明 handle，实际内存由 `UCN_V6_*_STORAGE_BYTES` 和对应 Storage 类型在编译
期确定。初始化顺序为：核对 Manifest → 核对 Storage 大小/对齐 → 清零并建立私有 magic/
schema → 注册 Provider/Driver。运行时禁止 heap；表满返回明确错误，不驱逐安全状态，也不
把失败静默降级成低安全路径。

## 4. 发送路径

应用先构造 `ucn_v6_message_t`，明确 Traffic Class、Delivery Guarantee、Interaction Role
和 Operation ID。若超出单帧 Payload Budget，进入 Transfer；否则直接进行安全封装、路由
选择和 QoS 排队。QoS 选中后才交给 Adapter，Driver 完成事件必须回到 Owner 才能释放 token。

任一阶段失败都必须保持未提交状态：Route Candidate 在 Probe/Activate/ACK 完成前不能替换
Active Route；durable operation 未持久化前不能执行外部副作用；Adapter 未确认完成前不能
复用 buffer token。

## 5. 接收和转发

接收先形成不可错位的原子 `{frame,event-key,timestamp}` 或普通 frame item，再进入 Owner。
中继只解析路由、安全和逐跳调度所必需的可见字段；E2E Payload、Realtime Envelope 和业务
内容保持不透明。目标节点在业务副作用前再次做 E2E、ACL、Replay、Deadline 和 Operation
Journal 门禁。

## 6. 故障恢复

Session/Binding/Path/Link Instance 任一代际变化都会使依赖旧域的 Route、QoS、Transfer、
Realtime pending 和 Cluster Authority 失效。持久化状态必须 reload 后再决定能否承诺；
无法证明新鲜性、完整性或单调性时 fail-closed，而不是回退读取更旧且可能已经发布的状态。
