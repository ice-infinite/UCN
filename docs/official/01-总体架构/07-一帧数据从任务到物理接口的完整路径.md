# 一帧数据从任务到物理接口的完整路径

> 文档级别：`NORMATIVE GUIDE`
> 实现状态：`CURRENT`
> 最近核对：`a093862`，2026-08-25

## 发送路径

```text
业务任务
  ├─ 直接 Node Send
  └─ Service Send（本机则进入 Inbox，远端则进入 Bridge Queue）
        ↓
Endpoint + Destination Node + Q0/Q1 + Delivery semantic
        ↓
安全 TX 授权 / 是否 E2E 保护
        ↓
显式 Path / Policy / Route / 直连 Neighbor 选择
        ↓
按目标能力、字段和 MTU 选择 W0～W3
        ↓
写入 Node Q0/Q1 固定队列
        ↓（立即唤醒或下一次 Owner step）
选 Link → Frame Encode → Link send 回调
        ↓
产品 Driver / DMA / 控制器
```

数据入队后不需要等待 HELLO 周期才发送。只要 Owner 被事件唤醒或按最大 Step 间隔运行，就会在队列与调度预算允许时尝试发送。

## 接收路径

```text
外设 ISR/DMA
   ↓
Stream/CAN/自定义 Source 固定 Ring
   ↓ Owner service
完整 Carrier Frame → Adapter RX Queue
   ↓
peek Wire Profile/长度 → Frame Decode/CRC
   ↓
Network/Session/Replay/Security/ACL/Hop 校验
   ├─ 本节点：控制 handler / Transfer / Endpoint / Service Bridge
   └─ 非本节点：Route/Path 选下一跳并转发
```

## 中继节点

中继节点不需要知道 IMU、气压、温度等业务语义，只使用目标 Node、Endpoint 外层语义、Hop、Route/Path 和安全转发策略。E2E 密文可在不解密 Payload 的情况下透明转发。

## 完成语义

- `ucn_node_send()` 成功：本地队列接受，不代表远端收到。
- Link send 成功：Driver/链路队列接受，不代表远端任务执行。
- Transfer `DELIVERED`：远端完成重组并返回 ACK，不代表业务执行成功。
- Service Result `REMOTE_EXECUTED`：必须由远端业务任务显式返回，不能由传输层推断。

## 1. 发送前的输入检查

Node 首先验证目标不是非法地址、Endpoint 在允许范围、Payload 不超过当前接口上限、Q0/Q1 合法、deadline 尚未过期、Hop 在本地/线上上限内。若安全策略要求 E2E，而 Provider 未就绪，发送在入队前失败。

这一顺序保证错误请求不会先占据有限队列再在发送时失败。

## 2. 路由选择的优先顺序

概念上先检查业务 Policy：

1. `PINNED_STRICT`：只接受指定 Path/egress，失效直接报错；
2. `PINNED_FAILOVER`：优先指定 Path，故障时允许普通 Route；
3. `AUTO_BALANCE`：只对允许的 Q1 flow 在验证候选间选择；
4. 普通自动：使用有效 Route；
5. 目标为一跳 Neighbor 时使用直连 Bearer；
6. 没有路线则进入路由发现或返回未找到/等待状态。

精确顺序以 Policy/Route 实现为准，但业务不应自行遍历 Link。

## 3. Wire Class 和序列号

发送方计算能表达当前地址、Cost、Hop 和扩展字段的最低 W0～W3，再与远端接收上限和路径 MTU 求交。随后分配 Source Session 下的 Sequence，用于普通 Frame 重复抑制和安全 AAD/Replay 语义。

如果字段只能由 W2 表达，而路径只允许 W1，必须返回能力错误，不允许截断成 W1。

## 4. 队列和即时发送

数据进入 Q0/Q1 队列后由 Owner 尽快推进。事件 Runtime 会在应用提交或 Driver completion 后唤醒 Owner；`UCN_MAX_STEP_INTERVAL_MS` 是兜底上界。Heartbeat/HELLO 周期与业务发送无关。

Q0 FIFO 保留顺序；Q1 可按 Endpoint/flow 使用 Latest 语义。队列满时调用方收到背压，应按业务 deadline 决定重试、覆盖旧状态或失败。

## 5. 中继的具体动作

中继接收后：

1. 严格解码并检查 Network/版本/长度；
2. 执行重复窗口和允许的安全转发策略；
3. 检查目标不是本地；
4. Hop 为 0/即将耗尽则丢弃并计数；
5. 查 Path/Route 得到下一跳；
6. 更新允许变化的路由字段并重新编码；
7. E2E Payload/Tag 保持不被中间节点解密或修改。

## 6. 接收端分发顺序

控制 Type 进入 Node 控制 handler；Transfer Fragment 进入 Transfer Endpoint；普通业务进入 Endpoint handler；Service Bridge 再把对应 Endpoint 转入本机 Inbox。未注册 Endpoint 返回/统计未找到，不能把 Payload 随便交给默认任务。

## 7. 失败例子：链路在发送中断开

假设 A→B→C，B→C Link Down：

- B 的 Link send 返回 `LINK_DOWN`；
- B 使依赖该出口的 Route/Path 失效并按范围产生 RERR；
- A 收到 RERR 后清理到 C 的缓存；
- 普通 Q1 可在 deadline 内重新发现路线；
- Transfer 根据 fragment/ACK 状态有界重传；
- 已经交付到 C 的业务是否执行由 Service Result 处理。

协议不会承诺切换期间绝对零丢失。无缝程度取决于备选路径验证、队列、deadline 和上层幂等。

## 8. 调试观察点

发送失败时依次查看应用 acceptance、Node queue、Route/Path、选中 Link、Driver completion；接收失败时依次查看 Source ring、Carrier、Adapter Queue、Frame decode、安全、重复、Endpoint。不要直接把最终 `TIMEOUT` 归因于无线速度。
