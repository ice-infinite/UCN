# 内存、时间与失败关闭三条基础契约

> 文档级别：`NORMATIVE`
> 实现状态：`CURRENT`
> 最近核对：`a093862`，2026-08-25

## 静态内存契约

- UCN 库不使用动态分配。
- 所有表、队列、Ring、Slot 和对象都有编译期上限。
- 表满返回 `UCN_ERR_NO_SPACE`、拒绝或按明确策略处理；不得隐式扩容。
- Feature/Profile 变化可能改变对象布局，整个产品必须使用一致编译定义。
- Host `sizeof`、Archive text 和 `.su` 只是软件资源证据，最终 MCU 仍需 linker map、栈水位和运行测量。

## 时间契约

- 协议使用调用者提供的权威 32 位单调毫秒时钟。
- Deadline 比较必须使用回绕安全函数，持续时间不能超过 `INT32_MAX` 语义窗口。
- Node 的唯一 Owner 应在 `UCN_MAX_STEP_INTERVAL_MS` 内被事件或兜底调度推进。
- Transfer 不接受第二份调用者缓存时间；它从配置回调统一采样。
- Heartbeat、路由老化、ACK、Retry、Cluster Lease 等是独立定时器，不依赖业务发送或 HELLO 周期触发。

## 失败关闭契约

以下情况必须拒绝或撤权：

- Magic、版本、长度、CRC、Flags、保留位非法；
- 字段超出 Wire Profile 表示范围；
- MTU、Hop、Route、Path 或能力不满足；
- 安全策略要求保护但 Provider 未就绪；
- 输出缓冲不足、表/队列/Slot 满；
- FSM 转换、Epoch、Config、Vote、Persistence 证据非法；
- 串行号达到 no-wrap 阈值。

失败关闭并不意味着所有错误都永久锁死。例如队列背压可有界重试，Link Down 可触发回退；但这些恢复必须由明确状态机执行，不能把传输错误误记成持久化成功或权限成功。

## 1. 静态容量如何设计

产品先从最大并发反推表大小：同时在线 Link、直连 Neighbor、目标 Route、进行中 RREQ、Q0/Q1 队列、Transfer TX/RX、Service Inbox 和 Cluster 成员。每项都应有“满时行为”，例如拒绝新事务、替换最旧非活跃缓存或回收已过期项。

错误示例：把 Route 表从 8 调到 64，却不计算 `ucn_node_t`、Candidate、Policy 和 MCU RAM 总增量；或给 T8K 配多个 RX slot，却只看 Core object 大小。

## 2. 时间来源为什么必须统一

如果 Node 使用系统 uptime、Transfer 使用调用方缓存时间、Cluster 又使用另一时钟，就会出现 ACK 已过期但 Route 仍有效、重启后 transaction 立即超时等问题。所有相关模块应从同一权威单调时钟采样。

32 位毫秒约 49.7 天回绕，因此不能使用 `now >= deadline` 的普通无符号比较。UCN 使用半范围时间代数，duration 必须不超过 `INT32_MAX` 毫秒。

## 3. Deadline 与周期的区别

- 周期：何时发下一次 Heartbeat/Probe；
- Deadline：一项工作最晚何时仍有意义；
- Timeout：等待状态允许持续多久；
- Lease：对端声明/投票可被信任到何时。

业务发送不等待周期；周期只维护状态。舵机命令即使网络后来恢复，超过业务 deadline 也应丢弃，不能晚到执行。

## 4. 错误分类和恢复

| 错误类型 | 示例 | 恢复策略 |
| --- | --- | --- |
| 暂时背压 | Queue/Driver 满 | deadline 内有界重试 |
| 链路故障 | Link Down/Bus-Off | RERR、Failover、重新发现 |
| 输入错误 | malformed/version/CRC | 丢弃并计数，不重试同帧 |
| 配置错误 | 缺 Provider/Profile 冲突 | 初始化失败，修产品配置 |
| 安全错误 | ACL/tag/replay | 拒绝并审计，不自动降级明文 |
| 权威错误 | quorum/lease/Fence | 撤权，等待合法恢复事务 |
| 持久化错误 | torn write/reload 不一致 | fail-closed，禁止 promise |

## 5. “失败不写回”原则

解析、查询和构建 API 应先完成全部校验，再写调用者 output。否则调用者可能误用半初始化 Epoch、Route 或安全明文。测试不仅检查返回码，还用哨兵和 `memcmp` 验证错误时完整 output 不变。

有些异步 API 会明确进入 `PENDING`，这不是失败写回；其状态和所有权必须在接口中说明。

## 6. No-wrap

安全相关 serial、Term、Config generation、txid 和 incarnation 在接近冻结阈值时停止自增，通过 Session rollover、Rekey 或明确恢复进入新身份域。自然整数回绕会让旧消息重新落入可接受窗口，因此不能继续运行到 0。

## 7. Fail-closed 的代价

失败关闭可能降低可用性：表满会拒绝新节点，Persistence 故障会让 Cluster 停止承诺，未知版本会丢帧。UCN 选择先保护状态一致性，再通过明确扩容、恢复和升级流程恢复服务，而不是为了“看起来在线”接受不可信状态。

## 8. 产品验收

除软件测试外，产品需测：各固定表峰值、Owner 最大间隔、deadline 长尾、时钟回绕/重启、Link 故障、持续背压、真实 Flash 撕裂写和目标 MCU stack/heap。只有这些数据才能确认默认参数适合具体产品。
