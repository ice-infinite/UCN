# 数据平面、控制平面与诊断平面

> 文档级别：`NORMATIVE`
> 实现状态：`CURRENT`
> 最近核对：`a093862`，2026-08-25

## 数据平面

数据平面承载 `UCN_MSG_DATA_Q0/Q1`、Transfer Fragment/ACK 和可选 Service Bridge 业务。它按目标 Node、Endpoint、Traffic Class、Route/Path/Policy 发送，并在中继节点只做必要的校验、Hop 递减和下一跳选择。

数据平面不负责：

- 发现邻居；
- 建立 Route；
- 授予 Cluster Authority；
- 推断远端业务任务已经执行完成。

## Core 控制平面

Core 控制帧包括 HELLO/Join、Heartbeat、RREQ/RREP/RERR、Path Probe/Activate/Install/Revoke 等。它维护一跳状态和有界路由/Path，不需要业务层为每种介质重写寻路流程。

维护控制帧与业务队列共享发送机会，但 Node 使用维护预算避免持续业务流永久饿死心跳和路由维护。

## Cluster 控制平面

Cluster 使用独立 Endpoint/固定帧和独立对象，处理 Role、Epoch、Member、Backup、Recovery、Config、Authority 等。它不是 Core 路由的替代层，也不应把所有 Cluster 状态塞入 `ucn_node_t`。

Current v3 和 Target v4/实验模型必须单独标识。存在 Codec 或模型不等于生产 RX/TX/FSM 已接线。

## 诊断平面

Full 提供 Path Trace、Node Snapshot、Policy Diagnostic 等低频诊断。诊断帧必须经过授权，尤其 Node Snapshot 默认拒绝远端管理请求。

诊断平面不得：

- 绕过正常 Route/Path 权限；
- 占用无界缓存；
- 以高频全网广播替代正常状态维护；
- 将调试数据误当作权威配置。

## 三平面共享的底线

三者都使用同一 Frame/Link/Adapter 边界、Hop 和安全入口，但具有独立状态、预算与权限。将它们分开是为了让业务拥塞、诊断请求或 Cluster 波动不能无限放大到整个协议对象。

## 1. 为什么要分成三个平面

如果所有消息都进入同一个无差别队列，持续日志流可能让 Heartbeat 发不出去，远程 Snapshot 可能挤占舵机命令，Cluster 重选又可能把业务流量全部阻塞。分平面不是定义三套 Wire，而是给消息不同的职责、权限、频率和预算。

## 2. 数据平面的完整生命周期

1. 应用选择目标 Node、Endpoint、Q0/Q1、deadline 和安全策略；
2. Node 查询 Route/Path/Policy；
3. 找不到路由时，Q1 可进入有界 Pending 并触发控制平面 RREQ；
4. 找到下一跳后，Frame 进入固定发送队列；
5. Owner 在维护预算之外发送业务；
6. 中继只按外层头转发；
7. 目标完成重复、安全和 Endpoint 校验后交付。

Transfer Fragment/ACK 属于数据交付协议，但仍使用 Core 路由。Service Result 属于业务语义，不能由普通数据帧接收自动生成。

## 3. Core 控制面的触发关系

| 控制消息 | 触发 | 改变的状态 | 不应改变 |
| --- | --- | --- | --- |
| HELLO | Link Up/调度周期 | Neighbor candidate/capability | 远端业务执行 |
| Heartbeat | 已准入邻居维护 | liveness、Bearer 质量 | 全网 Route |
| RREQ/RREP | 目标无 Route | Route/Candidate | Endpoint 数据 |
| RERR | 下一跳/Path 失效 | 相关 Route/Path | 无关目标路线 |
| Path Probe/Install | 显式 Path 管理 | Path 表/验证状态 | 普通自动 Route 语义 |

控制消息通常只在必要范围传播。Heartbeat 是一跳消息，不经中继全网转发；RREQ 才按受限 flooding 规则扩散。

## 4. Cluster 控制面为什么独立

Cluster 的选举/Config/Authority 安全要求高于普通路由。例如 Head 宣告可能要求 quorum、lease 和 durable promise，而普通 Route 更新不应等待 Cluster Flash。独立对象和 Endpoint 可以让 Core 在 Cluster 被关闭、Fenced 或升级时继续转发普通业务。

## 5. 诊断平面的请求模型

Path Trace 和 Node Snapshot 都是显式、低频、有 transaction/timeout 的控制请求：

- 正常通信不持续携带完整路径；
- 节点快照不持续同步全网目录；
- 请求者提供固定结果 buffer；
- 超时后返回已收到部分和明确状态；
- 产品 Authorizer 决定谁可以触发远程诊断。

## 6. 平面间的优先级示例

假设节点正在通过 Transfer 发送 4 KiB 日志，同时需要发送 Heartbeat 和 Q0 急停命令：

1. Source/Owner 先保证维护控制预算，避免邻居被误删；
2. Q0 急停进入关键 FIFO，不被后续状态覆盖；
3. Transfer Fragment 按窗口和队列余量继续；
4. 远程 Snapshot 如果达到诊断预算则背压或拒绝。

具体调度仍由实现和产品参数决定，但不能让低优先级诊断形成无界工作。

## 7. 安全边界

三个平面可以使用不同 Endpoint/Type 授权。允许普通数据的节点不一定有权限发 Path Install、Snapshot 或 Cluster Config；中继密文的节点也不因此获得解密和管理权限。
