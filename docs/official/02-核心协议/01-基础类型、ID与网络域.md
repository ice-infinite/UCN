# 基础类型、ID 与网络域

> 文档级别：`NORMATIVE`
> 实现状态：`CURRENT`
> 事实源：`include/ucn/ucn_types.h`、`src/core/ucn_core.c`
> 最近核对：`a093862`，2026-08-25

## 逻辑身份

| 类型 | 宽度 | 规则 |
| --- | --- | --- |
| `ucn_node_id_t` | 32 bit | 0 非法；`0xFFFFFFFF` 为广播；产品在 init 前提供 |
| `ucn_network_id_t` | 32 bit | 0 非法；不匹配网络的帧返回 Network 错误 |
| `ucn_session_id_t` | 32 bit | 用于区分节点启动/安全会话；保护重放域 |
| `ucn_sequence_t` | 32 bit | 每个 Source/Session 的单调帧序号 |
| `ucn_route_cost_t` | 32 bit | `UINT32_MAX` 表示 Unknown，最大有效值为其前一值 |
| `ucn_endpoint_t` | 8 bit | `0x40..0xBF` 为静态业务 Endpoint |

Node ID 是逻辑地址，不要求等于 MAC、芯片 UID 或固定硬件序列号。产品可从编译配置、Flash/NVS、出厂分配或身份服务读取；UCN Core 只要求在入网前得到合法值。

## Network ID

Network ID 是最外层逻辑网络域。不同 Network ID 的节点不会因为物理上能互收就自动成为同一 UCN 网络。它不是加密密钥，也不能替代身份认证。

## Wire Profile 对 ID 的限制

API 内部类型为 32 bit，但低 Wire Profile 只编码较窄字段：

| Profile | 地址宽度 | 最大普通 Node ID |
| --- | ---: | ---: |
| W0 | 1 B | 254 |
| W1 | 2 B | 65,534 |
| W2 | 3 B | 16,777,214 |
| W3 | 4 B | 4,294,967,294 |

发送选择低档时，Network、Source、Destination 和 Session 都必须可表达；否则选择更高档或失败，不能截掉高位。

## Endpoint 与 Message Type

Core 控制帧使用固定 Message Type。产品业务使用静态 Endpoint `0x40..0xBF`，复用 `frame.message_type`，因此每帧不额外增加 Endpoint 字段。产品必须冻结每个 Endpoint 的 Payload 版本、单位、字节序、Q0/Q1 和安全策略。

## 1. Node ID 从哪里来

UCN 不强制一种分配方式，因为不同产品的生产和维护流程差异很大。常见来源：

| 来源 | 优点 | 风险/责任 |
| --- | --- | --- |
| 编译期常量 | 简单、可预测 | 每块板烧录前要修改；量产易重复 |
| 芯片 UID/MAC 派生 | 默认唯一、无需配置 | 不便管理；必须处理截断/碰撞 |
| Flash/NVS 配置 | 可像 IP 一样管理和更新 | 首次配置、掉电原子性和回滚 |
| 安全身份 Provider | 可绑定证书/权限 | 实现和密钥基础设施复杂 |

推荐启动顺序是：先读取产品配置的 Node ID；没有显式配置时再使用经过碰撞处理的硬件派生值。Node ID 必须在 `ucn_node_init()` 前确定，不能先入网后随意改变。

如果两个节点使用相同 Node ID，路由、重复窗口、Service 结果和安全身份都会混淆。UCN Core 无法仅凭线上帧自动判断“同 ID 的两块物理板”，产品应在入网策略或身份 Provider 中拒绝冲突。

## 2. Network ID 的作用和限制

Network ID 防止物理上可互收的不同产品网络互相处理帧。例如同一实验室内有测试网和正式网，二者即使共享 Wi-Fi channel，也可用不同 Network ID 隔离普通协议状态。

Network ID 是公开路由字段，不提供保密或认证。攻击者可以伪造相同 Network ID，因此生产安全仍需认证 Source/Session、E2E Tag 和 ACL。

## 3. Source、Destination 与 Broadcast

Source 必须是合法单播 Node ID。Destination 可以是单播目标，也可以在具体 Message Type 允许时使用广播值。广播不代表“所有消息都应该全网 flooding”：

- HELLO/Heartbeat 通常限定一跳；
- RREQ 有 Hop、重复/Best-Cost 和速率限制；
- 普通业务广播是否允许由消息和策略决定；
- Cluster/Federation 有独立传播规则。

广播目标不能被写进需要唯一返回路径或唯一 Authority 的字段。

## 4. Session 和 Sequence 的组合身份

单独 Sequence 在节点重启后可能从小值重新开始。接收端用 `(Source, Session)` 选择重复窗口，再在该窗口内判断 Sequence。因此新 Session 可以建立新的序列域。

安全产品必须保证 Session 经过认证，并确保旧 Session 不会被攻击者重新激活；否则攻击者可以把旧帧换一个未经认证的 Session 绕过普通去重。

## 5. Route Cost 的数值域

`UINT32_MAX` 表示 Unknown，不参与“更小更优”的正常比较。有效 Cost 采用饱和加法，路径累加超过最大有效值时保持最大，而不是整数回绕成极小值。

线上 Route Cost 是相对稳定、可跨节点累加的基础值；Full 的队列、RTT、失败率等动态惩罚主要形成本地 effective select cost，不把局部瞬态拥塞无界传播到全网。

## 6. Endpoint 版本化示例

假设 Endpoint `0x40` 表示 IMU：

```text
byte 0      payload_version = 1
byte 1      flags
byte 2..5   timestamp_ms (big-endian)
byte 6..11  accel xyz (3 × int16, mg)
byte 12..17 gyro xyz  (3 × int16, mdps)
```

这只是产品 ABI 示例。接收端先检查 payload version 和精确长度，再解释单位。若未来增加四元数，可以定义 v2 或新 Endpoint，不能在没有版本字段的情况下猜长度。

## 7. 地址档位选择示例

节点 A=`0x12`、C=`0xEF` 可以由 W0 表达；如果 Network ID 或 Session 超过 1 B，仍必须提升 Wire Profile。Profile 选择检查的是该帧所有变宽字段，不是只看 Destination。

如果目标 Node=`0x00010000`，W1 无法表达，发送方应选择 W2/W3。路径只允许 W1 时返回能力错误，禁止发送截断后的 `0x0000`。
