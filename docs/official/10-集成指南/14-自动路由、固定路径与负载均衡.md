# 自动路由、固定路径与负载均衡

> 文档级别：`GUIDE`
> 实现状态：`PARTIAL（通用合同已实现，产品 BSP/SDK 需接入）`
> 适用版本：UCN 5.0.0 / Core Wire v5
> 事实源：公共 API、Port/Adapter/Source 实现与测试
> 最近核对：`codex/v5-adaptive-wire@a093862`，2026-08-25
> 硬件状态：部分 ESP32-S3 UART/ESP-NOW；其他平台按正文标注

- 自动：Route Cache 命中直接发；无路由时 RREQ/RREP，后台刷新候选。
- 固定：安装 Path/Pinned Policy，只走指定 next hop/Bearer；断链时按配置失败或转自动 Failover。
- 负载均衡：仅对允许的 Q1 flow，在多个已验证候选间按 Cost/利用率分配。

先启用自动路由并验证 RERR，再添加固定路径，最后开启负载均衡。Q0 不应因为追求吞吐而跨路径乱序。

## 自动路由接入

先为每个Link配置可靠status/metrics和Neighbor，然后使用普通`send_endpoint()`。首次`NOT_FOUND`时调用discover；收到RREP后缓存下一跳。Route接近过期时后台refresh，业务继续用当前verified route。

测试A-B-C、A-D-C两条候选：改变一条Link Cost，确认候选达到20%改善、连续样本/probe后才切换。直接断开活动Link应立即RERR/失效，不等待30s缓存到期。

## 固定Path

规划完整路径后，对源、每个中继和终点分别发送授权PATH_INSTALL。每个节点只安装本地下一跳。安装完成后设置Policy：

- `PINNED_STRICT`：只准指定Path；适合隔离控制链路；
- `PINNED_FAILOVER`：Path断开后转自动Route；适合固定主链+应急链。

Path capability应取整条路径的maximum Wire Class和minimum MTU瓶颈。撤销/lease到期后中继拒绝旧Path帧并发RERR。

## Q1负载均衡

只把多个已验证、满足安全/MTU/constraints的候选加入Policy。balance按flow绑定，而不是每包轮询：

```text
(destination, endpoint, flow) → selected path + lease
```

因此同一IMU流保持顺序，不同传感器/会话可分散到CAN/UART/Wi-Fi。queue pressure连续拥塞后才迁移，恢复后仍受hold/滞回。

## 优先级例子

| 业务 | 策略 |
| --- | --- |
| 舵机Q0 | CAN Pinned Strict，失败立即上报 |
| IMU Q1 | UART主、CAN failover或Auto Best |
| 多路相机摘要Q1 | Auto Balance按flow分配 |
| 日志Q3 | Wi-Fi Pinned Failover到USB，不占CAN |

## 失败和诊断

无候选时应返回明确错误，不能绕过Pinned/安全策略。查看Link Cost breakdown、Route candidates、Path entry/lease、Policy flow和switch stats。若路径频繁切换，先查metrics抖动/重复计费，再调整samples/hold，不能简单把Cost写死。

## 分阶段验收

1. 单路径稳定发送；
2. 自动发现/缓存/RERR；
3. 双路径Cost变更与无缝验证；
4. Pinned strict/failover断链；
5. Q1多flow平衡和顺序；
6. Q0+Transfer高负载下的公平性。
