# 05 · 机器人/无人机编队控制场景容量推演

> 场景：1 个控制节点（地面站/领航机）向一群机器人/无人机发送控制信息，经多节点转发，含各种复杂拓扑。
> 全部数字来自代码常量（已逐一核对）与模拟实测。核心问题：能解决吗？能同时控制多少？不同情况极限各是多少？

## 0. 决定极限的关键代码事实（已核实）

| 事实 | 值 | 含义 |
| --- | --- | --- |
| 每节点注册 Link | ≤4（UCN_MAX_LINKS） | **每条 Link 绑定单一对端**（link->peer_node_id 单值）→ 一跳精准单播上限 = 4 台 |
| 一跳直连 | 不占路由缓存 | find_direct_link 先于路由表 → 4 台直连始终可控，不挤占 8 条路由 |
| 远端路由缓存 | ≤8（UCN_MAX_ROUTES） | **多跳精准控制上限 = 8 台同时** |
| 并发寻路 | ≤4（UCN_MAX_ROUTE_DISCOVERIES） | 同时只能为 4 个未知目标发 RREQ |
| 本机 RREQ 预算 | 4 + 1/100ms ≈ 14 个/s | 每秒最多发 14 次寻路/广播控制帧 |
| 中间节点 RREQ 接收预算 | 5 + 1/200ms = 25 个/s | 多跳泛洪时中间节点是漏斗（254 节点两跳实测 15% 的数学根源） |
| 业务广播 | **不跨跳转发** | 广播只到一跳邻居；多跳群控只能靠多次单播 |
| 发送调度 | 1 帧/step = 100 帧/s（10ms） | Event Runtime 多轮可达 800 帧/s 峰值 |
| 邻居/心跳 | ≤8 邻居，心跳 1 帧/s/邻居 | 固定开销 |
| 跳数 | ≤16 | 链式最长 16 跳 |
| 实测佐证 | 254 节点 local 100%；16 节点 local 8 msg/tick 100%；64 节点 incast 15.5%；32 节点 pairs 13.1%；254 two-hop 15.0% | 见审计报告 02 |

## 1. 不同情况的极限表

### 情况 A：地面站一跳直控（星型）

| 子情况 | 同时可控数量 | 控制频率上限 | 极限依据 |
| --- | --- | --- | --- |
| A1 精准单播（每台不同命令） | **4 台** | 调度：100÷4=25Hz/台；介质 UART 115200：~11Hz；ESP-NOW：~100Hz | Link 4 上限（每 Link 1 对端） |
| A2 广播群控（同命令/带目标 ID 分拣） | **不限数量**（一跳介质范围内所有） | 100 帧/s（每帧 1 条命令）；token 不限制业务广播 | 广播帧一跳全收，不占路由表 |
| A3 混合 | 4 台精准 + 不限台群控 | 精准 4×25Hz + 群控 100Hz | 二者独立（队列共享 100 帧/s 总预算） |

**结论：一跳场景能控制"4 台精准 + 无限台群控"。若要每台独立命令控制 N>4 台，必须多跳或增加 Link 数（调大 UCN_MAX_LINKS，每条 Link 约 40B RAM）。**

### 情况 B：地面站 → 中继 → 机器人（两跳树）

| 项 | 值 | 依据 |
| --- | --- | --- |
| 网络容量 | 4 中继 × 3 台 = **12 台** | 中继 4 Link：1 上联 + 3 下联 |
| 同时精准控制 | **8 台** | 地面站路由表 8 条（中继是直连不占） |
| 控制频率 | 100÷8 = **12.5Hz/台** | 调度上限；Event Runtime 多轮可到 100Hz/台 |
| 上行遥测 | 8 台 × 10Hz = 80 帧/s RX，pump 预算轻松 | 中继转发不占业务队列 |
| 轮换扩展 | 12 台需轮换：8 活跃 + 4 等待 | 路由 30s 寿命，刷新 6s 提前 |

### 情况 C：三跳树（地 → 中继 → 二级 → 叶子）

| 项 | 值 | 依据 |
| --- | --- | --- |
| 网络容量 | 3×3×3 ≈ **39 台**（根 3 中继） | 每节点 4 Link：1 上联 + 3 下联 |
| 同时精准控制 | **8 台**（根路由表） | 8 条路由上限 |
| 二级节点约束 | 每二级 ≤8 台（其路由表） | 路由表共享 |
| 泛洪代价 | 3 跳 RREQ 泛洪，中间节点 25 帧/s 预算 | 实测 64 节点两跳 28%、254 节点 15% |
| 控制频率 | 12.5Hz/台（调度） | 与 B 相同（瓶颈在根） |

### 情况 D：链式编队（领航 → 僚机1 → 僚机2 → …）

| 项 | 值 | 依据 |
| --- | --- | --- |
| 链长 | ≤16 跳（16 台+领航） | 跳数上限 |
| 每中继下游 | ≤8 台 | 路由表 |
| 同时精准控制 | **8 台**（领航视角） | 路由表 |
| 群控 | 链上群控只能逐台单播（广播不转发） | 无业务多跳广播 |

### 情况 E：全网任意两两互连

| 规模 | 交付率 | 依据 |
| --- | --- | --- |
| ≤9 台 | 100% | 8 路由 + 直连 |
| 16 台 | 68.8% | 实测 |
| 32 台 | 43.8% | 实测 |
| 64 台 | 28.1% | 实测 |
| 254 台 | 15.0% | 实测（预算公式吻合） |

### 情况 F：上行遥测汇聚（多对一）

| 项 | 值 | 依据 |
| --- | --- | --- |
| 一跳汇聚 | 4 台 × 任意频率（介质限） | Link 4 |
| 两跳汇聚 | 8 台 × 10Hz 轻松 | pump 预算 3200 帧/s 理论 |
| 实测 | 64 节点 incast 15.5%（多跳汇聚） | 泛洪预算瓶颈 |

### 情况 G：混合业务（下行控制 + 上行遥测 + 广播群控）

| 业务 | 帧率 | 合计 |
| --- | --- | --- |
| 下行 8 台 × 12.5Hz | 100 帧/s | — |
| 上行 8 台 × 10Hz | 80 帧/s | — |
| 心跳 4 邻居 | 4 帧/s | — |
| 广播群控 | ~14 帧/s（token 预算） | — |
| **合计** | **≈198 帧/s** | **> 100 帧/s（step 模式）→ 需 Event Runtime 多轮（800 帧/s 上限）或降频** |

## 2. 核心结论

1. **能解决吗？能。** 一跳直连控制 16 节点高频（8 msg/tick）实测 100% 交付；两跳内 8 台精准控制 + 广播群控完全可用。
2. **同时精准控制（每台独立命令）= 4 台（一跳）/ 8 台（多跳）**。这是 Link 上限与路由表上限决定的硬数字。
3. **广播群控（同一命令）= 数量不限**，但只覆盖一跳；多跳群控需逐台单播（≤8 台）或应用层转发。
4. **控制频率 = 100 帧/s ÷ 目标数**（step 模式），Event Runtime 多轮可提升至 800 帧/s（8 台 × 100Hz）。
5. **任意两两互连 = ≤9 台 100%**；超过后按实测曲线下降（16 台 68.8%、32 台 43.8%）。
6. **50 台无人机的现实方案**：分层——地面站连 4 个区域控制器（一跳精准），每个控制器管 ≤8 台僚机（两跳精准）→ 总 4×8 = **32 台精准控制**；或地面站广播群控 + 8 台轮换精准。

## 3. 提高极限的手段（按性价比排序）

| 手段 | 提升效果 | 代价 |
| --- | --- | --- |
| 调大 UCN_MAX_LINKS（4→8/16） | 一跳精准 4→8/16 台 | 每条 Link ~40B RAM + 邻居表 |
| 调大 UCN_MAX_ROUTES（8→16/32） | 多跳精准 8→16/32 台 | 每条 ~40B RAM |
| 调大 UCN_ROUTE_REQUEST_RX_TOKEN_REFILL_MS 预算 | 多跳泛洪成功率 ↑（254 节点 15%→更高） | 防滥用能力下降 |
| Event Runtime 多轮 | 控制频率 100→800 帧/s | CPU 占用 |
| 分层设计（区域控制器） | 数量可线性扩展（每层 ×8） | 架构复杂度 |
| W0/W1 压缩档 | 命令帧 46B→33B，帧率 ↑ | 地址域缩小 |

## 4. 一句话回答

> **能控制：一跳 4 台精准 + 不限台群控；多跳 8 台精准（12.5Hz/台，Event Runtime 可 100Hz）；任意互连 ≤9 台全可靠。超过这些数字就进入"轮换控制"或"分层架构"区域——协议本身不崩溃，只是交付率按实测曲线下降（16 台 68.8% → 254 台 15%）。**
