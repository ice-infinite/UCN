# 01 · UCN 项目介绍与架构

## 1. UCN 是什么

UCN（Unified Communication Network）是一个面向 **MCU 自组网**的 C99 通信核心库（MIT 协议）。它让应用通过统一 Node/Link 接口通信，而**不把 WiFi、UART、CAN、BLE、LoRa 等具体承载方式带入路由核心**。

核心设计信条：
- **MCU-first**：没有 Linux 时 MCU 节点仍能独立发现、转发和恢复通信；Linux/ROS2/MAVLink/地面站只是可选 Host/Adapter。
- **无中心**：任何节点可随时加入/离开，不依赖 Coordinator 常驻。
- **零动态内存**：固定帧上限、固定表、静态数组，可在几千字节 RAM 的 MCU 上运行。
- **异构介质透明**：WiFi/ESP-NOW、UART、CAN、BLE、LoRa 统一抽象为 Link。
- **小核心、严格边界**：Core 只承担自组网必需能力，Q2/Q3、服务发现、时间同步等重能力全部后置为可选 Extended 或 Host。

## 3. 协议栈分层功能全景

| 层 | 组件 | 理论应实现 | 当前状态 | 证据/缺口 |
| --- | --- | --- | --- | --- |
| L1 物理 | 介质无关 Link 抽象 | 任意介质统一接口 | ✅ | ucn_link_t ops：open/send/poll/get_status/get_metrics |
| L1 物理 | 多介质同机接入 | WiFi+UART+CAN 同时在线 | ✅ | UCN_MAX_LINKS=4；T21 实机 UART+ESP-NOW |
| L1 物理 | 链路质量归一 | RSSI/SNR/错误率→统一 Cost | ✅ | ucn_link_metrics_t 9 项指标 + LC-1 定点 EWMA |
| L2 成帧 | W0-W3 多档线协议 | 按域/MTU 选最省字节 | ✅ | 头 17/21/26/30B；四档统一解码器 |
| L2 成帧 | CRC/完整性 | 传输错误检测 | ✅ | CRC16-CCITT 全帧 |
| L2 成帧 | 大消息分片 | 超帧消息可靠传输 | ✅ | Transfer T32~T8K（8KB）、CRC32、ACK |

| L3 网络 | 单层自动分簇 | 局部选 Head、加入、租约和失效重选 | ⚠️ 首阶段 | `ucn_cluster` Host 软件已验证；簇间寻址、拆并、多级簇和 MCU 实测未完成 |
| L3 网络 | 跨域互联 | 多域 Gateway | ❌ | V5-06 设计评审通过，明确不进当前 Core |
| L4 传输 | Q0/Q1 优先级 | 关键帧优先 | ✅ | Q0 抢占 + absolute deadline + 背压有界重试 |
| L4 传输 | Q2/Q3 | 可靠参数/批量 | ❌ | 规划 Extended（Core 明确拒绝） |
| L4 传输 | 可靠大消息 | ACK/重试/窗口 | ✅ | Go-Back-N 窗口 1~8、3 次重试、CRC32 整消息 |
| L4 传输 | 组播 | 群组通信 | ❌ | 规划 Extended（当前受限广播/多次单播） |
| L5 会话 | 会话 ID/防重放 | 端到端会话 | ⚠️ | Session ID + 32/64 位序列窗口已实现；完整会话生命周期未实现 |
| L5 安全 | 身份/入网授权 | 可信准入 | ⚠️ 框架 | ucn_security_ops Provider + JOIN_PROVIDER；真实身份/密钥未实现 |
| L5 安全 | E2E 加密 | 业务机密性 | ⚠️ 框架 | seal/open 接口 + AAD（Profile/地址/Path ID 绑定）；真实 AEAD 属 S02 未完成 |
| L5 安全 | 密钥轮换 | 防长期密钥暴露 | ⚠️ 框架 | rotate_session 接口 + 序列回退门禁已定义 |
| L6 服务 | 任务间通信 | 同节点任务协议通信 | ✅ | Service Router 本地零线上直达（Q0 FIFO/Q1 Latest） |
| L6 服务 | 跨节点服务 | 远程任务通信 | ✅ | Service Bridge + Validator + 防重放表 + Q0 背压重试 |
| L6 服务 | 服务发现 | 发布/订阅服务 | ❌ | 规划 Extended |
| L7 应用 | 远程诊断 | 路径/拓扑/策略查询 | ✅ | Path Trace / Node Snapshot / Policy Diagnostic（均需显式授权） |
| L7 应用 | 时间同步 | 全网时钟 | ❌ | 规划 Extended；当前仅单调本地时钟 |
| 系统 | RTOS 集成 | 多平台 | ✅ | 裸机/FreeRTOS/Zephyr/NuttX/RT-Thread 6 个独立 Port |
| 系统 | Linux Host | 与 ROS2/MAVLink 互通 | ❌ | 规划 UCN-Host（白名单 Bridge），MCU 侧不依赖 |

**全景结论**：协议栈 7 层骨架全部就位；Core 自组网主链已实现，Cluster 进入单层首阶段。Gateway、簇间 Locator/Tunnel、Q2/Q3、组播、服务发现、时间同步、Linux Host 与生产安全闭环仍是未完成的 Extended/Host 工作，不能用简单百分比掩盖发布门禁。

## 4. 关键设计机制

- **编译期配置合同**：ucn_config.h 集中 100+ 参数，优先级链「编译器宏 → 产品头 UCN_USER_CONFIG_HEADER → 全局默认 → 原头文件回退」；typedef char [1:-1] 断言在编译期拒绝非法组合（Hop>254、Q0 重试为 0、维护时延 ≥ Suspect 等）。
- **三档 Profile**：NANO（无动态网格/安全/诊断）/ LITE（动态网格+安全）/ FULL（全部），Service 正交开关；跨 Profile 符号门禁。
- **控制预算**：本机 token bucket（4+1/100ms）+ 每 Peer 独立预算（RREQ 5+1/200ms、Heartbeat 4+1/100ms、Trace 1+1/1s）+ 诊断独立预算，防单个故障 Peer 拖垮节点。
- **事件驱动**：ISR 只入队不处理协议；唯一 Protocol Owner 带预算批量 pump；Event Runtime 合并最多 8 个 Source。
- **安全 fail-closed**：UCN_SECURITY_REQUIRED_BY_DEFAULT=1 时，Provider 不完整/策略不生产级则拒绝一切收发。
- **静态内存纪律**：所有表/队列/窗口编译期定长，无 malloc、无递归、无隐式扩容。
