# V6S-00-01 文档结构与机器门禁

> 状态：`DONE / SELF-REVIEW PASS / FINAL EXTERNAL REVIEW PENDING`

## 1. 目的

文档门禁不是语义外审的替代品，但它必须阻止已经冻结的结构在后续编辑中悄悄漂移。
本子项把下列机械事实纳入同一个只读检查器：

- 维护范围内的本地链接存在；
- 逻辑模型编号、章节、状态围栏完整；
- Owner Mermaid 连线和伪代码调用符合唯一登记表；
- Markdown 表格的表头、分隔行和每个数据行具有相同列数；
- 简化版候选清单成员、字节数和 SHA256 与现场文件一致。

## 2. 表格解析合同

检查器只把“首尾均为 `|` 的连续行块”识别为规范表格。第二行必须是 Markdown 分隔行，
每个单元格必须匹配 `:---`、`---:`、`:---:` 或至少三个 `-` 的无对齐形式。

列数按实际分隔符计算，但以下 `|` 不作为列边界：

- `\|` 转义字符；
- 行内反引号代码中的 `|`，例如 `` `A | B` ``；
- fenced code block 中的全部文本。

只要表头、分隔行或任一数据行的列数不同，检查器就返回非零。它不猜测作者想把多出的
单元格拼回上一列，也不静默丢弃内容。

## 3. 本轮修复范围

[故障恢复与对抗矩阵](../UCN_v6_逻辑模型与伪代码/13-故障恢复与对抗矩阵.md)中存在
十二条“三个语义单元格放在两列表头下”的行。本轮把受影响矩阵统一为：

```text
反例 | 错误实现 | 正确结果
```

原本只有“反例/正确结果”的行在中间列使用 `—`，不凭空补写未经审查的错误实现；原本已经
明确写出错误实现的行保留三个独立单元格。这样既修复结构，又不丢失审计信息。

## 4. 检查器自测

每次运行必须先验证检查器自身：

| Fixture | 预期 |
| --- | --- |
| 合法两列表格 | 接受 |
| 含 `\|` 的单元格 | 接受 |
| 含 `` `x | y` `` 的行内代码 | 接受 |
| 数据行少一列 | 拒绝 |
| 数据行多一列 | 拒绝 |
| 分隔行少一列 | 拒绝 |

检查器自测失败时，即使当前文档没有报告错误，整体门禁仍必须失败。

## 5. 适用边界

该门禁只证明“已纳入维护清单的文档结构没有机械漂移”。它不能证明：

- Wire 字段语义正确；
- Owner 状态机不存在逻辑漏洞；
- API 可由 C99 安全实现；
- 资源账适合目标 MCU；
- Persistence 能承受真实掉电；
- 文档已经取得外部复审 GO。

这些证据分别由 `V6S-00-02～08` 和后续实现/硬件阶段负责。
