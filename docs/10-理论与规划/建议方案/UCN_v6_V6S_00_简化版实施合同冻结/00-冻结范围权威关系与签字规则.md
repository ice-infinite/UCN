# V6S-00-00 冻结范围、权威关系与签字规则

> 状态：`DONE / SELF-REVIEW PASS / FINAL EXTERNAL REVIEW PENDING`

## 1. 冻结对象

`V6S-00` 冻结的是未来简化实现的输入，而不是当前完整 V6 的输出。候选范围包括：

- Wire 可见标量、Contract、Opcode、字段 offset、字节序、长度和认证覆盖；
- Generation、Sequence、Lease、Fence 和事务键的唯一 Owner；
- 公共 API/ABI、Opaque Storage、Feature OFF 和模块连接边界；
- Full/Lite/Nano 的编译期容量 ceiling、资源公式和耗尽行为；
- Persistence Foundation 的共同 Envelope、Provider、双槽、Witness、Proof 与恢复顺序；
- 独立 Golden、Negative、Fuzz/Property oracle 和跨合同追踪关系。

不在本阶段冻结：

- 各业务模块 Record Body 的最终字节布局；
- 真实 Flash 擦写时间、掉电窗口和寿命；
- 生产密码 Provider 的吞吐、密钥存储和硬件加速结论；
- ESP32、CAN/CAN-FD、UART、USB、无线的实际时间戳、MTU、吞吐和功耗；
- Full/Lite/Nano 的最终 Flash、最坏栈和任务水位实测值；
- 生产 Codec、RX/TX、Runtime 或 Owner 实现。

## 3. 状态词

| 状态 | 准确含义 | 不代表什么 |
| --- | --- | --- |
| `NOT STARTED` | 尚未形成可审查合同 | 不可按其他文档自行实现 |
| `IN PROGRESS` | 正在修改，候选仍可变化 | 不可冻结，不可编码 |
| `SELF-REVIEW PASS` | 作者完成定向和交叉自审 | 不是独立外审 |
| `EXTERNAL REVIEW PENDING` | 候选已固定，等待外部检查 | 不是 GO |
| `EXTERNAL GO` | 精确候选范围通过独立复审 | 只覆盖声明的文档范围 |
| `AUDIT HOLD` | 存在阻断或候选仍在变化 | 不得进入依赖阶段 |

`V6S-00-00～07` 的分项自审不会逐项解除实现门禁；只有 `V6S-00-08` 对同一候选执行全体
自审、固定哈希并取得外部 GO，`IMPL-00` 才能由项目台账显式改为可启动。

## 4. 变更纪律

1. 每个子项开始前记录输入、预期输出和禁止事项；
2. 修改后运行本子项的定向门禁并保存结果；
3. 不用“测试通过”替代缺失的规范语义；
4. 不用设计文档宣称源码、硬件或生产能力已完成；
5. 发现跨合同冲突时停止后续子项，先修权威文档和追踪矩阵；
6. 外审候选形成后不再夹带无关修改；若候选变化，哈希和签字状态一起失效。

精确权威关系补充如下：RFC 冻结顶层安全原则，本目录冻结对应专题的可实现数值合同。RFC 内
已经声明失效的 41～47 B 旧 Header、固定 Core CRC/Magic/Length 等历史段只能解释演进，不能
覆盖 00-02～04 的精确字段、长度和 Golden。当前完整 V6 源码同样只是回归参考，不是反向规范。
