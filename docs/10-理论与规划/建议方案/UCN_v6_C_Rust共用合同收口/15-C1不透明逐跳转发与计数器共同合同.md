# C1不透明逐跳转发与计数器共同合同

状态：分层密码原语与Host自审阶段；**不是自动多跳Node接线完成**，不是生产或外审GO。
本段没有新增Opcode、正文前缀或普通数据头字段。C/Rust沿用相同C1/AAD/H1规则；当前新增
Rust原语和真实Host路径测试，C1的C自动中继适配仍未补齐，不声称两语言实现进度相同。

## 1. 一帧数据的组成与用途

A1 C1普通头仍13 B：Common3、Source2、Destination2、Service2、Origin Sequence4。
O1/O2增加既有16 B Origin Tag，H1增加既有16 B逐跳尾部（Sequence4+Tag12）。
例如21 B业务的完整UCN帧为`13+21+16+16=66 B`。不含物理承载头、CRC或填充；安全开销
不能只报告13 B。使用O2时业务密文长度等于明文长度，具体Provider必须另外验收。

端到端A→C与邻居A↔B、B↔C是三个不同安全域。路由只负责选择下一跳，不证明A的权限，
也不能把B的Session当作A的业务Session。源和目标使用实际已激活的Origin Session；中继
只持有相邻Hop Session。静态H0的Origin保护结果可以再由相邻H1包装，不增加标识字段。

该H0示例不要求直连建立第二个Session。[合同18](18-直连多跳统一Origin与HopContext接线合同.md)
已补充真实H1 Session的显式Origin-only投影；两层可共用同Handle，但ACL、Key、
序号和Replay仍分别检查，完整packet API不能被当作H0降级入口。

## 2. 各端的最小逻辑

```text
Source Coordinator:
    validate actual endpoint Identity, Origin Session, Service ACL, Route and MTU
    origin_packet = Origin.protect(C1, plaintext, exact Origin counter)
    packet = Hop.wrap(origin_packet, actual next neighbour, shared Hop counter)
    enqueue locally; successful queueing is NOT remote delivery

Relay Coordinator:
    claim one atomic Adapter frame and physical neighbour discriminator
    pending = Hop.verify_and_reserve(actual neighbour, exact service ACL, packet)
    validate current Route, egress neighbour, MTU, TTL and bounded queue capacity
    forwarded = Hop.forward(pending, same packet, TTL-1, actual egress, new Hop counter)
    accept the immutable output into the local queue
    commit inbound Hop replay; on failed preflight abort the reservation
    retire actual Driver holder separately, including UNKNOWN obligations

Target Coordinator:
    verify inbound actual-neighbour H1 and reserve Hop replay
    independently verify actual Origin Session, source/destination Binding, Service and Origin replay
    preflight both pending proofs and actual application capacity
    accept one Endpoint message, commit both replay domains in one exclusive Owner quantum
```

这是分层规则，不意味着上述完整Node流程均已接通。当前Host用显式Coordinator测试串联
实际Owner、真实Foundation回读、实际Adapter TX/原子RX；全局有界调度和唯一Ingress仍待。

## 3. 不允许偷换的证据

- `C1HopOpened`字段私有、不实现Clone/Copy，绑定实际Security Owner、Session、待提交
  Replay、整帧128-bit密码摘要及长度。它只证明当前邻居，绝不是Endpoint授权。
- forward前重新检查原始完整字节、当前父代际和pending期限，拒绝改载荷/Tag/TTL后复用证明。
  入、出事实必须具有同一个本地Binding和同一个可信now；TTL=1不能再转发。
- 中继不修改Source、Destination、Service、Origin Sequence、业务/密文或Origin Tag。
  Origin AAD沿用既有规则屏蔽可变TTL；H1重新认证实际发送的整帧和TTL。
- 包装入口仅允许Source等于本端地址；中继必须使用上述pending证明，不能把源包装入口
  当作任意Origin转发入口。结构校验本身不验证Origin Tag，目标必须独立完成验证。
- 当前只接受Data。加密Control/Transfer的Opcode不对中继可见，不能把Data service ACL
  扩大成未知Control权限。这里也不授予Q0、EDF或其他调度特权。
- 错误时输出保持不变；不足workspace/输出、坏Tag/ACL、过期proof或耗尽TTL不提交Driver。
  failed commit释放仍存在的pending，不能因错误返回泄漏固定Replay槽。

## 4. 共享计数器及防意外重置

Capability、Route和业务路径可能共享相同Session/Key。它们不能各建一个从1开始的Hop
计数器。C0 transaction、普通Origin Sequence、Hop Sequence各有独立的严格递增命名空间；
新计数必须大于本Session已经消耗的对应高水位。

顺序固定为：完整Wire/ACL/容量预检 → 核对外部counter preview与内部高水位 → 外部burn
成功 → 内部高水位前进 → Provider。Provider错误、发送失败或围栏不能归还已消耗序号。
本地真正未提交的精确缓存帧重试不重新封装Origin；不得用同一Nonce重封不同内容。

已经完成精确Flow安全绑定的Origin Sequence由各自Flow Owner维护，不能误用全Session
高水位限制所有Flow共用一个Origin序列。Hop仍是相邻Session共享序列。

内部高水位是live Session的固定标量，不是持久化Nonce历史表。重启后旧Session不得复用，
必须通过既有Foundation/新Key Generation规则建立后继Session；本段不替代耐久防回退。
Rust每Session新增16 B内部高水位，与C已有reserve/consumed机制的安全意图一致。
