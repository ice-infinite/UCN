# C动态接入原生后端与受控热续接合同

本合同补充07～19、23～25的实际接线，不修改普通Wire、Opcode、签名正文或Record格式。
实施基线为`v6-simplified-rust@b9913d4`之后的工作树，见[计划12](../../../00-项目管理/12-C动态接入与原生后端热续接实施计划.md)。
内部软件自审不等于外部签字或生产放行。

## 1. 支持范围与非目标

本轮面向固定Realm、预期身份对、专用Link及静态业务通道。C Coordinator连接真实JOIN、
Foundation、Session、Capability和Native发布订阅。业务仍使用原Publisher/Subscription，
不因Session换代重新创建句柄。

产品必须提供当前受信Authority、密钥解析、身份签名/验签、Cookie、精确授权与真实Provider。
C没有从空白Flash选举或恢复地址Authority的完整Owner，不能把产品Authority View称为
本模块新完成的Authority耐久证明。Authority地址Binding须由独立合法颁发者实际发布。

不含共享无线Link、未知Peer自动信任、动态Topic目录、Authority换主、多Bearer迁移、
独立远端Origin自动重认证或全模块Node自动装配。工厂仍为产品内部SPI，不是新安装包自动联网API。

本轮支持**新Session中的新Capability协商**。同Session认证新ADVERTISE或不一致KEEPALIVE
使旧Profile立即停止授权；当前C子集不原地无缝改Profile，由产品Coordinator受控Reauth后重选。
不能把这写成七类控制消息的全部自动化，也不把底层Owner原语当作Native已经可达。

## 2. 唯一Coordinator、固定内存与借用

```text
产品配置/物理Driver
    → 首次JOIN Coordinator → Foundation/Identity/Security的Request/Proof
    → 实际ACTIVE Session + 真正物理排空 → Native Routed Coordinator
        → 唯一Adapter RX领取/退休；向Reauth、Capability或Route Control借出实际RX
        → Security认证 + 精确ACL + 当前父域 → Native应用事件
        → Route/Adapter → 业务与控制帧
```

叶不能自行claim第二份RX、伪造认证事实、按两个Ring顺序配对或重置Token冒充退休。
Owner、Gate、配置、Provider上下文与规则表保持借用，直到其全部物理义务和Session退休。
回调使用实际caller-owned Gate，不新增进程全局可变Owner。

热续接的来源历史表由产品显式提供`ucn_native_lifecycle_storage_t`并在start前enable，
后端通过受锁setup SPI取得永久借用范围，防止查询输出或其他工作区覆盖退休历史。
Rust用永久借用的`LifecycleStorage<N>`表达同一边界；不增加堆或第二份Payload池。

## 3. 首次JOIN与真正耐久发布

1. 初始化实际Adapter、三个Foundation Domain、Identity、Admission与Security。
   Domain分别保存预置Authority地址Binding、Device地址Binding、Session历史。
2. JOIN仅接受零工作区；首次事务起点、Principal、Realm、Link generation、nonce、txid、
   总截止期固定。Cookie Echo之后创建pending也必须沿用首次Challenge起点，不能续租。
3. 实际交换HELLO/Challenge/Echo与五类签名事件。分片由真实Driver Token承载；
   NOT_SUBMITTED保留原帧，UNKNOWN不假定成功/失败，签名错误不授予权限。
4. 对应Offer/Commit/Final发布及Session激活等待本端提交、Witness、回读和Proof消费。
   对端Final、typed DTO和Host常量不能代替本端耐久性。
5. ACTIVE查询仍复验Identity/Authority、Link、Selector和期限；真正TX/RX/IO排空后handoff。
   原JOIN Root保留，不能重新init来抹除历史。

Foundation私有Domain View返回真实`current_transaction_id`；下一事务不能猜为record generation+1。
Record/Wire布局不变。默认Nano只有两个Domain，动态工厂明确Unsupported，CMake禁止stock Nano
启用Native Dynamic；静态Native继续可用，仍按768 B测栈，不能拿它冒充Nano动态JOIN通过。

## 4. 精确Session ACL与Capability

产品可在AWAITING_DURABILITY阶段一次绑定最多64项不可变ACL，精确约束Principal、Binding、
当前Origin/Hop fingerprint、Service或Opcode及方向。规则替代而非合并默认表；后继重新授权，
不继承旧规则，不允许ACTIVE后改表。C借用表到Session退休，Rust以Owner生命周期借用约束。

Capability每次使用从实际ACTIVE Session取完整Candidate，按192 B canonical Record精确比较，
并复验原JOIN的真实父域。直连H1只包一个Hop；split-path仅允许独立H0 Origin和H1 Hop。
错误H1 split调用在任何reserve、crypto或输出写入前拒绝。

C0事务来自同一Counter Bank。Driver背压重试原帧；协议重试保留Origin字节，仅更新Hop序号。
收到重复请求，必须先验证真实新Hop，再逐字节核对缓存Origin后重发，不重复派发业务。
分片、重试、重复均不能刷新总截止期或预算。

127/128 B实际Host Adapter测试的控制帧：HELLO85、QUERY81、ADVERTISE101/101、SELECT120、
ACK105/104 B。大MTU目前仍固定双片，不宣称实现了按MTU选单帧的优化。
Backend同时校验协商Feature、Session实际Suite、消息等级及MTU，SELECT不是通配授权。
Hop Suite16映射Capability bit1，而不是bit16。更新、撤销、过期或父域不一致使旧Profile失效。

## 5. 热续接的严格顺序

1. 在step/dispatch及Provider/Driver回调之外，围栏精确旧Session。匹配的Endpoint、Neighbor、
   Control与业务均停止；独立Origin不重置。
2. Native退休旧Scope排队样本及未提交目标，保留其他扇出目标；真实TX、RX、RREP proof与IO
   等待实际completion/cancel/retire。Link reopen、逻辑超时和memset都不是退休证明。
3. 旧域真正drained、旧Capability叶quiescent后，attach独立Reauth叶，继续借用原JOIN父域。
4. Reauth采用V2 canonical208及双方身份签名，本地真实Record/Transaction回读，双方历史
   max+1。普通静态prepare仍严格prior+1，不为重认证普遍放宽。
5. 本端耐久回读前不发对应RESPONSE/ACCEPT。丢ACCEPT重发原缓存；真实历史2/1及1/2均
   通过新握手收敛到3，不能回滚Flash或伪造本端Proof。
6. 新Session重新授权；新认证ADVERTISE在原Capability Owner/槽replace predecessor，
   再完成SELECT/ACK。新MTU/Profile不继承旧值。
7. stage不等于发布。commit再次核验当前父域、Profile、物理排空与代际上限，退休旧Route/Reverse。
   RREP转发证明未完成时必须拒绝。
8. 通过Reauth handoff移交ACTIVE Session，不能调用会撤销Session的stop。随后一次更新精确
   Endpoint/Neighbor及Scope槽代际；同Publisher/Subscription接收新Session从1开始的序号。
9. 真正quiescent后detach旧Reauth；产品显式退休已排空的旧FENCED Security槽，之后才回收
   旧ACL/工作区，不能无界积累旧Session或提前释放Provider借用。

Route LinkRef冻结完整Peer/Binding、Link ID/generation、cost、capability bits和
`min(local physical, authenticated peer frame, peer processing)`。Route Control使用同一引用，
退休用原快照，不拿默认编译MTU重造。成功交接后才换新快照；同generation物理MTU漂移拒绝。

Reauth身份Provider预算独立于物理发送：checked `max_attempts*4`，调用前扣除，坏Proof也计数。
专用Security两次身份验签及Session verifier计入；Driver cancel/completion/retire不耗身份预算，
防止预算耗尽后无法排空。STOPPING/QUIESCENT、错Root/Owner、旧Scope、回退代际不能commit。

## 6. 两侧完成度与开销

| 项目 | C | Rust |
| --- | --- | --- |
| JOIN/Reauth共同正文 | 新增真实C控制链，沿用共同Codec | 既有Runtime与共同Codec |
| ACL/来源退休 | 精确新ACL及同namespace槽代际更新 | 同语义、生命周期借用及FIFO/Latest回归 |
| 本轮Native协议热接线 | 真实首次JOIN后，同Root两次Reauth/Capability更新 | 既有Routed Runtime热交接；不宣称本轮完成固定借用Native Backend的全部自动Reauth装配 |
| 同Session原地Profile重协商 | 暂停并走受控新Session | 不由Owner原语推导Native已自动接线 |

合同统一不等于全部高级工厂完成度相同。Codec/Golden及单语言Host Root测试不替代C↔Rust真实互通。
普通C1头新增**0 B**：A1示例仍是13 B头+16 B Origin Tag+16 B Hop Trailer+4 B业务=49 B。
控制签名、Capability交换和可选RAM有实际成本，不称“零费用”。Native Layout3是本地ABI，不是Wire扩展。

`UCN_FEATURE_NATIVE_DYNAMIC`默认OFF，依赖Native/Persistence，与最小Core分开。
256 B单函数和Nano/Lite/Full 768/1536/3072 B整链门限不放宽；图包括所有叶、Foundation驱动和
真实SPI靶点。产品回调、RTOS和ISR栈仍须实测，不按零字节计算。

生产密码、真实Flash/Witness/掉电、MCU栈水位、物理Bearer/时间戳、性能功耗和长稳未验证。
本轮不操作实机、不提交推送，不据Host通过授予外审或生产GO。
