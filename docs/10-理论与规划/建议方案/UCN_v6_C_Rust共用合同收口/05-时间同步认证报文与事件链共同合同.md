# 时间同步：认证报文与物理事件链共同合同

## 1. 用途与实施边界

时间同步是可选功能，用来建立可信的 Domain Time；不改变普通数据的路由、寻址和发送头。
本合同沿用既有 `0601..0604`、TimeKey12、TimeStamp24、Domain Record128 和 Envelope16。
不把四个物理 event key 放到 Wire，也不为普通 One-Way Data 添加时间或认证字段。

2026-10-14 本轮实现：Rust `time-runtime` 接固定单 Peer、专属直连 H0 Link、专属
Timed RX Queue 的认证四报文。C 同步既有 Codec/Domain Record 与非对称界准入规则；
**C 四报文认证 Root、动态/多 Peer、诊断 Root、全部模块共用调度尚未完成**。
不能用 C/Rust 字节相同，替代 C Runtime 的收发实现证明。

产品配置一个可信 STATIC_MASTER Principal。成员只接受当前认证 Session 的该 Principal；
Master 只使用自己的配置身份。该配置是产品信任根，不是未认证报文提供的字段。
Master 的本代 Domain Time 以自己的可信单调时钟为参考，并非自动提供 UTC/GPS 时间。
重启后先耐久换代，未恢复/未换代的 TimeDomain 不具备网络发布许可。

## 2. 报文和费用

| Opcode | 角色 | Body | 产生条件 |
| --- | --- | --- | --- |
| 0601 SYNC | OneWay | TimeKey12 | 当前耐久域、线性 Sync sequence、当前出站 ACL |
| 0602 FOLLOW_UP | OneWay | TimeKey12 + T1:u64be + bound:u32be | SYNC 的实际 T1 completion |
| 0603 DELAY_REQ | Request | TimeKey12 | 已认证的同一完整 SYNC 与原子 T2、专属预留 T3 |
| 0604 DELAY_RESP | Result | TimeKey12 + T4:u64be + bound:u32be | 精确请求、同一事务的 T1、真实 T4 |

TimeKey 为 `domain:u16be + reserved_zero:u16be + generation:u32be + sequence:u32be`。
每个新报文使用发送方自己的 C0 transaction。它不等于 Sync sequence，也不等于本地
TX/RX token。C0 的 canonical AAD、Origin Tag 和 Replay 域仍按既有共同合同执行。

H0、O1/O2 的单帧费用为 `C0(25+2×address_width) + Body + OriginTag16`。
各地址宽度一轮四报文总费用分别为 244、252、260、268 B，不含 Carrier 开销和重试。
A1 的四帧是 57、69、57、69 B。它是低频同步费用，不是每个业务数据包的固定费用。
只有应用明确选择 SYNCED_STAMP/DEADLINE 时才使用既有可选 Envelope16。

## 3. 四个事件的所有权与执行顺序

| 顺序 | Master Coordinator | Member Coordinator | 本地物理证明 |
| --- | --- | --- | --- |
| 1 | 保护并实际提交 SYNC | 原子领取完整 SYNC、执行 Security/ACL/Replay | Master T1、Member T2 分属各自 TimedLink |
| 2 | T1 completion 后保护 FOLLOW_UP | 精确匹配 Peer/域/代际/序号，保存 T1 | FOLLOW_UP 自己也有独立 TX/RX holder，不冒充 T1/T2 |
| 3 | 等待 DELAY_REQ | 内部构造精确请求，实际提交预留 T3 | 任意其他 TX 不能用来作为 T3 |
| 4 | 认证 DELAY_REQ，用真实 T4 构造响应 | 认证响应；T3 已 completion、T1 已收到后才计算 | T4 不引用远端 token；只绑定 Wire TimeKey |
| 5 | 退休本节点 holder | 输出不可伪造 TimeSample，交给 TimeDomain | 成功 Driver receipt 后才回收 Queue/Sync 义务 |

所有跨 Owner 的调用都由 Coordinator 编排。SyncOwner 不调用 Security、Persistence
或 TimedLink；它只消费 Coordinator 提交的精确事件事实并产生退休义务。
Runtime 不接受调用方的 `opened`、`authenticated=true`、任意时间戳三元组或任意 TX key。
接收入口自己从专属 TimedRxQueue 领取完整帧与其 Timestamp，再验证这枚 key 当前属于
同一真实 TimedLink，最后调用实际 Security。普通帧 Ring 与独立时间戳 Ring 不能靠顺序配对。

## 4. 当前耐久证明和序号

`time_domain_proof()` 只接受实际 TimeDomain 和实际 Foundation Owner：精确 Consumer、
Runtime/Owner/Domain/Schema、当前 128 B 正文、Record generation 与完整 digest 必须匹配。
当前 I/O/Proof 义务未退休、Fault/Loading/Pending 都拒绝。私有借用证明不能自行构造或 Clone。
Root 构造时冻结这份完整 binding；另一合法 Domain 的同名配置也不能替代它。

Master 的 sequence 由实际 TimeDomain 签发线性许可。许可不可 Clone，错误消费仍烧掉许可。
同代际的 acquisition/holdover/UNSYNCED 清理不重置分配高水位；到顶不回绕。
只有实际新的耐久 Domain generation 确认后才重置；旧 Record 恢复仍 Loading，不能分配。
C0 transaction 由现有实际 counter Owner 独立预览/烧号；过小 MTU 在烧号和分配物理 token 前拒绝。

使用时仍检查 Session、完整 Binding、Policy、双向 Key Generation、Origin 等级、固定
Fingerprint、专属 Link instance/generation 及固定 Path。H0 仅适用于此处已配置的安全直连域；
普通动态 Route 不能借用此入口。Path/Capability 的当前动态 Owner 证明尚需后续 Root 接线；
本子集的定向路径和能力配置来自可信静态产品合同，不冒充已实现动态路径验证。

## 5. 保守上界与有效样本

已知的 timer、link capture、filter、rounding、sample capture、asymmetry 分量必须为正，
aggregate.asymmetry 必须大于等于冻结 Path 的 max_asymmetry。C/Rust 均拒绝低估这项分量。
四个真实 capture bound 与 checked aggregate 相加；Rust Sync 再覆盖整数除法的 1 us 保守界。
在发布以 Member now 为参考的样本前，额外增加：

```text
elapsed = max(member_now - T2, T4 - T1)       // checked subtraction
exchange_drift = ceil(elapsed * 2 * oscillator_ppb / 1_000_000_000)
```

产品的 oscillator_ppb 必须覆盖两个参与时钟各自的误差；未知、零或溢出失败关闭。
TimeDomain 后续滤波保留每个样本的 bound/time，计入残差与漂移；clock(now) 再计入采样后的
漂移。不能把一份迟到的 Offset 当作刚刚测得且零误差的事实。

缺可信 asymmetry 的现有 SyncOwner 结果只能是 Diagnostic，不能进入 TimeDomain 有效窗口、
LOCKED、DOMAIN_TIME_VALID 或网络 Timed Envelope。本次 Rust Root 进一步限于有完整已知
上界的持久化配置；未实现诊断 Root，不会暗中删除分量后放行。
本轮 C 同步 asymmetry 准入；C 完整滤波/四报文的组合数值互通仍留在后续共同 Root 验收，
不能宣称上述 Rust aggregate 已成为 C Runtime 的逐数值实现证明。

## 6. 失败、停止和退休

SYNC 是尽力同步，不是业务 Reliable RPC。本子集的 NOT_SUBMITTED、UNKNOWN、丢帧、
乱序缺证据或原始 Deadline 到期可以放弃一轮样本。放弃后保留全部已分配 event key，
待 Driver 真实退休，再用新的线性 sequence 开新轮；不为等待延长旧截止或伪造 completion。

T1/T3 不能早于相应启动/实际提交时刻；所有 TX completion 不得晚于本次可信 now。
实际 T1 未到达时，FOLLOW_UP 不产生。T3 只绑定内部构造并保护的 DELAY_REQ。
没有 T3 或 FOLLOW_UP 时 DELAY_RESP 不能成为样本；未来 Timestamp 也不能推进阶段。

`retire()` 固定 holder 容量 6、持续 cursor、每次至多 min(budget,6) 检查。执行顺序：

```text
peek exact holder / Sync release
retire actual TimedLink Driver reservation
retain sealed RetirementProof in holder
release exact atomic RX claim, if owned
ACK exact Sync release, if owned
clear holder only after all local obligations succeed
```

Driver 首次失败时原 key 留在队列；Driver 成功而 Queue 尚未回收时保存 receipt，
不能再次调用已退休的 Driver key。Queue 已回收则清除 claim 再执行 Sync ACK。
Driver 的退休成功必须证明该 key 的物理操作及可能的 completion 回调已静默；
“已经发出取消命令”不算成功，不能仍在 ISR 发布中就返回成功。
提交时的 frame slice 只借用于本次 SPI 调用；异步 Driver 返回前须复制到其有界自有存储。
打点完成不等于 Driver 预留已退休，不能因为已取得 T1/T3 就丢弃该 key。
stop 不可逆地拒绝新网络工作，仍允许原 holder 退休；组件静默不等于全节点或远端静默。
Driver/Provider 使用同一个实际 CallbackGate，不能使用相同编号的另一对象冒充；
step、stop、取出样本和退休也检查该真实门，回调内不改变另一个 Root 的状态。

## 7. 验收及未完成项

正式回归必须使用实际 Foundation 回读、实际 Session/ACL/Replay、Fake TimedDriver
completion、原子完整帧 Queue、真实 retirement receipt。既有模型测试不能替代这条链。
正向是连续两轮、四报文、全部 holder 退休；负向覆盖错域/代际/sequence、错误当前
Domain、无 ACL、坏 Tag、T1 缺失、过小 MTU、背压、UNKNOWN、超时、reopen 与退休失败。

当前范围是 Host 自审，不能推出实际 UART/CAN/无线打点精度、Flash/Witness 掉电安全、
时钟漂移与路径非对称参数、同步性能、TSan/Miri 或 MCU 栈水位已经验证。
动态/多 Peer、诊断 Root、全部模块统一预算、C 完整 Root 及 C↔Rust 四报文 Runtime
互通仍是软件任务；本合同不把它们改成“只剩实机”。
