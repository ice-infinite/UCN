# C动态发现控制与可选后端完整栈合同

状态：限定Host接线、软件矩阵和内部整体审查完成；外部/实机/生产未放行。承接合同14/24，不扩展普通数据头。

## 1. 动态发现不是动态身份

C沿用封存的完整Binding、实际ACTIVE Session/ACL、独占物理Link、绝对装配期限。
缺少业务路由时，原Native命令在原期限内等待，Coordinator用原Route Owner分配发现ID并经真实
C0/Q0/BestEffort/O1/H1传播；业务Origin序号到路由/MTU/当前授权就绪后才分配。
路由控制的外层Peer和内层原始发现者分开，内层转述不是业务授权。C数据静态后端可以不启用控制模块。

## 2. 唯一入口、计数与退休

只有一个Coordinator能claim Adapter RX，区分C0控制/C1业务；认证及精确ACL通过后才变更Route Owner。
固定控制Job/Peer组装槽使用合同14完整正文和0206分片。C0事务从产品跨模块共享的精确Session银行取得，
Hop计数复用Security Owner；没有“控制后端初始化为1”的计数器。计数器回调同Provider一样受重入Gate约束。
真正已发送后的新逻辑尝试使用新外层事务；明确NOT_SUBMITTED重试保留同一已保护帧。
这一区别同时适用于C和Rust，不得把明确未提交当作已发送回复丢失。原内层发现、组键和绝对期限不刷新。
RREP转发只有真实终态和Token退休后才完成反向义务；失联、stop、Unknown不得清除尚有物理引用的状态。
控制和业务采用固定工作预算、独立容量和轮转，不借Q0身份获得无限优先权。

每个C出站控制job的全部分片合计最多16次Adapter submit调用，包括NOT_SUBMITTED；不按分片重置。
达到次数/原deadline时禁止新提交；尚未取得真实终态的token仍须继续持有。
Rust沿用产品配置`max_attempts`的同一整job物理次数语义；等效产品设16，不声称两种产品的整次发现总次数相同。
原Reverse到期由首次RREQ固定，Route锁内Action给Coordinator原期限快照。
重复请求重答和迟到RREP上游发送使用该原期限，不得取“当前receive_time+新寿命”。

REOPENED只改变Link可用性/代际，不是旧token的物理排空证明。只有Driver真实物理完成或排空后，
针对**原精确token**报告完成（交付结果允许仍为IN_DOUBT），才能退休；冲突已锁存的终态不能借迟到完成复活。

## 3. 完整协议栈的证明口径

检查必须覆盖Native公开入口、实际Backend虚表、C0/C1安全和路由、Adapter/Codec的所有可达协议函数；
不能只按旧kernel源码前缀筛选。Compiler已内联的函数栈包含在其caller，不重复相加；保留下来的间接调用
须精确映射真实协议目标。映射遗漏、源码漂移、缺少可达函数记录、无界动态栈和未排除的递归都失败关闭。

保留单函数门限和Nano/Lite/Full链上限768/1536/3072 B。若超过，重构固定工作区和阶段边界，
不得通过丢调用边、选择小caller、关闭诊断、换大门限或把协议工作伪装外部callback放行。

Driver、密码Provider、锁、应用回调是产品代码，不可能给任意实现凭空证明固定栈；检查报告须逐类
显式列出边界及剩余栈预算。Host测试/纯编译只能证明其明确覆盖的实现；生产callback、IRQ嵌套和RTOS
任务水位仍需产品验证。协议间接边未知不能当作产品边界自动豁免；产品回调若回入协议，须包含允许的
真实回入前缀或声明禁止的调用域并给拒绝路径证据，不能静默形成递归漏洞。

### 3.1 可复算门禁

`generate_native_call_stack_policy.py --check`核对真实工厂九个虚表成员、完整Native结果API入口及全部源码指纹。
开发者经审查才能显式`--write`，CI不得自动刷新。`check_native_call_stack.py`用GNU `.ci`记录和原门限，
按每个实际间接调用点的源码位置解析成员/数组/跨行表达式；不认识的调用语法失败，不猜测为外部回调。
同名静态函数按编译单元区分，缺函数、冲突记录、递归和无界动态帧均拒绝；有界动态帧完整计入。

Native允许的业务回调内API、Driver允许的同步completion/RX/link-event协议调用也是协议边，
与直接调用一样累计。产品函数帧用联合不等式表达，例如`driver + lock <= X`；分别满足各自投影上限
并不保证同时存活时安全。`PROJECTED_ONLY / PRODUCT_STACK_NOT_PROVEN`不能解释成实机已满足。
任一产品边界剩余预算为0也必须失败，不能靠“空实现”假设过门禁。

图必须新于其实际编译依赖：GNU/Ninja使用编译器依赖库，独立ARM编译使用相邻`.ci.d`；
仅更新源码指纹不能把旧调用图洗成新证据。其它生成器须提供等价编译依赖，否则该门禁拒绝。
这只是软件可追溯性检查，不防御恶意篡改编译器或伪造时间戳。CMake注册H0/H1完整链与检查器自测；
Profile、Feature和优化矩阵各自执行，不能用Debug的图替代Release/MinSizeRel。

`UCN_I_STACK_PHASE`仅保留确实分离的Actor阶段，使结构复制/检查临时量不贯穿深层调用；
这不是全局禁内联或关闭诊断。注解头不含类型、函数、Owner引用；Native依赖检查逐行限制其内容，
不借此放开Facade直接调用Security/Route/Adapter。
