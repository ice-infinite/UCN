# 原生发布订阅认证后端共同合同

## 1. 本轮范围与信任边界

本合同承接原生 API 首轮静态接口，新增可信产品装配的 Backend SPI，并接入既有 Security 与 Adapter。
首个认证后端只持有**一个不可变、已耐久激活的直连 H0 Session 和一个 Service**；支持固定通道、
单帧、OneWay/BestEffort、O1/O2。多 Peer、动态路由、Admission/Capability 热续接、RPC、Transfer、
Timed Command 不在该后端中悄悄启用。业务通道不因此增加任何普通 Wire 字段。

Backend 是与密码 Provider、Driver 一样的可信产品装配边界，不是业务可提交的认证凭据。
应用只调用 publish/send/subscribe；不能向 Inbox 注入 `authenticated=true`。调用方任意改写 C RAM、
替换可信 Backend 或提供恶意密码 Provider，不属于进程内存隔离承诺。

## 2. 结构与依赖

| 层 | C | Rust | 责任 |
| --- | --- | --- | --- |
| 业务外观 | `ucn_native.h` / `ucn.hpp` | `ucn-native` | 通道、实体、复制、FIFO/Latest、延迟应用回调 |
| 可信后端端口 | `ucn_native_backend.h` | `Backend` / `BackendScope` / `BackendMessage` | 有界收发、当前授权复验、物理生命周期 |
| 首个 Session 协调器 | `src/runtime/ucn_native_session.c` | `ucn-runtime/native_backend.rs` | 编排现有 Security 与 Adapter；不重新实现安全 FSM |
| 安全事实 | 现有 Security Owner | 现有 Security Owner | 精确 Principal/Binding、Session、ACL、序列、Codec、Replay |
| 物理义务 | 现有 Adapter | 现有 Adapter | 原子 RX、TX Token、背压、Unknown 和真实退休 |

C 的认证 factory 本轮仍是私有产品装配 SPI；安装包公开的是 Native 端口，不冒称完整高级 Root
factory 已经公开。Rust 的 `native-backend` feature 默认关闭；Core 与基础 Native 不依赖 Runtime。
静态 O0 后端仍要求显式 `STATIC_TRUSTED`，不能满足 OriginAuth/Encrypted 的要求，也不自动降级。

## 3. 初始化与固定来源

1. 产品先用既有流程完成 Session proof、Persistence/reload 和 ACTIVE；本后端不制造该证明。
2. 首个后端独占一个已打开但未启动接收、没有遗留 TX/RX 义务的 Adapter，配置不可变。
3. 核验完整 Session、当前 Binding、Context fingerprint、地址宽度、Link Generation、H0、Service
   和保护级别。错误配置不发布 Native Root，错误 Hash/Layout 不写 Native Storage。
4. Native 来源表中的 `principal_digest` 只是配置标签/过滤条件，**不是 ACL 身份**。安全授权始终由
   后端的完整 16 B Principal、Binding 和精确 Session 完成；Sample 才投影完整已验证身份。
5. Scope 只在本进程本后端注册域有效，不能上 Wire，不能跨 Root 当作通用授权凭证。
6. 不支持在该 Root 中替换 Session/Peer/Service。需要后继 Session 时先停止并真实排空，再用新的
   Root 实例与存储装配；不得清零旧 Root 或继承旧队列/Latest 高水位来复活权限。

Native C API/Layout 升为 2，Magic 对应新布局，必须整体重编译；Core Storage Layout 保持 5，
不为 Native 增加 Core Node 字段。Native 既有三档存储上限不扩大，认证协调器工作区独立计算。

## 4. 发布和物理发送

`publish()` 成功只代表业务字节已复制进本地有界队列，不代表加密、上链路、远端收到或执行。
`step(now)` 使用本次可信单调时间做授权/Deadline 检查，不能以旧 step 时钟允许已过期发送。

后端先检查当前 ACL、保护级别、MTU/容量和 Token，再调用唯一 Security 序列域保护报文。
C 复用 Security 内部序列；Rust 显式借用既有唯一 `OriginSequenceOwner`。Native 不另分配网络序列。
密码 Provider 观察过的序列不得重用；保护完成即由后端持有完整帧，物理暂时失败不让 Facade
重新制造同一业务请求。NOT_SUBMITTED 继续提交同一帧、同一 Origin sequence，原 Deadline 不刷新。
C 单次 Adapter Token 退休后再预留物理 Attempt；Rust 按自身 Adapter 合同重交允许重试的 Token。
两者不要求本地 Token 数值相同，但 Wire 与交付语义相同。

Driver submit/cancel 与 Security 共享控制回调域，不持有 Native 短锁调用其他 Owner 或应用。
SUBMITTED/IN_DOUBT 保留真实 token/frame；不能因失败、Stop 或逻辑到期直接清零。

## 5. 接收、Replay 与应用交付

独占 Adapter 的后端必须认领并退休不支持/畸形输入，不能把它们留在 Ring 中永久占槽。
一份完整帧、原始本地 RX 时间与物理 Token 保持原子归属。入口逐项检查：

1. 当前 Link/Session/Policy、完整对端身份与 Binding。
2. 既有 C1 大端布局、H0、HopLimit=1、Data/OneWay/BestEffort、Service、O1/O2。
3. 当前入站 ACL、密码验证和 Security Replay；失败不发布业务样本。
4. 接收本地复制成功并提交唯一 Replay；真实 RX 退休成功后，才把后端复制样本交给 Native。
5. Native 再核对通道、来源、长度、类别、最低保护、围栏和 Latest 顺序，保留原始 RX 时间。

这是 BestEffort：认证后 Native 应用队列满可以丢弃，不能据此宣称可靠交付，也不回滚已提交 Replay
来允许旧帧复活。`max_local_age_us` 是本地 RX/接纳到分发的寿命，不是跨节点源年龄保证。
严格半开到期条件为 `now < original_anchor + max_local_age`；不能重新入队刷新起点。

每个订阅回调前，必须重新验证 exact Scope、当前完整 Principal/Binding/Session/ACL、时间和保护
级别。第一个回调撤权后，第二个回调不得继续交付。C 验证解锁后还须核对原订阅代际/recipient，
不能把旧订阅事件交给同槽新订阅。Rust 独立 `Inbox::dispatch` 遇到保护通道返回 Unsupported；
只有持有真实后端的 `NativeRoot::dispatch` 执行当前授权复验。

## 6. 样本、关闭与资源

| 场景 | C provenance | Rust | Principal |
| --- | --- | --- | --- |
| 本地复制 | LOCAL | local=true、protection=None | 不伪造远端认证身份 |
| 显式可信 O0 | STATIC_TRUSTED | StaticTrusted | 配置标签，不是密码身份 |
| 验证后的 O1 | ORIGIN_AUTH | OriginAuth | 完整认证 Principal |
| 验证后的 O2 | ENCRYPTED | Encrypted | 完整认证 Principal |

当前保护通道的本地复制也复验其固定 Session 的出站授权；它不是独立于网络授权的通用本地事件总线。
回调在 Native/协议锁外执行，允许复制当前借用 payload 到延迟 publish；不允许保存借用指针到回调后。
close/fence 不依赖空闲命令槽；Stop 阻止新接纳，关闭入口并有界退休全部 RX/TX。
已 CLAIMED RX 或其他遗留义务不能被 `NOT_FOUND` 冒充为空。只有整个独占 Adapter 真正排空才能
报告 quiescent/deinit。deinit 后 API 在原短锁内返回 State，不再解引用已经可释放的后端；
Root存储和原短锁/context必须保持到所有并发API调用者退出，不能随deinit返回立即销毁锁。
旧 Root 不能重建。固定后端首版对晚于当前step快照的RX时间戳保守丢弃，不刷新寿命。

## 7. 费用与验收边界

既有 C1 Header 为 `9 + 2 × address_width` B，即 A0～A3 为 11/13/15/17 B；O1/O2 都沿用 16 B
Origin Tag，H0 无 Hop Trailer。总费用为 `Header + Business + 16`，本轮新增普通头字段 **0 B**；
配置标签、Scope、完整 Principal、回调元数据不重复上 Wire。O2 Nonce 仍按现有安全合同派生。

Host 测试使用可控 Driver/Flash/密码 Provider。O1 Rust fixture 使用 HMAC；C fixture 与 O2 wiring
fixture 是明确的测试替身。O2 可逆测试变换**不是 AES/ChaCha 实现**，只证明 Provider 接口、密文路径、
认证拒绝和业务明文交接，不证明算法、密钥管理或真实精度。既有独立密码/Codec oracle 继续单独运行。
真实生产 Provider、Flash/Witness/掉电、MCU 栈水位、DMA/IRQ、物理链路、性能和生产放行仍待验收。
